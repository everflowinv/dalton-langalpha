# MSFT 跟踪研究与写作规则

每轮研究开始时读完本文件。判断是否重要、如何改工作底稿、如何写卡片，都按这里的数字、期间和条件执行。

日常跟踪只改工作区 `research/tracker/thesis.md`。导入档案 `research/tracker/imported-msft/thesis.md` 保持原字节。工作区根目录的财报 `thesis.md` 和 `data/thesis.json` 不是这份跟踪底稿，不覆盖，也不把跟踪底稿写进通用知识 JSON。

本文件不记录收件人、旧工作目录、旧采集脚本或旧发送命令。网页用 WebSearch 与 WebFetch。内部研究、AlphaEngine 和 SEC 用现有 researchdata 工具。卡片文件由 `scripts/render_card.py` 构造，发送由自动化报告工具完成。

## 工作底稿要保住的内容

底稿继续存放：核心判断、D1 至 D7、KPI、修正假设、专家可靠性、观点池、待核实线索、变更记录。每条数据写明来源和时间。

无论本轮是否重要，都用编辑工具改有变化的章节，保留结构和其余内容，不整篇重写。需要更新的部分：

- KPI 当前值。
- 一致预期基线，写上读取日期。
- 观点池新增条目：机构或身份、日期、一句话。
- D1 至 D7 的当前倾向和置信度；有变化时写原因。出现底稿里没有的新分歧时补上。
- 催化剂日历。
- 「最近更新」改成本轮时间。
- 本轮打不开原文、又只有单一来源的线索写入「待核实线索」：来源、日期、URL、已核 0 轮。
- 末尾「变更记录」追加一行 `YYYY-MM-DD HH:MM | material=yes/no | 一句话`。

和观点池重复的说法不算新信息。

通用知识层可以按已有读序参照（`agent.md` 托管块，以及 debate、drivers、management、verdicts、agenda 等已有材料）。不调用会覆盖财报研究的知识层写入接口。

## 每轮必读的材料

1. 完整读 `research/tracker/thesis.md`。
2. 完整读本轮 `packet.md`，再逐个读其中列出的 excerpts。内部库没有新增时，仍然完成本节的新闻、X 和待核实线索检查。
3. AlphaEngine 新文档先看摘要。只挑带新数字的，最多两篇读全文。新数字包括盈利预测、Azure、M365、Copilot 增速、capex、评级、目标价、买方调查。全文调用保留完整 `doc_id`，包括 `_inst_` 等后缀，不转成整数，不截断。全文额度和同周期其他跟踪共用。返回额度、`E_DESKTOP` 或 `E_UPSTREAM_API` 时停止读全文，只用摘要，并在本轮更新里注明。
4. SEC 新公告：
   - 8-K 先看 item，`finance(route="sec", operation="eight-k", ticker="MSFT", limit=2)`。
   - 财报 8-K 用 `finance(route="sec", operation="attachments", ticker="MSFT", form="8-K")` 列出最新一份的附件，再读 99.1 新闻稿。
   - 10-Q 用 `finance(route="sec", operation="search-text", ...)` 查关键词：`Anthropic`、`remaining performance obligation`、`finance leases`、`severance`。
   - 融资文件 S-3ASR、424B2、424B5、FWP 同样读附件，记下金额、品种和利率。微软在本轮周期还没发过债，首次发债算重要。
5. 新闻摘要和 X 上的消息类帖子（券商动作、公司数字）只当线索。券商评级或目标价变化，要在 AlphaEngine、sales notes 或可打开的新闻原文里找到第二个来源，才写成事实。只有单一来源时写明「据 X 帖」或「据 MarketBeat」这类归属。核原文用 WebFetch。页面 403、挑战页或打不开时换一个来源；仍打不开就按单一来源处理。
6. 「待核实线索」每轮最多核 3 条，即使本轮数据包里没再出现也要核。用 WebFetch 打开原文，或在 AlphaEngine、sales notes 找第二来源。核实后移进观点池，并按下一节判断是否重要。核不到就把「已核 N 轮」加 1，满 3 轮或超过 5 天就删掉。
7. 专家访谈和管理层交流按 2026-10-15 已确认的合规范围使用，包括自称微软在职人员的专家。写法注明日期和自述身份，例如「10/15 自称微软 Azure AI 业务、负责公司战略和预算的专家」，并说明和公司披露、第三方数据、其他专家是对得上还是有冲突。专家给的经营数字按单一来源估计写，和公司披露、第三方数据分开写。底稿「专家来源可靠性」记录各位专家已被验证或被推翻的说法；新材料要对照这一节判断可信度。财报出来后，把专家关于 Azure、Copilot 席位、capex 的说法逐条对一遍，更新这一节。

## 新闻与 X

本轮两条固定网页查询，以数据包里的记录为准，就是这两条：

- `Microsoft analyst estimates price target downgrade upgrade Azure`
- `Microsoft OpenAI Copilot capex datacenter Anthropic news`

每条都查。结果写入本轮 `research/tracker/<run_id>/news.md`，保留标题、来源、日期、URL，以及检索状态和原文打开状态。

X 帖子读数据包里已经采集的「X 帖子」一节，不另跑旧的账号时间线程序。

- 作者是基金经理、分析师、前卖方或独立研究，并且帖子给出数字和推理的，算专业基本面观点。
- 新闻搬运号的帖子按上面的线索处理。纯技术面、喊单、段子跳过。
- 专业观点写入观点池，格式 `X @handle（身份）MM/DD，赞 N：一句话`，写清它支持哪条 Debate 的哪一方。赞 100 以上或收藏多，并且提出观点池里没有的论据或数字的，优先记。
- 权重低于 TMTB、卖方邮件、AlphaEngine 和专家访谈。专业帖里引用的卖方动作和公司数字，仍要第二来源。
- 卡片里最多展示 3 条专业帖。单条专业帖只进观点池。
- 至少两个互不相关的专业账号提出观点池里没有的同一个新论据，或专业帖带出的新数据已经由第二来源核实，可以构成重要变化。

账号池：

- 某位作者连续给出有数字、有逻辑的基本面分析，用本技能 `state.py` 的 `x-pool add` 加入。研究依据必填，写明身份和依据。同时覆盖多家时可以写 `MSFT,META,GOOGL` 这类代码，适用范围保留 MSFT 或 ALL。
- 池里的账号转成主要在喊单或搬运时，用 `x-pool remove` 移出，写明原因。历史记录保留。
- 每轮最多新增 3 位。重复加入同一作者不重复计数。计数以本轮持久记录为准。
- 不调用旧的 xreach，不编造 profile、粉丝或 rest_id。资料缺失就在记录里写明缺失；以后有可靠资料再更新。已导入的作者缓存里已有的字段可以沿用。

## 是否重要

满足任一条就是 `material=yes`：

- 一致预期：数据包自动触发项里有 FY27 或 FY28 的 EPS、收入，或平均目标价的阈值触发。自动阈值是：下一财年 EPS 相对上一轮 1.0%，相对 7 日 2.0%；下一财年收入相对上一轮 0.7%；平均目标价相对上一轮 2.0%；下一财年 EPS 向下修正家数 7 日达到 5。或者主流券商改评级、目标价调整 10% 以上、改 FY27 或 FY28 EPS、Azure 增速、M365、Copilot 或 capex 预测，且改动幅度或理由是观点池里没有的。主流券商包括 GS、MS、JPM、BofA、Citi、UBS、Barclays、Jefferies、Evercore、Bernstein、Wells Fargo、Deutsche Bank、Piper、TD Cowen、Oppenheimer、Stifel。
- 公司事实：财报、指引、8-K、融资（首次发债、可转债、大额租赁或表外融资）、管理层对 capex、Azure、Copilot、Maia 的新表态、OpenAI 或 Anthropic 合同条款变化（分成、独家、RPO、算力承诺）、Anthropic 上市文件或定价、裁员或重组公告、重大法律或监管进展（金额 10 亿美元以上，或改变时间表）。Anthropic 上市文件或定价会决定微软 FQ2 投资收益。
- Debate：D1 至 D7 某条的当前倾向或置信度需要改，或出现底稿里没有的新分歧。
- KPI 越过底稿里写的阈值，包括 FQ1 Azure 第三方跟踪或买方 whisper、Copilot 席位、FY27 capex 新数字、剔除 OpenAI 的 RPO 增速。
- 买方 whisper、拥挤度或对冲基金调仓有明显变化，来源是 sales notes 或 TMTB。
- 催化剂新增、改期或取消。
- X：至少两个互不相关的专业账号提出观点池里没有的同一个新论据，或专业帖带出的新数据已由第二来源核实。
- 股价自动触发（单日 4% 或 5 日 8%）并且能找到原因。找不到原因时只在底稿记一笔，不单独发卡片。

不算重要：重复观点池里的说法、单条 X 帖或搬运号转述、通用财报前瞻、只有一家小机构的目标价微调、没有新数字的评论。几条中等信息合在一起改变了修正方向或催化剂判断时，算重要。

内部没有新增，不代替上述检查。新闻、X 和待核实线索仍然要做。

### 财报特别轮

财报 8-K（Item 2.02）第一次出现在数据包的那一轮，一律算重要，按财报特别轮写。之后几轮回到上面的常规标准。卖方在财报后改预测，通常算重要。

下列数字是原底稿里这一轮财报要对照的比较值，保留期间和来源，不要改写成永久的当前数值：

- 实际收入和经营利润对一致预期：FQ1 收入 907.1 亿、EPS 4.72；公司指引中值约 904 亿、EPS 约 4.70。先拆出 Anthropic 等投资收益和裁员费用，再写超没超。
- Azure 增速对指引 44% 至 45%、买方约 47%、专家约 45%。
- FQ2 Azure 指引对 47%。
- M365 商业云对 17%。Copilot 付费席位对 4,000 万，同时看 E7 和用量收入。
- Microsoft Cloud 毛利率对 65%。
- FQ1 capex 对 500 亿以上，以及对 FY27 的三档说法：2,200 亿、2,400 亿、2,600 亿。
- 剔除 OpenAI 的 RPO 增速对 25%。
- 然后给出 FY27、FY28 盈利预测的修正方向。

## 盈利预测怎么拆

微软财年是 7 月至次年 6 月。数据包里 `0y` 是 FY27（止于 2027-06），`+1y` 是 FY28。判断盈利预测修正时两年都看。

一致 EPS 是 non-GAAP，只剔除 OpenAI。Anthropic 投资收益和裁员费用都在 EPS 里面。EPS 变动时先查是不是来自这两项，两项分开识别。

盈利预测修正按三层写：收入（Azure、M365 Copilot、消费端）、成本（毛利率、capex 与折旧、裁员费用）、投资收益（Anthropic 等）。写明哪一层动了，以及隐含费用空间的变化。没有变化就写「一致预期未动」。

金融假设来自 FY26 Q4 8-K 附件 99.1（accession `0001193125-26-323632`）：non-GAAP 净利润 353 亿、EPS 4.74，约 74.5 亿股。FY27 Q1 指引税率约 20%，其他收入约每季 -1 亿（不含 OpenAI）。跟踪模型沿用的常数是：稀释后股本 7.45（74.5 亿股），税率 0.2，其他收入 FY27 与 FY28 各 -4 亿。这些常数有上述来源；财报特别轮的比较数字仍按上一节的原底稿期间使用，不互相覆盖。

## 卡片正文

只在 `material=yes` 时写 `research/tracker/<run_id>/card.md`。从第一个 `##` 开始。每个 `##` 渲染成一个加粗分栏。目标 2,500 字，硬上限 3,000 字。上限按卡片构造前的最终正文长度计算，含区间改写和 Debate 补注。超过 3,000 字时压缩新信息和来源后再构造，不自动截断，不发出半张卡片。

固定章节：

```markdown
## 判断
一到两句。先说这次变化让核心判断或哪条 Debate 往哪边动、置信度如何。判断没变时直接写「判断不变」，再说这次新信息强化了哪一边。

## 新信息
- 每条一个事实或观点：来源身份（机构、管理层、专家身份或平台）+ 内容 + 带期间的数字。

## 盈利预测修正
收入、成本、投资收益三层里哪层动了；一致预期的变化；隐含费用空间的变化。没有变化就写「一致预期未动」。

## X 上的专业观点
本轮有值得看的专业帖时写，最多 3 条。
- @handle（身份）：观点一句话，赞 N，[原帖](url)

## 催化剂
新增或改期的事件和日期。没有就删掉这一栏。

## 改判条件
只在本轮有变化时写。没有就删掉这一栏。

## 来源
- [标题](url)，或「AlphaEngine 某券商 10/15 doc 150001501906778」这类可回溯的标识
- 有来源失败或只读到摘要时，最后加一条「数据备注：……」
```

写法：

- 中文。链接用 `[文字](url)`。不用表格，不用图片。
- 数字区间写「至」。金额写「美元」「亿美元」，不用 `$`。代码直接写 MSFT。
- 「来源」一栏由构造程序显示成灰色小字。
- 卡片读者看不到底稿。每条 Debate 在卡片里第一次出现时写成 `D1（用一句话说这条分歧在争什么）`，之后可以只写编号。多空写「看多」「看空」。漏写括号时，构造程序用底稿里 `### D1 标题` 这种标题补上第一次出现，已有括号的不重复补，链接里的编号不补。
- 标题、副标题和 MSFT 标签由构造程序生成。`card.md` 不写这些，也不写收件人。
- 每个数字都能回指本轮工具结果或工作底稿里已有记录。本轮查不到的不写。事实、管理层说法、卖方预测、社区观点分开写清身份。

## 语言

卡片正文、工作底稿和最终回复按仓库语言要求写：主语清楚，少用被动，不堆黑话，不凑三点，不加奖状式开场，也不加结尾推销。

这三处自行撰写的文字不用防御性否定，包括「不代表」「并非」「而不是」「不能」「不构成」「不应」以及同义改写。先给判断，再写事实和依据。需要说明边界时，用正面、具体的句子写清证据范围、置信度和改判条件。逐字引文、命令和原始报错保持原样。
