# 中文交付与写作规范（Writing & Delivery Guide）

## 1. 判断先行与段落组织（Conclusion First）

- **开门见山给判断**：报告开篇直接亮明立场、核心依据与估值赔率（完整覆盖备忘录按 `memo-writing.md` 的「摘要」结构展开，其他交付物第一段不超过 3 句话），不铺垫行业背景或公司历史。
- **段落先给结论，再写证据与传导**：每段围绕一个论点展开，第一句直接写结论，随后用带期间的事实数字和业务机制说明它如何影响收入、margin、FCF 或估值倍数；证伪与改判条件集中放在「跟踪」节（多空讨论 Debate 的「我的判断」下就近一句），不在每个自然段末尾机械重复。

---

## 2. 口径警告的正向改写与集中声明

- **少写否定式免责套话，直接改写成准确口径 + 投资含义**：
  - 避免在正文里反复堆砌"需要注意这个数字不是……、不能直接说明……、不代表……"等防御性废话。
  - **正确写法**：先把指标改成准确口径陈述事实，紧接着写它的投资含义（例如：不要写"第三方抓取的调用量不代表真实收入"，直接写"第三方监测显示 2Q26 API 调用量环比增长 40%（单源估计），但由于大客户阶梯降价，预计对 2Q26 云收入的净拉动约为 +2 个百分点"）。
- **限制条件集中写一次**：数据可得性边界、样本偏差或模型简化假设，在相关章节末尾或附注中**集中说明一次**即可，严禁在每一段末尾重复免责。

---

## 3. 引用格式、期间标注与假设分离

- **每一句含事实数字的句子，句末带它的引用**：句末（句号或分号之前）标一组 `[引用N]`，该句的事实数字共享这一组；同一来源再次被引用时沿用同一编号即可（例：`2Q26 收入同比增长 18%，OPM 13.2% [引用1]。`）。不要紧跟每个数字逐个标注，也不要把引用归并到段尾或节尾——发布前的数字核验按“同一句”绑定引用，跨句不认，第二句起不标引用的数字会失去确定性来源。需要交代来源身份时（卖方机构、管理层、专家），身份在句中自然写明（如“管理层在 2Q26 电话会上表示……”“UBS 估计……”），编号留在句末。
- **一条底表 / 模型引用只对应一个数字**：指向底表键（`f:<key>`，如 `f:rev_q8`、`f:net_cash_basic`）或模型单元格（`model:model/<TICKER>-model-v<NN>.xlsx!<Sheet>!<Cell>`）的引用只能核验一个数值；同一句里有多个来自底表或模型的数字时，句末引用组并列写出（如 `……收入 xx、营业利润 yy [引用1][引用2]。`，两个编号分别指向各自的键 / 单元格）。`evidence:` 与 `prov:` 引用可覆盖同句多个数字。
- **表格逐格标注；来源行只用于整表同源**：
  1. **数字和 `[引用N]` 写在同一单元格内**（如 `| 512 亿美元 [引用1] |`）——来自模型的多行数字（如三情景表、House vs consensus 对比表）必须逐格各标各自单元格的引用，派生列（“差异”“较现价”这类由同行其他数字算出的列）不挂其他单元格的引用；
  2. **整表数字同源时**（如同一份法定报表），在表头分隔行之后、第一条数据行之前加一行来源行，首格写 `来源`（或 `数据来源` / `source` / `sources`），该行标明 `[引用N]`——来源行的引用会挂到整张表每一个未标注的单元格，只放能覆盖全表的引用，不放只对应单个单元格的 `model:` 引用。不要把来源写在表尾、表外表注或单独一列“来源”里。
- **期间写在句内**：含事实数字的句子在同句写明期间（`2Q26`、`1H26`、`FY2025`、`TTM`、`FY27E`），同句多个数字属于同一期间时只在第一个数字前写一次；表格在列头 / 行头标期间。口径切换（GAAP↔Non-GAAP、季度↔年度、报表币种变化）在句中点明，同比/环比标 `YoY` / `QoQ`。禁止整段罗列没有期间锚点的裸数字。
- **假设、阈值与情景数字加豁免标记，并与事实数字分行书写**：分析师自行设定的预测假设、confirm/warn/break 观察阈值、多空情景推演数字，必须在句中显式标注 **`[假设]`**、**`[估计]`**、**`[示意]`** 或 **`[举例]`**（支持 `[]`、`（）`、`〔〕` 三种括号；来自本方 Excel 模型单元格的预测数用 `[引用N]` 指向 `model:model/<TICKER>-model-v<NN>.xlsx!<Sheet>!<Cell>`）。带 `[假设]`、`[估计]`、`[示意]`、`[举例]` 标记的句子，必须与包含事实数字的句子**分开写在不同的行**，不在同一行混写假设数字与事实数字，也不把假设标记与外部引用混在同一括号内。

## 4. 中文交付风味与禁用词表

- **中文交付，保留英文专业术语**：正文一律使用自然、准确的现代中文撰写；高频金融与行业标准术语直接保留英文缩写（如 `EBITDA`、`FCF`、`SBC`、`ROIC`、`WACC`、`Take rate`、`GMV`、`ARPU`、`Capex`、`YoY`、`QoQ`、`Beat/Miss`、`Guidance`、`Bogey`、`Thesis`、`Debate`），无需强行生造拗口中文译名。
- **句式干净、主谓清楚**：
  - 明确写出动作主体（"管理层下调了……"、"大客户削减了……"），少用含糊的被动句（"被认为……"、"得到了提升"）。
  - **直陈句，少用否定式/防御式套路**（初稿就避开，不要留给语言审查返工）：想肯定 B 就直接写 B——不写"不是 A，而是 B""并非……而是……""这并不意味着……"；不写"需要指出的是 / 值得注意的是 / 客观来说"这类预防式开场，不对没人提出的反对意见先行辩解，一句里不叠多个"可能 / 或许 / 在一定程度上"。**承载事实或判断的否定必须保留**（如"公司未披露 TPU 外售金额""本轮未取得该数据""不加仓"），与判断强度一起不许削。
  - **不用英文直译句式**：动词和句子结构用自然中文——不写"3Q 打印"（写"3Q 财报"）、"落地在 X"（写"为 X / 达到 X"）、"指引的上修"（写"上调指引"）、"beat 了预期"（写"超出预期"）、"这对于……来说是一个积极的信号"（直接说影响）。英文术语本身（capex、guidance、backlog、bull/bear 等）按约定保留——直译的是句式和动词，不是术语。正反例见 `.agents/skills/dalton-language/SKILL.md` 与其 `references/examples.md`。
  - **不凑三点、不追求形式对称**：有几条硬证据就写几条，不要为了凑齐"三大驱动、四个风险"而把同一件事拆成三条同义反复。
  - **禁止奖状式开场**：严禁使用"作为全球领先的行业巨头，公司凭借卓越的战略定力……"之类公关稿辞令。
- **绝对禁用词表**：
  - 严禁在报告中使用互联网黑话与空洞套话：**"赋能"、"闭环"、"抓手"、"心智"、"组合拳"、"护城河不断深化"、"呈现出……态势"、"体现了……韧性"**。

## 5. 数字、比例、区间与货币符号规范

1. **"相当于" vs "占"**：
   - 当分子并非分母的子集时（例如比较资产负债表项与利润表项，或资本开支与净利润），必须写 **"Capex 相当于净利润的 x%"** 或 **"净现金相当于市值的 x%"**，**严禁写成"Capex 占净利润的 x%"**（只有部分属于整体时才能写"占"，如"广告收入占总收入的 98%"）。
2. **区间连接符**：
   - 数字区间统一写 **"至"** 或 **"–"**（如 `15% 至 18%`、`120 亿至 130 亿美元`），**严禁使用波浪号 `~`**（易与约等于号混淆，且在 Markdown 中易触发删除线渲染错误）。
3. **货币金额写法（禁用 `$` 符号）**：
   - 正文与表格说明中的美元金额统一写 **`USD`** 或 **`美元`**（如 `USD 45.2B`、`452 亿美元`、`每股 18.5 美元`），**严禁使用 `$` 符号**（避免 Markdown 渲染器将同行的两个 `$` 之间内容误解析为 LaTeX 数学公式导致排版错乱）。

## 6. 一句话收尾（The One-Line Closing）

每一份初次覆盖报告（Preview）、完整投资备忘录（Memo）或深度复盘的结尾，必须用下面这句标准格式做极简收束（中英皆可，通常保留英文句式骨架以确保锐度）：

> **"The stock works if [X — 核心多头兑现的具体条件与数字]; it breaks if [Y — 核心逻辑证伪的具体条件与数字]; the key debate is [Z — 当前市场分歧最大、未来 1–2 个季度见分晓的唯一焦点问题]."**

**末尾合并为单一 `## 引用` 节**：所有报告正文统一使用 `[引用N]`（多空讨论股东回报支线用 `[回报引用N]`）标注来源，文末统一合并为一节 `## 引用`（不再另设独立的来源章节，且 `## 引用` 之后不再有其他正文章节）。每行一条，冒号后先写核验可识别的目标前缀（`evidence:`、`model:`、`prov:`、`f:`），空格后在括号内写出可读来源说明（来源类型｜机构/作者｜标题或内容概述｜日期｜文档 id / accession / 链接）：

```markdown
## 引用
[引用1]: evidence:E-20261023-01 （法定财报｜Meta Platforms｜FY2025 10-K 分部披露｜2026-02-01｜accession 0001326801-26-000012）
[引用2]: model:model/META-model-v01.xlsx!DCF!C12 （本方模型｜DCF 估值页核心输出｜2026-10-23｜model/META-model-v01.xlsx）
[引用3]: prov:3f6c9a12-0000-0000-0000-000000000001 （卖方研报｜Morgan Stanley｜META 3Q26 Preview｜2026-10-12｜alphaengine:doc_123）
[引用4]: f:rev_q8 （数字底表｜最近一季营业收入｜2Q26｜research/2026-10-23-fc/facts.md）
```
