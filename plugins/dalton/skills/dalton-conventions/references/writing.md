# 中文交付与写作规范（Writing & Delivery Guide）

## 1. 判断先行与段落组织（Conclusion First）

- 通用的判断与写作规则见系统提示词的研究写作部分。
- **段落先给结论，再写证据与传导**：每段围绕一个论点展开，第一句直接写结论，随后用带期间的事实数字和业务机制说明它如何影响收入、margin（利润率）、FCF（自由现金流）或估值倍数；证伪与改判条件集中放在「跟踪」节（多空讨论 Debate 的「我的判断」下就近一句），不在每个自然段末尾机械重复。

---

## 2. 正文给人读

1. **用户可见文字不出现机器内部标识与报错原文**（总规则见系统提示词「用户可见文字」，以下为 Dalton 报告与推送中的具体替换规范）：
   - 进度消息、任务卡标题、最终回复、报告正文、推送正文（飞书 / Discord 推送）和外部渠道正文一律不写知识层编号（如论点支柱 `P1`、多空分歧 `D1`、触发器 `T25`、待验证项 `V-013`、证据 `E-20261023-01` 等）、枚举值（如 `NO_CHANGE`、`THESIS_STRENGTHENED`、`clearly_above`、`sector_beta`、`act_now`、`wait_evidence`、`frozen_pre_event=true` 等）、英文字段名（如 `stance`、`conviction`、`actionability`、`binding_constraint`、`breakeven_verdict`、`b_row`、`debate_ids`、`0y`、`+1y` 等）、函数名、脚本名（如 `price_reaction.py`、`implied_model.py`、`move_quant.py`）、工具名（如 `knowledge_update`、`researchdata`）、知识文件版本号和工具报错原文。工作区文件路径（如 `data/consensus/...`、`predictions.json`）正文不写；链接目标可以包含定位文件所需的真实路径。例外：报告内部给读者看的章节序号和短名（如多空讨论里的“Debate 1：云业务利润率能否守住”）可以保留，禁止的是知识层内部编号（`D1`、`P1`、`V-013` 这类）。
   - **正面写法**：提到某条分歧或支柱时，用一句话直接写出它的具体内容；提到胜率裁决时写中文（“显著高于门槛”“在门槛附近”“低于门槛”“无法判断”；裁决所评的方向写“做多 / 做空”），提到事件五词结论时写中文（“无变化”“强化”“削弱”“证伪”“新论点”），提到方向、确信度、行动分类与限制变量时写中文（方向：“看多 / 看空 / 中性 / 暂不表态”；确信度：“高 / 中 / 低”，暂不表态时为“无”；行动分类：“立即行动 / 等待买点 / 等待证据 / 暂不参与”；限制变量：“无 / 价格 / 关键证据待验证 / 催化剂时点 / 下行路径风险 / 交易执行条件”）；数据缺口与取数失败的披露位置见本节第 5 条（不贴工具报错原文，渠道失败不得写成“没有新信息”）。
   - **示例 1**：
     - 改前：`结论：强化（THESIS_STRENGTHENED）——1Q26 实际业绩与 2Q26 指引同时验证 P1（美国餐饮主业现金牛稳固）、P2（新零售与杂货规模效应跨过盈亏平衡拐点）及 D1（2026 年投资周期属于可控的短期节奏错配）。`
     - 改后：`结论：强化——1Q26 实际业绩与 2Q26 指引同时验证美国餐饮主业现金流稳固、新零售与杂货业务跨过盈亏平衡拐点，并印证 2026 年平台投入属于可控的短期节奏错配。`

2. **机器文件照常写编号与枚举；`## 引用` 保留核验前缀，`## 来源` 行末可带文档编号**：
   - 知识层编号、枚举值与字段名照常写进 JSON、知识层写入（`knowledge_update`、`knowledge_append_verdict`）和机器文件（如 `predictions.json`、`*.gates.json`）。
   - 文末 `## 引用` 节每一行的格式不变：冒号后**先写**核验目标（`evidence:`、`model:`、`prov:`、`f:` 开头，发布前的数字核验只认冒号后的第一段），然后在括号里写人能读懂的来源说明（来源类型、机构、标题、日期），文档编号（`doc_id`、accession〔SEC 申报受理号〕等）放在括号内最后。`## 来源` 节（推送和快讯）每行先写来源说明，文档编号（`doc_id`、accession、`mail:ID`、`funda:ID` 等）放在行末，方便追溯。正文段落里不写文档编号。

3. **常见买方英文术语照常直接用，不建术语替换表**：
   - 买方日常使用的英文专业术语直接保留英文（如 `EBITDA`〔税息折旧及摊销前利润〕、`FCF`〔自由现金流〕、`SBC`〔股权激励费用〕、`ROIC`〔投入资本回报率〕、`WACC`〔加权平均资本成本〕、`GMV`〔商品交易总额〕、`GOV`〔订单总金额〕、`ARR`〔年度经常性收入〕、`NRR`〔净收入留存率〕、`RPO`〔剩余履约义务〕、`YoY`〔同比〕、`QoQ`〔环比〕、`guidance`〔业绩指引〕、`bogey`〔买方隐含预期门槛〕、`beat/miss`〔超预期/低于预期〕、`bull/bear`〔多头/空头情景〕、`initiate`〔首次建仓〕、`add`〔加仓〕、`trim`〔减仓〕、`hold`〔持有〕、`exit`〔清仓〕等），不建术语替换表，不生造拗口中文译名。

4. **一句话里的事实数字一般不超过两个**：
   - 单句中的事实数字一般不超过两个；超过两个时拆成多句，或改写成小表，不要在一句话里连塞五到八个数字和多层括号。

5. **口径、来源分歧、未取得的数据与模型简化：缺口只说一次，放对位置**：
   - **报告正文**：会改变结论、确信度或行动的数据缺口，在相关判断第一次出现的地方用一句话写清影响；其余缺口、检索范围、失败原因、口径换算说明、不同来源的数字分歧和模型简化假设，统一只放文末 `## 附注`（放在 `## 引用` 之前；周报中的 `## 口径与缺口` 节承担附注的作用），同一缺口全文只说明一次，后文直接使用已经限定过的判断。按任务范围没做、也不影响结论的检查，只记在内部底稿，不写进正文或附注。渠道失败仍不得写成“没有新信息 / 没有数据 / 无新增”。不要把缺口说明散落在正文各段里，不要塞进 `## 引用` 节，也不要写进表格来源行（表格来源行只用来放整表共用的 `[引用N]`）。
   - **推送稿**：通知卡片只识别 `## 结论`、`## 要点`、`## 下一步验证`、`## 来源` 四节（没有 `## 附注`），因此会改变结论或行动的缺口在判断处用一句话写清影响，其余取数失败或数据缺口只写成 `## 来源` 节里的一句人话（例如“本轮未取得专家访谈：连接超时”），不写工具报错原文，也不在正文与 `## 来源` 重复写两遍。

## 3. 口径警告的正向改写与集中声明

- **少写否定式免责套话，直接改写成准确口径 + 投资含义**：
  - 避免在正文里反复堆砌"需要注意这个数字不是……、不能直接说明……、不代表……"等防御性废话。
  - **正确写法**：先把指标改成准确口径陈述事实，紧接着写它的投资含义（例如：不要写"第三方抓取的调用量不代表真实收入"，直接写"第三方监测显示 2Q26 API 调用量环比增长 40%（单源估计），但由于大客户阶梯降价，预计对 2Q26 云收入的净拉动约为 +2 个百分点"）。
- **同一缺口、限定与改判条件全文只留一处**：按第 2 节第 5 条放对位置后，后文直接使用已限定过的判断，不再重复交代；成稿和每次修订后，写稿人必须通读全文完成跨章节去重（语言审查工具每次只看一节）。

## 4. 引用格式、期间标注与假设分离

- **每一句含事实数字的句子，句末带它的引用**：句末（句号或分号之前）标一组 `[引用N]`，该句的事实数字共享这一组；同一来源再次被引用时沿用同一编号即可（例：`2Q26 收入同比增长 18%，OPM 13.2% [引用1]。`）。不要紧跟每个数字逐个标注，也不要把引用归并到段尾或节尾——发布前的数字核验按“同一句”绑定引用，跨句不认，第二句起不标引用的数字会失去确定性来源。需要交代来源身份时（卖方机构、管理层、专家），身份在句中自然写明（如“管理层在 2Q26 电话会上表示……”“UBS 估计……”），编号留在句末。
- **一条底表 / 模型引用只对应一个数字**：指向底表键（`f:<key>`，如 `f:rev_q8`、`f:net_cash_basic`）或模型单元格（`model:model/<TICKER>-model-v<NN>.xlsx!<Sheet>!<Cell>`）的引用只能核验一个数值；同一句里有多个来自底表或模型的数字时，句末引用组并列写出（如 `……收入 xx、营业利润 yy [引用1][引用2]。`，两个编号分别指向各自的键 / 单元格）。`evidence:` 与 `prov:` 引用可覆盖同句多个数字。
- **表格逐格标注；来源行只用于整表同源**：
  1. **数字和 `[引用N]` 写在同一单元格内**（如 `| 512 亿美元 [引用1] |`）——来自模型的多行数字（如三情景表、House vs consensus 对比表）必须逐格各标各自单元格的引用，派生列（“差异”“较现价”这类由同行其他数字算出的列）不挂其他单元格的引用；
  2. **整表数字同源时**（如同一份法定报表），在表头分隔行之后、第一条数据行之前加一行来源行，首格写 `来源`（或 `数据来源` / `source` / `sources`），该行标明 `[引用N]`——来源行的引用会挂到整张表每一个未标注的单元格，只放能覆盖全表的引用，不放只对应单个单元格的 `model:` 引用。不要把来源写在表尾、表外表注或单独一列“来源”里。
- **期间写在句内**：含事实数字的句子在同句写明期间（`2Q26`、`1H26`、`FY2025`、`TTM`、`FY27E`），同句多个数字属于同一期间时只在第一个数字前写一次；表格在列头 / 行头标期间。口径切换（GAAP↔Non-GAAP、季度↔年度、报表币种变化）在句中点明，同比/环比标 `YoY` / `QoQ`。禁止整段罗列没有期间锚点的裸数字。
- **假设、阈值与情景数字按句或按格加豁免标记，且假设和事实数字不写在同一句里**：发布前的数字核验按句（以中英文句末标点〔。！？；!?;，以及句尾的英文句号〕断句，换行也算断开）或按表格单元格逐格豁免——分析师自行设定的预测假设、证实/警告/证伪观察阈值、多空情景推演数字，必须在**假设数字所在的那一句或那一格里**显式标注 **`[假设]`**、**`[估计]`**、**`[示意]`**、**`[举例]`** 或 **`[阈值]`**（支持 `[]`、`（）`、`〔〕` 三种括号；来自本方 Excel 模型单元格的预测数不标假设，改用 `[引用N]` 指向 `model:model/<TICKER>-model-v<NN>.xlsx!<Sheet>!<Cell>`）。**标记不会传到下一句（过句末标点或换行即重新起算）或相邻单元格，在段前或表前只写一次不够**；同时，**假设和事实数字不写在同一句里**，也不把假设标记与外部引用混在同一括号内。句内或单元格内标明 `[假设]` / `[估计]` 后，不再追加“这是我们的假设，不是事实”之类的解释句。

普通聊天使用紧邻主张的来源链接。推送使用对应技能规定的 `## 来源`。同一份交付物采用一种引用格式。子代理内部交付还须保留可检查的原始来源位置。

## 5. 数字、比例、区间与货币符号规范

1. **"相当于" vs "占"**：
   - 当分子并非分母的子集时（例如比较资产负债表项与利润表项，或资本开支与净利润），必须写 **"Capex 相当于净利润的 x%"** 或 **"净现金相当于市值的 x%"**，**严禁写成"Capex 占净利润的 x%"**（只有部分属于整体时才能写"占"，如"广告收入占总收入的 98%"）。
2. **区间连接符**：
   - 数字区间统一写 **"至"** 或 **"–"**（如 `15% 至 18%`、`120 亿至 130 亿美元`），**严禁使用波浪号 `~`**（易与约等于号混淆，且在 Markdown 中易触发删除线渲染错误）。
3. **货币金额写法（禁用 `$` 符号）**：
   - 正文与表格说明中的美元金额统一写 **`USD`** 或 **`美元`**（如 `USD 45.2B`、`452 亿美元`、`每股 18.5 美元`），**严禁使用 `$` 符号**（避免 Markdown 渲染器将同行的两个 `$` 之间内容误解析为 LaTeX 数学公式导致排版错乱）。

## 6. 一句话收尾

每一份初次覆盖报告（Preview）、完整投资备忘录（Memo）或深度复盘的结尾，必须用下面这句中文标准格式做极简收束：

> **成立的条件：[X — 核心多头兑现的具体条件与数字]；失效的条件：[Y — 核心逻辑证伪的具体条件与数字]；最关键的分歧：[Z — 当前市场分歧最大、未来 1–2 个季度见分晓的唯一焦点问题]。**

发布前的数字核验按句（句末标点或换行断开，见本文第 4 节）或按表格单元格豁免；上面这句收尾句用分号「；」断开了三个分句（半角 `;` 同样断句），因此每个分句里的数字必须各自带 `[假设]` 或 `[引用N]`（前一个分句的标记不会传到分号之后的下一个分句）。

**末尾合并为单一 `## 引用` 节**：所有报告正文统一使用 `[引用N]`（多空讨论股东回报支线用 `[回报引用N]`）标注来源，文末统一合并为一节 `## 引用`（如有 `## 附注`，放在 `## 引用` 之前；不再另设独立的来源章节，且 `## 引用` 之后不再有其他正文章节）。每行一条，冒号后先写核验可识别的目标前缀（`evidence:`、`model:`、`prov:`、`f:`），空格后在括号内写出可读来源说明（来源类型｜机构/作者｜标题或内容概述｜日期｜文档 id / accession〔SEC 申报受理号〕 / 链接）：

```markdown
## 引用
[引用1]: evidence:E-20261023-01 （法定财报｜Meta Platforms｜FY2025 10-K 分部披露｜2026-02-01｜accession 0001326801-26-000012）
[引用2]: model:model/META-model-v01.xlsx!DCF!C12 （本方模型｜DCF 估值页核心输出｜2026-10-23｜model/META-model-v01.xlsx）
[引用3]: prov:3f6c9a12-0000-0000-0000-000000000001 （卖方研报｜Morgan Stanley｜META 3Q26 Preview｜2026-10-12｜alphaengine:doc_123）
[引用4]: f:rev_q8 （数字底表｜最近一季营业收入｜2Q26｜research/2026-10-23-fc/facts.md）
```
