# 事件五词结论与持续跟踪（Event Verdicts & Active Tracking）

## 1. 五词结论规范（Five-Word Verdicts）

在持续覆盖（Active Coverage）中，每次处理财报、指引更新、同业交叉数据、监管政策、专家访谈或股价异常波动时，必须给出且仅给出以下**五词结论**之一：

| 正式词形（JSON / 数据库必填） | 中文短标签（Markdown / 界面显示） | 适用标准与触发动作 |
|---|---|---|
| **`NO_CHANGE`** | **无变化** | 事件符合预期或属短期噪音，核心驱动因子（Drivers）与 Thesis 支柱未发生实质偏移。无需修改模型核心假设。 |
| **`THESIS_STRENGTHENED`** | **强化** | **相对当前投资论点**：支撑论点的证据增强——核心驱动因子向论点预期的方向兑现、关键争议（Debate）向有利方向收敛。经营"改善"或"恶化"本身不是判据，方向取决于持仓立场（空头立场下，经营恶化属于论点强化，见下方动作表）。动作按下方 stance × verdict 查表。 |
| **`THESIS_WEAKENED`** | **削弱** | **相对当前投资论点**：与论点预期相反的证据出现——某项驱动因子不及论点假设、转化路径延后，或反方逻辑出现初步迹象，但尚未触及硬性证伪线（多头立场下的经营恶化、空头立场下的经营改善都属此类）。收紧跟踪阈值；动作按下方 stance × verdict 查表。 |
| **`THESIS_BROKEN`** | **证伪** | 触发预设的硬性证伪条件（Falsifier / Kill Criteria），核心投资逻辑不复存在。立即启动零基审视并写入复盘教训（`lessons.md`）；动作按下方 stance × verdict 查表。 |
| **`NEW_THESIS`** | **新论点** | 公司发生重大业务转型、并购重组、新产品周期或管理层更迭，原有框架不再适用，需要新建 Thesis 支柱或 Debate。 |

- **词形硬性规定**：在 JSON（如 `knowledge_append_verdict` 参数）与数据库 `dalton_verdicts`（渲染为 `verdicts.md`）中**一律使用Playbook正式词形**（`NO_CHANGE`、`THESIS_STRENGTHENED`、`THESIS_WEAKENED`、`THESIS_BROKEN`、`NEW_THESIS`），**严禁使用 `STRENGTHENED`、`WEAKENED`、`BROKEN` 等旧简写**；在给 PM 读的报告正文、笔记与推送正文中一律只写对应的**中文短标签**（无变化、强化、削弱、证伪、新论点），不把英文枚举写进正文。

### 动作映射：按 stance × verdict 查表

verdict（上文五词结论）描述的是论点本身的变化，动作要看 stance（持仓方向：long 看多 / short 看空 / neutral 中性 / no_view 暂不表态）。同一个 verdict 在看多和看空立场下指向相反的动作：

| verdict | long 立场下的倾向 | short 立场下的倾向 |
|---|---|---|
| `THESIS_STRENGTHENED` | 经营兑现 = 论点强化：上调预测，倾向维持或加仓（`add`/`press`） | 经营恶化 = 论点强化：倾向维持或加空 |
| `THESIS_WEAKENED` | 论点削弱：收紧跟踪阈值，倾向减仓（`trim`） | 论点被削弱（经营好于空头假设）：倾向回补（`cover`） |
| `THESIS_BROKEN` | 论点证伪：启动零基审视，建议退出（`exit`） | 空头论点证伪：建议回补（`cover`）并复盘 |
| `NO_CHANGE` / `NEW_THESIS` | 与持仓立场无关：按事件本身处理（`NEW_THESIS` 重建支柱后重新表态） | 同左 |

- 表中的动作是**研究倾向，不是自动动作**：仓位动词的可用性仍受输入门槛约束（缺持仓信息时只禁仓位动作、不禁方向判断，见 `dalton-conventions/SKILL.md` §2 优先级表），实际执行由 PM 决定。
- **论点强化之后必须重算价格吸引力**：基本面虽按预期方向兑现，但若股价涨幅（或空头下的跌幅）已超出基本面改善幅度，必须如实写出"论点强化、赔率下降"（对照 §3 的已计价〔priced-in〕审视）；禁止只写论点强化而不评估当前价格下的赔率。

## 2. 每条事件记录的必填五要素

每次调用 `knowledge_append_verdict` 或撰写事件点评时，必须完整包含以下五项：
1. **事件描述与发生日期（Event & Date）**：具体发生了什么客观事件或披露。
2. **映射的目标节点（Target Pillar / Debate / Driver）**：明确指向知识层中的哪个 Thesis 支柱、哪条核心争议或哪个业务驱动因子（JSON 参数 `affected` 填编号如 `P1`、`D2`、`K1`；报告正文和推送正文用一句话直接写出该支柱、分歧或驱动变量的具体内容，不写编号）。
3. **五词结论（Verdict）**：JSON 填上述 5 个正式枚举值之一，报告正文和推送正文写中文短标签（无变化 / 强化 / 削弱 / 证伪 / 新论点）。
4. **量化证据与来源（Evidence & Source Attribution）**：实际数字 vs 预期数字（写明公司指引、卖方一致预期或买方 bogey 的各自口径与出处）。
5. **下一项待验证事项与日期（Next Verification & Date）**：为了确认该趋势延续或反转，下一步要看什么具体指标、在什么时间点验证（同步更新至 `agenda.md`）。

## 3. 验证后的二阶追问：是否 Priced In？催化剂是否耗尽？

论点强化（`THESIS_STRENGTHENED`，相对当前投资论点而言，不分多空立场）不等于股价必然继续上涨。每次事件验证后，必须追加两项市场面审视：
1. **是否已经 Priced In？**：结合财报前股价累计涨幅、期权隐含波动率、买方 bogey 及当日盘后/次日市场反应，判断好消息是否已被充分计价。如果显著 Beat 但股价高开低走或下跌，必须分析市场在担心哪个二阶变量（如 Capex 激增侵蚀下年 FCF、高基数导致明年增速见顶）。
2. **催化剂是否已经用尽（Catalyst Exhaustion）？**：如果原先期待的重大催化剂已经落地，未来 1–2 个季度是否进入"催化剂真空期"？若是，需如实提示短期赔率变化。

## 4. 错误归因与写入 `lessons.md`（五大错误分类）

当实际披露推翻了我们的预测，或事件结论为 `THESIS_WEAKENED` / `THESIS_BROKEN` 时，禁止含糊带过，必须将判断偏差归类为以下**五类错误**之一，并写入 `lessons.md`：

1. **事实错误（`fact`）**：漏看了公开披露文件、口径理解错误，或轻信了低质量/未交叉验证的单一来源。
2. **时机错误（`timing`）**：大方向判断正确，但高估了产品放量、提价落地或行业出清的速度（早就是错）。
3. **传导错误（`transmission`）**：上游指标（如用户时长、订单量）确实增长，但向收入、毛利率或自由现金流的传导机制被费用、折旧或补贴截留。
4. **估值错误（`valuation`）**：业绩预测准确，但高估了市场愿意给该业务属性或周期阶段的估值倍数（Multiple De-rating）。
5. **执行错误（`execution`）**：低估了管理层战略摇摆、组织内耗、激进并购或合规事故对业务基本盘的破坏力。

## 5. 日常跟踪纪律：只写重要变化，无变化不推送

- **拒绝噪音与刷存在感**：每日/每周例行扫描时，如果某家公司只有例行公关稿、无新意的卖方重复研报或正常市场随波波动（结论为 `NO_CHANGE` 且无新增高质量证据），**在静默日志中记账即可，不向 PM 推送废话日报**。
- **推送门槛**：只有当出现改变 Debate 天平的新证据、关键 KPI 触及预警阈值、重要专家/管理层新口径或显著个股 Alpha 异动时，才生成正式简报。
- **无论是否推送，报告正文必须单独回答“赔率变了没有”**：对照上一版三情景（`Bear` / `Base` / `Bull`）价带与所需胜率，写明这次事件之后当前价格下的赔率是变好、变差还是没变，以及原因。`dalton-stock-move` 与 `dalton-thesis-delta` 的每条 `verdict` 必须把这一判断写进 `payoff_assessment` 字段：赔率没变填 `{"changed": false, "reason": "none"}`；变了填 `{"changed": true, "reason": "<枚举值>"}`，`reason` 从 `"price_crossed_band"`（我们的三情景假设未改，单纯股价越过上一版三情景或买点价带）、`"scenario_revised"`（我们重算并调整了三情景的 EPS 或估值倍数假设）、`"expectations_migrated"`（我们的三情景假设未改，但 Street consensus 或买方 bogey 明显移动）、`"catalyst_expired"`（支撑催化剂已兑现、落空或过期）、`"protection_failed"`（生存、价值或路径任一下行保护条件失效）中按主因选一个；其他技能暂只在正文回答，不写该字段。
- **`NO_CHANGE` 但赔率变了，仍要推送（`dalton-stock-move`）**：价格触发异动归因中，若股价越过三情景或买点价带，或三情景假设、市场预期、催化剂、下行保护的变化改变了当前价格下的赔率，即使论点没变（`verdict` 为 `"NO_CHANGE"`、且 `payoff_assessment.changed` 为 `true`），仍必须向 PM 推送：按 `dalton-stock-move` 第 7 步写入推送稿并完成两轮 `check_language`，推送稿 `## 结论` 首句写明“论点未变、赔率变了：<一句话写清具体原因>”（通知卡片标题由系统按同一格式自动生成）。
- **禁止为了触发推送而改写五词结论**：`verdict` 只按论点本身的实际变化填写（见 §1 的动作表），赔率变化只写进 `payoff_assessment`。把 `"NO_CHANGE"` 改写成 `"THESIS_STRENGTHENED"` 等论点变化枚举来换取推送，属于造假，一律禁止。

## 6. 股价异动归因流程（先量化 Beta/Alpha，再按四步查因）

当覆盖标的出现显著单日或周度异动（如单日涨跌超 ±3% 或显著偏离同组）时，严格按以下两步执行（参考 `stock-move-analyzer` 纪律）：

### 第一步：先量化，剥离板块 Beta 与个股 Alpha
- 读取 `coverage.yaml` 中该标的所属的同组公司（`peers`）与板块 ETF（`etfs`），用 `yfinance` 拉取同一时间窗口的涨跌幅。
- 计算：
  - **个股涨跌幅** vs **大盘指数（SPY/QQQ）涨跌幅**
  - **个股涨跌幅** vs **板块 ETF 及同组 Peers 中位数涨跌幅**
- 先定性：**这是全行业共同的板块 Beta（如宏观利率、行业政策、同业龙头财报带动），还是本公司独有的个股 Alpha？**

### 第二步：按四级顺序排查原因（严禁倒序把股吧传闻当主因）
1. **监管 Filing 与公司官方公告**：先查 `sec`（8-K、Form 4 内部人减持、13D/G）或交易所公告、公司 IR 新闻稿、高管公开出席行业会议表态。
2. **权威财经新闻与同业/上下游联动**：查主流财经通讯社、上下游大客户/供应商最新财报或指引、监管/关税/反垄断动态。
3. **卖方研报与买方销售笔记**：查 `alphaengine`、`sales-notes`、`tmtb` 是否有大行升降级（Upgrade/Downgrade）、目标价调整、渠道调研（Channel Check）或专家会纪要流出。
4. **社媒与社区讨论（最后辅助）**：最后才查看市场传闻，且必须在报告中明确标为"市场传闻 / 未经证实"，不得与前三级硬证据混为一谈。
