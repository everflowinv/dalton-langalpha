# 数字与单位保真规范

正文有金额、比例、日期、数量或范围时读这份。

## 1. 处理顺序

数字写错不是润色问题，是事实错误。处理任何数字都按这个顺序走，不跳步：

1. 抄录原文完整表达，不只抄裸值；
2. 解析数值和原单位；
3. 换算成统一基准值；
4. 与同一语境的另一语言版本交叉核对；
5. 写入成稿；
6. 从成稿反向换算，复核回原文。

不得从增长率、行业常识或"看起来更合理"反推原文漏了小数点。除非转写里有直接证据，`78 billion` 就是 780 亿，不是 78 亿。

## 2. 数字账本

每个实质数字至少记这些字段（可记在线程 scratchpad 草稿中，不进成稿正文）：

| 字段 | 内容 |
|---|---|
| 原文 | 完整数字短语 |
| 数值 | 解析后的数字或范围 |
| 原单位 | billion、亿美元、%、tokens/day 等 |
| 规范化值 | 金额统一到基础币种单位；比例统一到百分比 |
| 修饰对象 | ARR、训练成本、客户数、毛利率等 |
| 时间 | 月末、年度、指引期等 |
| 说话人 | 谁提出或确认 |
| 状态 | 原话 / 翻译 / 派生 / 外部核对 / 待核 |

数字必须和修饰对象一起移动。不能把"训练算力占比 48%"接到"推理毛利率"上，也不能把 ARR 翻成应收账款。

## 3. 中英金额换算

先换算到基础币种单位，再选中文表达：

| 英文 | 基础值 | 中文等值 |
|---|---:|---:|
| 1 thousand | 1,000 | 1,000 |
| 1 million | 1,000,000 | 100 万 / 0.01 亿 |
| 1 billion | 1,000,000,000 | 10 亿 |
| 1 trillion | 1,000,000,000,000 | 1 万亿 / 10,000 亿 |

必须记住的对照：

- `65 billion USD = 650 亿美元`
- `78 billion USD = 780 亿美元`
- `110 billion USD = 1,100 亿美元`
- `12–14 billion USD = 120 亿至 140 亿美元`
- `200 million USD = 2 亿美元`

`billion` 和中文"亿"不是一一对应。英文数值写成"亿"要乘 10，`million` 写成"万"要乘 100。这是投研纪要里最常见的量级错误。

币种不明确时不得补成美元。`$`、USD、US dollars 规范为"美元"；`HK$`、HKD 为"港元"；`RMB`、CNY、yuan 为"人民币元"。其他币种保留原币种，不做汇率折算——受访者说港元就写港元，不许换成美元。

A 股和港股稿件同样适用：`12.5 亿元人民币`、`3 亿港元` 要和美元金额一样进账本。

## 4. 双语交叉核对

中英双语转写常有同一内容的两份 ASR 或现场翻译。两份都只是证据，都不保证正确：

1. 分别抽取英文和中文数字，不从一份复制到另一份；
2. 换算到同一基准值后比较；
3. 等值时，优先保留原发言语言的明确表达，用自然中文呈现；
4. 不等值时，检查单位遗漏、范围误切、币种变化、日期串位和 ASR 错误；
5. 闭不上环时，正文保留最接近原始发言的表达并加 `[数字待核：…]`，在校正说明里列冲突。不能凭行业数据或增长率挑一个。

双语里出现"英文数字 + 中文单位"时也要完整换算，不能默认中文已经处理过量级。

## 5. 派生值与原话矛盾

三类数字分开处理：

- **原话值**：受访者直接说的金额、比例或范围，正文默认保留；
- **派生值**：算出来的结果，必须标明是计算值，不能冒充原话；
- **外部核对值**：来自公开资料，只用于说明差异，不能替换受访者观点。

至少复算这几项：增长率 `(新值-旧值)/旧值`、份额金额 `总额×占比`、差额 `目标-当前`、分项合计是否约等于总额或 100%、范围上下限顺序和单位是否一致。

原话算术不成立时，用"保留原话 + 明示矛盾"。例如当前 ARR 780 亿美元、目标 1,100 亿美元，差额应为 320 亿；受访者说"仍差 400 亿至 420 亿美元"，既不能静默改成 320 亿，也不能不加说明地照抄。

## 6. 自动审计

含金额的稿件交付前跑一次：

```bash
python3 .agents/skills/dalton-transcript-polish/scripts/audit_numeric_units.py \
  transcriptions/<job_id>/transcript.txt transcriptions/<job_id>/polished_transcript.md
```

（非音频输入时将第一个参数替换为源文本路径，第二个参数替换为 `published/` 下的成稿路径。）

脚本会抽取 USD / HKD / CNY 三种币种的显式金额（英文 `million/billion/trillion` 与中文"万、百万、亿、万亿"），按币种分别换算并列出清单，对成稿中在源稿同币种里找不到等值表达的金额报 `WARN`。命中 10 倍差时提示量级错误，同一数值换了币种时提示币种漂移。

其他参数：`--json` 机读输出，`--fail-on-warn` 有告警时返回非零，`self-test` 自检，`--default-currency` 指定行内无币种标记时的记账币种。

每条 `WARN` 必须人工判断：

- 是错误就改稿；
- 是复算值就在正文或校正说明标为计算结果；
- 是外部核对值就给来源；
- 是原话冲突就保留冲突并说明；
- 是脚本解析错就在审计记录里写清楚，**不要为了消掉报警去改正文**。

脚本的边界：只看金额，不看百分比、日期和数量；不知道两个相同数值是否指同一指标；`¥` / `￥` 默认按人民币处理，日元稿件必须人工复核。即使输出 `OK`，仍要逐项核对数字账本。

## 7. 交付前检查

- 每个英文量级词都做了换算，不是直接抄数字；
- 每个中文金额都能反向还原回原英文金额；
- 金额、币种、比例、日期、单位和修饰对象没有被拆散；
- 范围保留了上下限，"小于、超过、接近、约"都还在；
- 同一数字在全文没有两个不等值版本；
- 双语冲突、算术矛盾和脚本报警都有处理记录；
- 没有因为外部常识或趋势判断擅自补小数点、改单位或改原话。
