# 周会持仓与业绩核对

业绩与仓位这一节每次都写。材料是本场已保存的转写，路径相对工作区。

## 1. 锁定本场资料

会议日期是运行目录名里的 Asia/Shanghai 公历日。读取：

- `state/tmeet-weekly-minutes/runs/<会议日期>/selected.json`
- `state/tmeet-weekly-minutes/runs/<会议日期>/minutes.json`
- `state/tmeet-weekly-minutes/runs/<会议日期>/todos.json`
- `state/tmeet-weekly-minutes/runs/<会议日期>/transcript.json`

先核对会议日期、主题和 `record_file_id`，摘要和转写必须来自同一场会。
`transcript.json` 在脚本确认段落编号 pid 从 0 起连续、无重复，且末页 `more` 为 false 后才写入文件。pid 不连续、有重复，或超过 50 页时，`fetch` 报错，这份转写不要写成“已完整获取”。整份都读过时写“已完整获取”。只核了其中几段时写“已核对相关原文”。

## 2. 先检索，再读上下文

在已保存的 `transcript.json` 里检索这些词，把 `<会议日期>` 换成会议日期：

```bash
rg -n -i -C 2 '仓位|持仓|净值|收益率|回撤|敞口|performance|year.to.date|买了|卖了|买入|卖出|加仓|减仓|清仓|拿住|put|call|我自己' state/tmeet-weekly-minutes/runs/<会议日期>/transcript.json
```

命中只是定位。接着读完整段和相邻段。长输出被截断时按段落编号 pid 分段读，先看整句再判断账户主体和买卖方向。
拟写入摘要的每一项记下：标的、账户主体、工具、买卖方向、持有或操作状态、规模、成交日期、发言人、时间或 pid、原句。缺的字段写「未披露」。
再用公司名和转写里的叫法查一次全文，核对后文有没有补充或冲突。后文的实际操作覆盖前文的计划。

## 3. 逐项判定状态

仓位分成三类，个人和第三方交易另列：

- 「本次确认持有或已执行调整」：「已经买了」「先拿住不动」归入这一类，并保留具体工具。会上首次提及但未说明本周成交日期的已执行仓位，也归入这一类，不因首次提及就归入本周新交易。提及时间和成交时间分开。
- 「成交日期明确的本周新交易」：成交日期落在本场会议所在周，并且原文有明确执行表述时，才写入这一类。
- 「讨论方案或待确认」：「可能买回」「再跌就买」「反弹后减」归入这一类。

按原文区分买 put（看跌期权）保护、put spread（看跌期权价差）和卖 put 收取权利金。原文只说「做 put」时，方向写「待确认」。三者的风险敞口不同。
每项保留发言人、录制时间或段落编号 pid，并核对账户主体、工具、买卖方向和时态。口语或转写不清的字段写「待确认」。
保留「很小」「没啥仓位」的原话，并注明比例「未披露」。「没啥仓位」按原话保留，不写成清仓。口语大小、零仓位和具体百分比分开写。
ETF（交易型开放式指数基金）代码、方向或数量听不清时保留原词，并标「待确认」。行情、同音词和上周持仓只作对照，不补成确定答案。
按「我们基金」「我自己」「朋友」标明账户主体。第三方交易单列。观点相同，基金持仓仍以原文为准。
上周持仓只作带日期的背景。旧持仓只在本场明确确认时更新。本场未提到的标的写「本次未更新」。

## 4. 拆开业绩数字与评价

先查净值、收益率、回撤和总敞口、净敞口。整份都没有这些具体数字时写「本次未披露量化业绩及敞口」，再列有出处的定性评价和回撤复盘。净值、收益率或敞口只缺其中几项时，缺的那几项逐项写「未披露」，同时保留有出处的定性评价。
基金的量化业绩、定性评价和回撤复盘分开写。
每个回撤或收益数字写清账户、期间和比较基准。个人历史经历、个股跌幅和情景下行空间留在各自的语境。个人历史回撤、同业样本评价和本基金当期业绩分开。基金当期回撤只用来自基金账户的数字。
「在我认识的基金里中等偏上」写成发言人的有限样本评价，不升成正式同业排名。
收益贡献只依据真实持仓或净值文件。文件标有 `demo: true` 时排除。缺数据时写明需要托管月报、券商对账单或 PM（基金经理）持仓表。

## 5. 用户同时问纪要、持仓和业绩

开头写会议日期、主要已确认仓位及是否披露量化业绩。然后按「持仓及操作」「基金业绩与回撤」「周会主要判断」「待办」来写。
持仓节注明「仅为会议披露，非完整持仓表」。未提及的资产保持未知。
每条待办写事项、负责人、截止时间和已有进展。原文没有的字段写「未明确」。
已有飞书纪要时，链接取 `state/tmeet-weekly-minutes/runs/<会议日期>/doc.json`。按需回复只发当前对话，不另建文档，也不发群。
公司经营数字、政策判断和估值写成发言人观点，并说明这一节是会议原文核对。需要独立投资判断时另行核对一手资料。
