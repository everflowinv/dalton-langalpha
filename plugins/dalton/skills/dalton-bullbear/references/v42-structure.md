# Bull / Bear Discussion 成稿结构与写作规则（v4.2）

本文件定义 Dalton 个股 Bull / Bear Discussion 完整成稿（v4.2 格式）的章节结构、引用规范、检索方法与自检要求。写稿前请先读 `.agents/skills/dalton-conventions/SKILL.md`。

---

## 0. 核心原则：判断先行与数字纪律

1. **判断先行**
   - 开头第一段「核心判断」直接写当前立场、最重要依据和决定回报的主要变量。
   - 各 Debate 的「我的判断」先回答更支持哪一边（偏 Bull / 偏 Bear / 中性，置信度高 / 中 / 低），再用简短理由说明取舍。仅罗列限制却缺少判断的段落算审稿 P1。
   - 关键论点按「判断 → 证据 → 对收入、利润、现金或估值的影响 → 改判条件」组织。
   - 遇到“不是 / 不能 / 不代表 / 不等于”式提醒，先找它保护的事实，直接写正确口径及投资含义；实质限制就近简述一次并说明影响，完整口径、未取得材料放在股东回报附录或信源覆盖段。

2. **不编造、带期间、一句一源**
   - 正文里每个数字都要能回指本轮工具结果、任务指定的输入文件（一致预期快照、财务体检表、股东回报摘要）或知识层文件；查不到就标 `N/A` 或“本轮未取得”。
   - **每个数字都要带期间**：季度写 `2Q26`、`3Q25`，半年写 `1H26`，年度写 `FY2025`、`2025 年`，滚动写 `过去 12 个月（至 YYYY-MM-DD）`。同一句里多个数字属于同一期间，只在第一个数字前写一次期间；期间变了重新标。禁止裸写“活跃客户 -2.8%、GMV -1.6%”。
   - **每个事实数字所在句必带引用，引用紧跟数字之后**，格式固定为 `数字（来源身份 [引用N]）`：
     - 卖方：写机构名，如 `（UBS [引用9]）`、`（Morgan Stanley [引用3]）`
     - 管理层：写 `（管理层 [引用5]）`；能落到具体人写 `（CFO [引用5]）`
     - 专家：写身份不写姓名，如 `（云计算渠道专家 [引用14]）`
     - 社区：写平台加用户名，如 `（X 用户 @xxx [引用12]）`
     - 公司披露、公告、行情：写 `（10-Q [引用6]）`、`（10-K [引用2]）`、`（行情 [引用1]）`
   - **一句多源分别紧跟数字，表格引用写在同格或表内来源行**：同一句包含不同来源的数字时各自紧跟标注，或拆成两句；含事实数字的表格采用“数字与 `[引用N]` 写在同一格”或“表内加一行、首格写 `来源` 并标 `[引用N]`”两种写法之一（表外单独一行的表注或单独一列“来源”不会挂到其他数据单元格）。正文不写日期、文档 id、链接，这些全部放到文末 `## 引用`。
   - **全文同一来源的同一数字只完整写一次**；同一份来源全文只占一个 `[引用N]` 序号，第二次引用沿用原序号。
   - **假设、阈值与情景标记（与事实数字分行书写）**：自己做的预测假设、兑现阈值和情景数字写成 `[假设] 数字（推导依据）`（或 `[估计]` / `[示意]` / `[举例]`）；带 `[假设]` 等标记的句子必须与包含事实数字的句子分开写在不同的行，不在同一行混写假设数字与事实数字，也不把假设标记与外部引用混写。
   - **分析师提问未确认数字**：电话会提问中出现但管理层未明确确认的数字，必须标为“分析师提问口径，管理层未确认”，不得作为管理层指引或已确认 KPI。
   - **股东回报回指**：股东回报支线的结论在主稿二至八节引用时写 `（见第一节股东回报）`，不占主稿 `[引用N]` 序号，不重新计算、不改口径。

## 2. 各节具体写作规则

### 第二节：市场共识（`## 二、市场共识：现在 price in 的是什么`）
- 固定三个父 bullet：`- **看多的人默认成立**：`、`- **看空的人默认成立**：`、`- **两边都不争的**：`。
- **父 bullet 冒号后不跟任何文字**，具体条目全部写成缩进子 bullet（`  - `）。
- 子 bullet 条数严格受检：`看多的人默认成立` 2–4 条、`看空的人默认成立` 2–4 条、`两边都不争的` 1–3 条。每条不超过 45 个汉字，句尾带来源。
- **不把价格走势当共识**：不写股价涨跌、不写技术位、不空泛复述估值倍数（除非估值倍数本身是共识的一部分，且说明了它隐含的增长/利润率假设）。三块之外不写额外段落。

### 第三节：Top N debates（`## 三、Top N debates：真正有分歧的地方`）
- N 一般为 3–5。每个 Debate 标题格式：`### Debate k：{可证伪问题}（{≤12 字短名}）`。
- 每个 Debate 固定包含以下五个一级 bullet（`- **块名**：`），全部用 bullet 组织，不写自然段：
  1. `- **分歧**：` 一句话把可证伪的分歧问清楚（不要“前景好不好”这种不可证伪问法）。
  2. `- **Bull 怎么看**：` 下挂 2–4 条子 bullet，每条一个论点加证据并标来源；最后一条固定写 `比共识乐观在哪：……`。
  3. `- **Bear 怎么看**：` 下挂 2–4 条子 bullet，最后一条固定写 `比共识悲观在哪：……`。
  4. `- **双方最强反驳**：` 下挂两条子 bullet：`Bull 对 Bear：……` 与 `Bear 对 Bull：……`，具体到数据或机制。
  5. `- **我的判断**：` 下挂三条子 bullet：
     - `立场与置信度：偏 Bull / 偏 Bear / 中性，高 / 中 / 低（和上一版比有变化就说原因）`
     - `依赖假设：[假设] ……（推导依据）`
     - `改判条件：……`（必须可观察、可量化）
- 固定写「我的判断」，**严禁出现「你的判断」**。

### 第四节：Earnings revision map（`## 四、Earnings revision map`）
- 直接引用准备阶段产出的一致预期快照（`consensus.md`）与 `implied_model.py` 结果，不重算：
  - **一致预期现状**：下一财年 EPS 与收入、7/30/90 天轨迹、近 30 天上调/下调家数、买方预期（whisper，来自 sales-notes / TMTB）。若当期 EPS low-high 区间异常宽或 90 天陡降，核对是否有分析师计入一次性项目（减值、和解、税项）。
  - **修正分层**：收入、费用/capex（或利润率）、一次性项目三层各自往哪边修，按对 EPS 影响大小排序。
  - **隐含费用对比**：`[假设] 卖方费用比一致预期隐含空间多 X，对应 EPS 少 Y（快照敏感度）`（此行不要含 `→` 符号）。
- **驱动变量回指规则**：Revenue、Margin、EPS 三组驱动各 ≤3 条。**凡含 `→` 的行，必须写成 `变量名 → Debate N 短名 → 敏感度（[假设] 变量变动 X 对应收入/EPS 变动 Y）`**（必须带 `Debate N`，不能只写短名）。EPS 驱动只列 revenue/margin 之外的税率、利息、股本、一次性项目。

### 第五节：Catalyst & KPI（`## 五、Catalyst & KPI`）
- 按 **3 个月 / 6 个月 / 12 个月** 分组：列出 `事件｜日期或窗口｜检验哪个 debate（Debate N 短名）｜bull/bear 兑现阈值（[假设]）`。
- **KPI**：列 3–5 个核心高频/季报指标，写明当前值（带期间与来源）、bull 区间、bear 区间。
- **近期财报风险**：若 3 个月内有财报，写清财报日期、过去 4 次财报次日涨跌（来自一致预期快照）、买方持仓/拥挤度（来自 sales-notes / TMTB）、公司通常在哪次财报给下一年指引 → 给出本次财报风险方向与置信度。

### 第六节：财务体检（`## 六、财务体检`）
- 只解读准备阶段生成的 `fincheck.md`，不重拉资产负债表和现金流。**结论先行，全节非空行 ≤12 行**：
  - `- **结论**：` 触发项数量、最关键的科目（加粗）及指向（经营性还是财务性，关联哪个 Debate 短名）。无触发时写 `资产负债表没有触发提示项`。
  - `- **核心项目**：` 1–2 项，格式 `**科目**：期间金额、占总资产比例、同比 → 机制解释一句话 → 关联 Debate N 短名（或与 debate 无关）`。
  - `- **其他触发项**：` 简要一行。不重复现金、有息债务、递延收入。
  - `- **Capex**：` 三年序列，固定写 **“Capex 相当于净利润的 x%”**（严禁写“占净利润的 x%”），并与**同一年份**的 D&A 对比。

### 第七节：Variant perception（`## 七、Variant perception`）
- 只写**一个**核心非共识观点：市场当前最可能低估或漏掉的是什么、为什么没看到（信息盲区 / 时间维度错配 / 叙事惯性）、体现在第四节哪个驱动变量上、何时验证。不重复第三节已展开的常规多空论点。

### 第八节：一句话（`## 八、一句话`）
- 固定句式：`The stock works if X; it breaks if Y; the key debate is Z.`
- **严禁裸写 `Debate N`**（如禁止 `Debate 1 和 Debate 2 同时成立`）：每次提到 debate 都必须自带可证伪条件，写成 `具体可观察条件（debate N 短名）`。

### 第九节与文末 `## 引用`：股东回报附录与引用
- 若有 PM 要求的额外专题章节，放在第八节之后、`<!-- INSERT:return_appendix -->` 之前；「股东回报附录」（`## 九、股东回报附录` 或顺延章节）与文末 `## 引用` 永远作为全文最后两节收尾，`## 引用` 之后不得再有其他章节（不再另设独立的 `## 十、引用清单`）。
- 在文末单一 `## 引用` 节内先写出 **信源覆盖段**（说明内部库 sales-notes / tmtb / funda-ai / company-wiki、AlphaEngine、Guidepoint、SEC filing 等各来源命中数与实际采用数，未取得的写明原因），紧接着在同一 `## 引用` 节下将引用清单与核验映射合并写在一起（每条一行，按序号排列，同时供 `bb_check.py` 与 `numbers.py` 解析）：
  ```markdown
  ## 引用

  **信源覆盖**：
  - 内部研究库（sales-notes / tmtb / funda-ai / company-wiki）：{命中数与实际采用数，未覆盖原因}
  - AlphaEngine（foreign_report / sell_side_comment / meeting_minutes）：{命中数与采用数}
  - Guidepoint 专家纪要：{命中数与采用数}
  - 一手披露（SEC filing / 电话会）：{覆盖期次与 accession}

  [引用1]: evidence:E-20261023-01 （行情｜Yahoo Finance｜价格与一致预期快照｜2026-10-18｜data/consensus/...）
  [引用2]: evidence:E-20261023-02 （公告｜SEC 10-Q｜2Q26 季报与指引｜2026-08-05｜accession 0001326801-...（超 3 个月））
  [引用3]: model:model/META-model-v01.xlsx!DCF!C12 （本方模型｜DCF 估值页核心假设｜2026-10-18｜model/META-model-v01.xlsx）
  [回报引用1]: evidence:E-20261023-04 （行情｜yfinance / anchors.json｜市值与汇率锚点｜2026-10-18｜anchors.json）
  ```
  超过 3 个月的材料在日期后标 `（超 3 个月）`；冒号后第一个词必须为 `evidence:`、`model:`、`prov:`、`f:` 之一。审稿必查：`## 引用` 表存在且每个 `[引用N]` / `[回报引用N]` 都能在表里找到。

## 3. 信源检索清单（主稿阶段必查）

1. **内部库**：`researchdata.research` 查 `sales-notes`、`tmtb`、`funda-ai`、`company-wiki`（公司名、核心产品、capex/费用/指引）。Wiki 中的专家访谈与管理层交流已过合规，标明日期、专家身份（不写姓名）及可靠性后照常引用。
2. **AlphaEngine**：先用 `researchdata.research(route="alphaengine", operation="list_filters")` 查各类别 `type_ids`，按外资深度报告、卖方点评、会议纪要分开调用 `researchdata.research(route="alphaengine", operation="search_library", query=..., start=..., end=..., params={"type_ids": [...], "sort": "relevance"})`；重要结论调 `operation="get_document"` 读正文。
3. **Guidepoint**：英文检索（`route="guidepoint", operation="search_library"`），原文引用 ≤20 个英文词并附出处。
4. **一手披露**：`dalton_sec.list_filings` 与 `researchdata.finance(route="sec")` 读最新定期报告与电话会（`route="transcript"`）。
5. **AI 收入与费用专项**：涉及 AI 商业化或 AI 提效时，按 `references/ai-revenue-rules.md` 执行。

## 4. 机械检查（`scripts/bb_check.py`）

主稿写完及合并后，必须运行：
```bash
python .agents/skills/dalton-bullbear/scripts/bb_check.py <draft_or_main.md>
```
确保以下检查项 **0 WARN**：
1. 正文 `[引用N]` 集合与 `## 十、引用清单` 条目集合完全相等；
2. 回报支线 `[回报引用N]` 集合与附录 `**回报引用清单**` 集合完全相等；
3. 第一节股东回报非空行 ≤48 行（目标 ≤40 行）；
4. 第二节市场共识含三个父 bullet，且子 bullet 数量分别为 2–4、2–4、1–3，父 bullet 同行无正文；
5. 第三节每个 `### Debate` 五个一级 bullet 块（`分歧`、`Bull 怎么看`、`Bear 怎么看`、`双方最强反驳`、`我的判断`）齐全；
6. 第四节所有含 `→` 的行都包含 `→ Debate N`；
7. 第六节财务体检非空行 ≤12 行，且全文不出现“占净利润”（应写“相当于净利润的”）；
8. 第八节一句话不出现 `Debate N 和/与/或/同时/成立/兑现` 等裸编号写法；
9. 引用清单位于文末，其后无其他章节；
10. 全文不出现“你的判断”。
