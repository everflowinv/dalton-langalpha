# 多空日跟踪共用研究与写作规则

每轮先读完本文件，再读本公司的 `references/<ticker小写>-rules.md`。判断是否重要、如何改工作底稿、如何写卡片，共用步骤在这里。本公司专属的数字、期间、口径、全文上限和停止条件在本公司规则里。四家相同的一致预期自动阈值写在下面「是否重要」。

日常跟踪只改工作区 `research/tracker/thesis.md`。导入档案 `research/tracker/imported-<ticker小写>/thesis.md` 保持原字节。工作区根目录的财报 `thesis.md` 和 `data/thesis.json` 不是这份工作底稿，不覆盖，也不把工作底稿写进通用知识 JSON。

网页检索与抓取用 WebSearch 与 WebFetch。内部研究、AlphaEngine 和 SEC 公告用现有研究数据工具（researchdata）；本公司规则里的 SEC 调用是 `finance`。卡片文件由 `scripts/render_card.py` 构造，发送由 `automation_report` 完成。

## 工作底稿要保住的内容

工作底稿包含以下章节：核心判断、多空分歧（Debate，编号 D1 至 D7）、关键经营指标（KPI）、修正假设、专家来源可靠性、观点池、待核实线索、变更记录。每条数据写明来源和时间。

无论本轮是否重要，都用编辑工具改有变化的章节，保留结构和其余内容，不整篇重写。需要更新的部分：

- 关键经营指标（KPI）的当前值。
- 一致预期基线，写上读取日期。
- 观点池新增条目：机构或身份、日期、一句话。
- 多空分歧 D1 至 D7 的当前倾向和置信度；有变化时写原因。出现工作底稿里没有的新分歧时补上。
- 催化剂日历。
- 「最近更新」改成本轮时间。
- 本轮打不开原文、又只有单一来源的线索写入「待核实线索」：来源、日期、URL、已核 0 轮。
- 末尾「变更记录」追加一行 `YYYY-MM-DD HH:MM | material=yes/no | 一句话`。

和观点池重复的说法不算新信息。

工作区已有的通用知识文件（`agent.md` 中的托管块，以及 debate、drivers、management、verdicts、agenda 等材料）只读参考，不调用写入接口覆盖财报研究数据。

## 每轮必读的材料

1. 完整读 `research/tracker/thesis.md`。
2. 完整读本轮 `packet.md`，再逐个读其中列出的摘录文件（excerpts）。内部研究材料没有新增时，仍然完成本节的新闻、X 和待核实线索检查。
3. AlphaEngine 新文档先看摘要。只挑带新数字的读全文。新数字的范围、全文篇数上限和停止错误码按本公司规则。全文调用保留完整 `doc_id`，包括 `_inst_` 等后缀，不转成整数，不截断。全文额度和同周期其他跟踪共用。遇到本公司规则列出的停止条件时停止读全文，只用摘要，并在本轮更新里注明。
4. SEC 新公告按本公司规则核对 8-K 条目号（item）、99.1 新闻稿附件、10-Q 关键词和融资文件。8-K 先看条目号（item）。财报 8-K 列出最新一份的附件，再读 99.1 新闻稿。融资文件同样读附件。
5. 新闻摘要和 X 上的消息类帖子（券商动作、公司数字）只当线索。券商评级或目标价变化，要在 AlphaEngine、卖方邮件（sales notes）或可打开的新闻原文里找到第二个来源，才写成事实。只有单一来源时写明「据 X 帖」或「据 MarketBeat」这类归属。核原文用 WebFetch。页面 403、挑战页或打不开时换一个来源；仍打不开就按单一来源处理。
6. 「待核实线索」每轮最多核 3 条，即使本轮数据包里没再出现也要核。用 WebFetch 打开原文，或在 AlphaEngine、卖方邮件（sales notes）找第二来源。核实后移进观点池，并按下一节判断是否重要。核不到就把「已核 N 轮」加 1，满 3 轮或超过 5 天就删掉。
7. 专家访谈和管理层交流按本公司规则里已经确认的合规范围使用。写法注明日期和自述身份，并说明和公司披露、第三方数据、其他专家是对得上还是有冲突。专家给的经营数字按单一来源估计写，和公司披露、第三方数据分开写。工作底稿「专家来源可靠性」记录各位专家已被验证或被推翻的说法；新材料要对照这一节判断可信度。财报出来后按本公司规则列出的说法逐条对照，更新这一节。

## 新闻与 X

本轮固定网页查询以数据包里的记录和本公司规则为准，每条都查。结果写入本轮 `research/tracker/<run_id>/news.md`，保留标题、来源、日期、URL，以及检索状态和原文打开状态。

X 帖子只读数据包里已采集的「X 帖子」一节。

- 作者是基金经理、分析师、前卖方或独立研究，并且帖子给出数字和推理的，算专业基本面观点。
- 新闻搬运号的帖子按上面的线索处理。纯技术面、喊单、段子跳过。
- 专业观点写入观点池，格式 `X @handle（身份）MM/DD，赞 N：一句话`，写清它支持哪条 Debate 的哪一方。赞 100 以上或收藏多，并且提出观点池里没有的论据或数字的，优先记。
- 权重低于 TMTB（买方科技简报）、卖方邮件（sales notes）、AlphaEngine 和专家访谈。专业帖里引用的卖方动作和公司数字，仍要第二来源。
- 卡片里最多展示 3 条专业帖。单条专业帖只进观点池。

账号池：

- 某位作者连续给出有数字、有逻辑的基本面分析，用本技能 `state.py` 的 `x-pool add` 加入。研究依据必填，写明身份和依据。同时覆盖多家时写本公司股票代码（ticker）和其他股票代码。适用范围保留本公司股票代码或 ALL。
- 池里的账号转成主要在喊单或搬运时，用 `x-pool remove` 移出，写明原因。历史记录保留。
- 每轮最多新增 3 位。重复加入同一作者不重复计数。计数以 `state.py` 写入的账号池记录为准。
- 不编造作者简介（profile）、粉丝数或用户编号（rest_id）。资料缺失就在记录里写明缺失；以后有可靠资料再更新。已导入的作者缓存里已有的字段可以沿用。

## 是否重要

满足任一条就是 `material=yes`。四家共用的一致预期自动阈值是：下一财年每股收益（EPS）相对上一轮 1.0%，相对 7 日 2.0%；下一财年收入相对上一轮 0.7%；平均目标价相对上一轮 2.0%；下一财年每股收益（EPS）向下修正家数 7 日达到 5。主流券商改预测的年份和科目、公司事实和关键经营指标（KPI）阈值按本公司规则。共用的几条是：

- 多空分歧（Debate）：D1 至 D7 某条的当前倾向或置信度需要改，或出现工作底稿里没有的新分歧。
- 买方私下预期（whisper）、仓位拥挤度或对冲基金调仓有明显变化，来源是卖方邮件（sales notes）或 TMTB（买方科技简报）。
- 催化剂新增、改期或取消。
- X：至少两个互不相关的专业账号提出观点池里没有的同一个新论据，或专业帖带出的新数据已由第二来源核实。
- 股价自动触发（单日 4% 或 5 日 8%）并且能找到原因。找不到原因时只在工作底稿记一笔，不单独发卡片。

不算重要：重复观点池里的说法、单条 X 帖或搬运号转述、通用财报前瞻、只有一家小机构的目标价微调、没有新数字的评论。几条中等信息合在一起改变了修正方向或催化剂判断时，算重要。

内部研究材料没有新增，不代替上述是否重要的检查。新闻、X 和待核实线索仍然要做。

### 财报特别轮

财报 8-K（条目 Item 2.02）第一次出现在数据包的那一轮，一律算重要，按财报特别轮写。之后几轮回到上面的常规标准。卖方在财报后改预测，通常算重要。

各家的比较数字写在本公司规则的「财报特别轮」。这些数字是原底稿里这一轮财报要对照的比较值，保留期间和来源，不要改写成永久的当前数值。

## 盈利预测怎么拆

年度口径、一致预期含什么、要先拆开的投资收益和一次性项目，以及三层结构的名称，按本公司规则。写明哪一层动了，以及隐含费用空间的变化。没有变化就写「一致预期未动」。

## 卡片正文

只在 `material=yes` 时写 `research/tracker/<run_id>/card.md`。从第一个 `##` 开始。每个 `##` 渲染成一个加粗分栏。目标 2,500 字，硬上限 3,000 字。上限按卡片构造前的最终正文长度计算，含数字区间改写（把“-”写成“至”）和多空分歧（Debate）括号说明补注。超过 3,000 字时压缩新信息和来源后再构造，不自动截断，不发出半张卡片。

固定章节：

```markdown
## 判断
一到两句。先说这次变化让核心判断或哪条 Debate 往哪边动、置信度如何。判断没变时直接写「判断不变」，再说这次新信息强化了哪一边。

## 新信息
- 每条一个事实或观点：来源身份（机构、管理层、专家身份或平台）+ 内容 + 带期间的数字。

## 盈利预测修正
按本公司规则的三层写哪层动了；一致预期的变化；隐含费用空间的变化。没有变化就写「一致预期未动」。

## X 上的专业观点
本轮有值得看的专业帖时写，最多 3 条。
- @handle（身份）：观点一句话，赞 N，[原帖](url)

## 催化剂
新增或改期的事件和日期。没有就删掉这一栏。

## 改判条件
只在本轮有变化时写。没有就删掉这一栏。

## 来源
- [标题](url)，或「AlphaEngine 某券商 10/15 doc 150001501906778」这类可回溯的标识
- 有来源失败或只读到摘要时，最后加一条「数据备注：……」
```

写法：

- 中文。链接用 `[文字](url)`。不用表格，不用图片。
- 数字区间写「至」。金额写「美元」「亿美元」，不用 `$`。股票代码直接写本公司 ticker。
- 「来源」一栏由构造程序显示成灰色小字。
- 卡片读者看不到工作底稿。每条多空分歧（Debate）在卡片里第一次出现时写成 `D1（用一句话说这条分歧在争什么）`，之后可以只写编号。多空写「看多」「看空」。漏写括号时，构造程序用工作底稿里 `### D1 标题` 这种标题补上第一次出现，已有括号的不重复补，链接里的编号不补。
- 标题、副标题和公司标签由构造程序生成。`card.md` 不写这些，也不写接收方。
- 每个数字都能回指本轮工具结果或工作底稿里已有记录。本轮查不到的不写。事实、管理层说法、卖方预测、社区观点分开写清身份。

## 语言

卡片正文、工作底稿和最终回复要求：主语清楚，少用被动句，不堆砌行话，不强行凑满三条，不用客套开场，也不加结尾推销。

这三处自行撰写的文字不用防御性否定，包括「不代表」「并非」「而不是」「不能」「不构成」「不应」以及同义改写。先给判断，再写事实和依据。需要说明边界时，用正面、具体的句子写清证据范围、置信度和改判条件。逐字引文、命令和原始报错保持原样。
