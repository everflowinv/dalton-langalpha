# SPCX 跟踪研究与写作规则

每轮先读 `references/common-rules.md`（始终适用），再读取脚本（`state.py rules-path` 或 `collect`）输出的 `rules_path` 对应的本公司规则，不要自行判断或选择规则路径。共用的工作底稿、新闻线索、X、待核实线索、卡片章节和语言步骤在共用规则里。下面是 SpaceX（SPCX）专属的来源范围、关注重点和判断标准。

导入档案是 `research/tracker/imported-spcx/thesis.md`（若存在则保持原字节）。

## 每轮必读的材料

### 第 3 条（AlphaEngine）

AlphaEngine 新文档先看摘要。只挑带新数字的，最多 2 篇读全文。新数字包括收入或盈利预测、Starlink（星链）用户数与商业化收入、算力建设与资本开支（capex）、估值与融资倍数、买方调查。返回额度、`E_DESKTOP` 或 `E_UPSTREAM_API` 时停止读全文，只用摘要，并在本轮更新里注明。

### 第 4 条（SEC 新公告）

- 重点核查 `8-K` 与 `99.1` 附件。
- `8-K` 先看条目号（item），`finance(route="sec", operation="eight-k", ticker="SPCX", limit=2)`。
- 用 `finance(route="sec", operation="attachments", ticker="SPCX", form="8-K")` 列出最新一份的附件，再读 `99.1` 新闻稿，提取收入、盈利、算力、资本开支与估值/融资条款。

### 第 7 条（专家访谈）

专家访谈和管理层交流按已确认的合规范围使用。写法注明日期和自述身份，并说明与公司披露、第三方数据、其他专家是对得上还是有冲突。有新披露出来后，把专家关于发射频率、Starlink 增速、算力投入与资本开支的说法逐条核对，更新「专家来源可靠性」。

## 新闻与 X

内部研究库查询路线为 `sales-notes`（卖方邮件）、`tmtb`（买方科技简报），关键词围绕 `SpaceX`、`SPCX`、`xAI`、`Grok`、`Starlink`、`星链`。

本轮两条固定网页查询，以数据包里的记录为准：

- `SpaceX Starlink xAI Grok valuation revenue capex IPO news`
- `SpaceX Starship Elon Musk xAI compute funding SEC 8-K news`

X 重点跟踪 Elon Musk（`@elonmusk`）、xAI 官方账号（`@xai`）及 SpaceX / Starlink 官方账号（`@SpaceX`、`@Starlink`）发布的实质动态，以及基本面专业账号。账号池里，同时覆盖多家时可以写多家股票代码，适用范围保留 `SPCX` 或 `ALL`。

## 是否重要

满足任一条就是 `material=yes`。共用的多空分歧（Debate）、买方仓位、催化剂、X 和股价条款在共用规则里。SpaceX 专属的几条是：

- 一致预期与行情：数据包自动触发项里有下一财年每股收益（EPS）、收入或平均目标价阈值触发（数据稀疏或暂无公开覆盖阶段若指标标注「暂无」，只作记录，按其余事实与研究证据判断）。或者主流券商/研究机构调整收入或盈利预测、估值基准或目标价，且改动幅度或理由是观点池里没有的。
- 公司事实与重点关注：
  - 收入或盈利预测的新披露或大幅调整；
  - 算力建设、数据中心或资本开支规模与节奏变化；
  - 一级/二级市场估值、融资、并购或整合进展；
  - SEC `8-K` 与 `99.1` 附件的重要公告；
  - 直接改变多空分歧（Debate）倾向或置信度的新证据（Starlink 商业化与现金流、星舰发射与可复用进展、xAI/Grok 算力与商业协同）。
- 关键经营指标（KPI）越过工作底稿里写的阈值。

## 盈利预测怎么拆

数据稀疏或刚上市阶段，一致预期与行情若尚缺数据，在数据包和工作底稿里如实标注「暂无」，按三层拆解已有数字与边际变化：

1. 收入层：发射服务收入、Starlink 用户数与每用户平均收入（ARPU）、xAI/Grok 商业化收入。
2. 成本与资本开支层：星舰研发与发射成本、卫星组网资本开支、算力集群资本开支与折旧。
3. 估值与资本层：最新融资或市场估值基准、股权结构变化与业务协同影响。

一致预期有变动时写明哪一层动了及隐含变化；尚无一致预期或未动时如实写「暂无」或「一致预期未动」。
