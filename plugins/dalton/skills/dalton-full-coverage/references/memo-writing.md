# 投资备忘录写作规范（`memo-writing.md`）

本文件定义 Dalton 买方完整覆盖投资备忘录（`drafts/<D>-memo.md`）的写作目标、章节结构、引用与数字纪律及校验标准。动笔前必须先读 `.agents/skills/dalton-conventions/SKILL.md`、`research/<D>-fc/facts.md`、`research/<D>-fc/questions.md` 与模型 `model/<TICKER>-model-v01.xlsx` 的输出。

---

## 一、写作目标：写给基金经理看

这份备忘录写给基金经理看：自然、直接、以判断为主线，数字只用来支撑论点。具体要求：

1. **每段先给判断**：一段一个论点，第一句就是结论；证据和数字跟在判断后面，只放支撑这个判断所必需的。结论不要埋在一串数字中间。
2. **用业务语言讲生意**：公司做什么、怎么赚钱、为什么能赚这个 margin、赚钱能持续吗。竞争格局讲机制（谁能抢这门生意、壁垒是什么），不堆同业财务表。
3. **每件事只写一遍**：摘要给判断和赔率，正文各节展开各自的判断，互不复述。12 问研究提纲（`questions.md`）与支线底稿文末的「逐题证据小结」是内部工作底稿，**不进正文**：写手按提纲的「论证章节」把各支线证据融入对应章节，不在正文按题号作答。
4. **计算过程放附录或 research 工作文件**：正文写结论和关键数字；推导、对账、逐季明细放 `## 附录` 或 `research/<D>-fc/` 下的底稿。
5. **信息缺口写它对判断的影响**：先写这个缺口让什么判断做不了，再写因此还能做什么判断，不逐项罗列“未披露”。例如：“我们难以跟踪公司的订单情况，也就难以比市场更好地预判 4–8 个季度的收入增速；我们能做的判断是 consensus 仍明显偏低。”
6. **术语**：买方常用的英文术语直接用（margin、consensus、EPS、CapEx、backlog、OPM、TAM、IRR 等），不逐一翻译；研究流程里的内部词汇（底表、底表键、口径代号、诊断、review-ready 等）不进正文——数字直接写，口径用业务语言说清。
7. **篇幅**：摘要不超过一页；其他各节按内容需要，建议公司与商业模式 2–4 页、核心投资逻辑与争议 2–3 页、财务预测与估值 2–3 页、风险 1 页以内、管理层 1–2 页、跟踪 1 页以内。**不设字数下限，也没有硬性上限**——但重复比长更糟。

## 二、章节结构与各节要求（二级标题名称逐字遵守）

`validate_memo.py` 与 `research_structure.py` 校验以下二级标题的名称与顺序（各节内部用三级小节自由组织；「行业与竞争」视公司而定，可按下面的规则并入上一节）：

```markdown
# {公司名}（{TICKER}）投资备忘录

## 摘要
一页以内。开头两行写基本信息与当前建议：代码 / 基准日期 / 股价（日期）/ 市值 /
EV（企业价值）/ 当前核心估值倍数（如 NTM P/E）/ 30 日均成交额；
当前建议写明方向（long / short / neutral / no_view）、确信度（高 / 中 / 低）、
当前动作（现在建仓 / 等回落至某价带建仓 / 等某项带期限的证据验证后建仓 / 暂不参与）
及主要顾虑（无 / 价格 / 证据 / 时机 / 下行风险 / 交易限制）。
随后 **5–7 条判断**：每条讲清一个判断及其业务机制，只放支撑结论的关键数字
（例如：“我们预测 27E EPS 32 美元，较 consensus 高 30%–40%；但场地开发挂钩新开工，
新开工放缓会同时压低收入和 margin，因此按 20x 27E P/E 设定观察价 650 美元（当前股价 800 美元）。”）。
随后**投委会四问**逐问回答（每问 1–2 句，缺任何一问审稿退回）：
① 什么在改变客户行为和公司的经济性？② 为什么这个解释比竞争解释更可信？
③ 市场在哪个环节判断错了？④ 看到什么我会认错（双向：看到什么减仓或回补、看到什么加仓或加空）？
最后列 **3–5 条关键跟踪点**（一句话一条，指向「跟踪」节）。

## 公司与商业模式
用业务语言讲清楚：公司具体做什么、怎么赚钱、为什么能赚这个 margin、这门生意能守多久
（Good Business 的三个问题——赚钱容易吗、赚钱多吗、赚钱久吗——在这里回答，不设子标题）。
- 发展沿革与关键转折（只讲影响今天生意的部分）
- 分部与利润池：收入规模最大的业务和增量利润最高的业务分别是什么
- 竞争格局：谁在抢这门生意、集中还是分散、壁垒的形成或侵蚀
- 收入确认与现金流转化（一段）：结合合同与结算机制说明收入如何确认、账面利润如何转化为
  自由现金流，点出近期趋势与异常项；Sloan、CFO/NI、CCC 等常规比率无异常时不逐个报数，
  计算明细放附录

## 行业与竞争
行业边界与规模结论（TAM 测算过程放附录）、产业链分工与定价权、周期位置、政策监管、全球对标。
（并入规则：若行业逻辑已在上一节讲透、无需单独成节，可删去本二级标题，改在「公司与商业模式」
末尾用三级标题 `### 行业与竞争` 简述；二选一，标题均只写 `行业与竞争`。）

## 核心投资逻辑与争议
- **市场现在怎么想**：当前 consensus 与市场叙事。叙事给时间线（什么事件、市场怎么解读、
  股价怎么反应），并交代股价表现——过去重估事件里 EPS 修正与倍数变化各贡献多少（对数分解放附录）。
- **我们哪里不同、为什么**（正文的重心）：先用一段总括——当前 consensus 隐含的核心假设是什么、
  我们的判断哪里不同、错误定价为什么还在（信息盲区 / 时间维度错配 / 叙事惯性 / 覆盖不足）；
  随后按 2–4 个核心争点分小节逐一展开业务机制、一手与专家证据、向收入 / margin / 现金流的传导。
- **现价隐含预期**：现价反推隐含的增速 / 利润率 / 资本开支要求，与我们的 Base 对比；
  与模型 `DCF`、`Street vs House` 页对齐。
- 与组合的关系（可选，一段以内）：股价与关键指数或主题因子的相关性、momentum 属性与回撤特征；
  未释放的定价或利润空间、隐含资产（如有）。

## 财务预测与估值
- **关键假设与理由**：逐项写假设值、与 consensus 的差异、依据（House vs consensus 对比表
  与模型 `Street vs House` 页一致）。假设的理由来自业务判断，不来自“模型算出来是”。
- **三情景与赔率**（与模型 `Scenarios` 页一致）：逐行情景写关键驱动假设、目标估值方法与倍数、
  目标价、较现价涨跌幅、**年化 IRR**，并写明**显式持有期限（月）**；表下写
  **上行/下行不对称比**（基准上行 / 悲观下行、乐观上行 / 悲观下行）。
  三情景之后、推导所需胜率之前检查是否存在**非线性机会**（倍数重估、盈利非线性释放、
  拥挤持仓叠加催化剂、反身性；有则写清触发机制，无则直接写“当前无明显的非线性机会”，
  不逐类罗列）。随后**所需胜率与赔率结论**按
  `.agents/skills/dalton-conventions/references/risk-reward.md` §2 第 4 条推导
  （base 测试权重 25% / 50% 两行、裁决四选一并写明方向 / 所用权重行 / 依据的 debate），
  结合核心分歧说明当前胜率是否足以覆盖赔率。
- **估值**：估值方法与目标倍数的理由必须来自业务属性——为什么这门生意配这个倍数、为什么给不到更高
  （例如：“场地开发挂钩新开工，新开工放缓会同时压低收入和 margin，因此 20x 27E P/E 是合理上限；
  即使后续业绩超预期，我们只会调高 EPS，不会上调估值倍数”）。DCF、可比公司、历史估值区间交叉印证，
  估值桥接与敏感度矩阵放附录。股权价值桥接须用业务语言交代净现金口径——扣除租赁、可转债等
  类债务与受限现金后的净现金，与账面净现金对照——以及折后隐含资产是否计入、计多少。
- **三层保护与失效条件**：生存 / 价值 / 路径，遵守 `risk-reward.md` §6 硬规则
  （不写单一“底价”；融资需求可写“未知”，但写“未知”时不得宣称生存保护充分）。

## 风险
简短。每条风险**一句话讲清机制**（触发 → 传导 → 对盈利或估值的影响），可附一个领先指标。
- **若一年后亏损 30%，最可能怎么发生**：2–3 条最强空方路径，写出空方最强的逻辑，不立稻草人
- 我们最脆弱的隐含假设（1–3 条：结论最依赖、尚未被证实的底层前提）

## 管理层
- 履历与战绩、治理结构（双重股权等，如有）
- **指引可信度**：C4 支线的过去 12 季 Guidance vs Actual 表 + 指引风格结论（保守 / 中性 / 激进、
  收入还是利润更保守、全年修正节奏）
- 薪酬考核（Proxy / DEF 14A）、持股与内部人交易（区分 10b5-1 与主动买卖）
- 资本配置与股东回报：过去 12 个月、近三年平均与未来 12 个月预期股东回报率，以及回购、分红
  与扣除 SBC 后的实际股本缩减（回购授权不算托底，只认股本净缩减）
- 必要时直接引用管理层原话佐证（注明说话人、场合与日期）——一段到位的原话胜过三段转述

## 跟踪
- **验证点与失效条件**：确认 / 警告 / 证伪阈值表（指标、阈值、越线怎么办、数据来源与频率）；
  越线动作直接写仓位动作（加仓 / 减仓 / 清仓并重审逻辑）
- **催化剂日历**：未来 3 / 6 / 12 个月的事件与观察指标
- **下一次要看什么**：下一份财报 / 数据发布时盯什么
- 节末用标准一句话收尾（见 `.agents/skills/dalton-conventions/references/writing.md` §6）：
  "The stock works if [X]; it breaks if [Y]; the key debate is [Z]."

## 附录
正文只写结论与关键数字，以下内容放这里（或 research/ 工作文件）：
- 三表摘要与模型假设明细；DCF / 目标价桥接与敏感度矩阵；估值对数分解
- 盈利质量计算明细（Sloan、CFO/NI、CCC）；净现金双口径与隐含资产拆分
- 产品体验表（toC）或从业者一线信号表（toB），来自 D 支线
- IR 访谈待问清单、信源覆盖说明

## 引用
格式见 `.agents/skills/dalton-conventions/references/writing.md` §6：文末单一 `## 引用` 节，
每行一条，`[引用N]: 前缀:目标 （来源类型｜机构/作者｜标题或内容｜日期｜文档 id / 链接）`；
底表引用用真实键名（如 `f:rev_q8`）。
```

## 三、引用与数字纪律

1. **数字出处铁律**：目标公司的历史财务、净现金、隐含资产、股东回报、盈利质量数字只取自
   `research/<D>-fc/facts.md`；预测、三情景、DCF 与敏感度数字只取自模型。正文**直接写数字与来源**，
   不写“底表”“键名”或单元格号——出处通过句末引用与文末引用表交代。
2. **引用、期间与假设标注**：遵守 `.agents/skills/dalton-conventions/references/writing.md` §3——
   每一句含事实数字的句子在句末带它的引用（同一来源可沿用同一编号）；一条 `f:<键名>` 或
   `model:…!<Sheet>!<Cell>` 引用只对应一个数字，同句多个底表 / 模型数字时句末并列多个编号；
   表格逐格标注（模型数字各标各自单元格的引用，派生列不挂其他单元格的引用），来源行只用于整表同源；
   期间写在句内、表格标在列头 / 行头；`[假设]` 等标记与事实数字分行。
3. **引用闭环**：正文的每个 `[引用N]` 必须在文末 `## 引用` 表里有对应条目，反之亦然
   （`validate_memo.py` 双向校验；`check_draft` 据此做发布前数字核验）。

## 四、写作与校验流程

1. **前置**：建模完成且 `recalc.py` 与 `audit.py --strict` 通过之后才开始写作——估值、三情景、
   House vs consensus 的数字全部来自模型，模型不在，写出来就要返工。
2. **一位写手一次成稿**：写手通读 `questions.md`（12 问研究提纲）、四条支线底稿（含文末逐题证据小结）、
   `facts.md` 与模型输出，按第二节的结构一次写成整篇备忘录（不再分段接力，避免各段复述上下文）。
   盘上已有成稿（resume 续跑）时沿用最新稿，不推倒重写。
3. **机械校验**：写完运行
   ```bash
   python .agents/skills/dalton-full-coverage/scripts/validate_memo.py --mode full drafts/<D>-memo.md \
     --questions research/<D>-fc/questions.md --research-dir research/<D>-fc
   ```
   到 **0 FAIL**。
4. **第 1 轮语言审查**：调用 `check_language(draft_path=…, round=1)`，按 `<草稿>.language.md` 清单修改
   （只改语言表达，不动事实、数字、术语、引用编号与判断强度），改完复跑第 3 步确认 0 FAIL。
5. **独立审稿与一轮修订**：`dalton-reviewer` 审稿；`revise` 则做**一轮**修订（P0 全改，模型改动按
   `.agents/skills/model-update/SKILL.md` 另存 v02）后复审；`block` 则停在草稿状态向 PM 汇报。
6. **第 2 轮语言审查（终稿）**：修订结束后、终稿定稿时调用 `check_language(round=2)` 按清单完成终稿
   语言修改；草稿有改动就再跑一次 round=2 复核（记录追加在同一 json），并复跑第 3 步确认 0 FAIL。
