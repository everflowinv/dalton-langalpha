# 基金模型格式手册

格式的作用：让人一眼分清哪些是公司披露的数字、哪些是我们的假设或估算、哪些是公式算出来的。

## 先判断用途，再定格式

每写一个单元格，先问它是哪一类（下表第一列），再用对应的格式：

1. **用户提供了模型**：在原模型**同一区块里找用途相同的单元格**，照它的格式写（不要只照抄相邻单元格——相邻的可能是不同用途，例如年度汇总列旁边是季度假设列）。原模型的习惯和下表不同时，以原模型为准（例如原模型历史年度的汇总公式用蓝字，就沿用）。
2. **新建模型或找不到参照**：用下表的默认格式。

`scripts/model_style.py` 提供两样工具：`python3 scripts/model_style.py profile <原模型.xlsx>` 输出原模型的格式画像（各类单元格常用的字体、颜色、底色、数字格式）；在 Python 里 `apply_cell_style(...)` 按单元格类型写格式，`clone_period_column_style(...)` 把已有期间列的格式复制到新增列。

## 单元格格式表（默认）

字体：英文和数字用 Arial 8 号；中文内容用等线 8 号（与原模型里中文行一致）。纯英文、纯数字的表全用 Arial 8 号即可。

| 单元格类型 | 字色 | 底色 | 字形 | 边框 | 数字格式 | 例子 |
|---|---|---|---|---|---|---|
| 历史实际值（公司披露、手工录入） | 蓝 `0000FF` | 无 | 正常 | 无 | 金额格式 | 2Q26 收入 `103,980` |
| 历史期我们的估算（未披露拆分、推算值） | 蓝 `0000FF` | 浅米黄 `FFFFC8`，或原表那种浅灰主题淡色（新建时用接近的浅灰） | 金额正常 / 百分比斜体 | 四边极细虚线（Excel 的 hair 边框） | 同类型 | 估算的历史 take rate `3.85%`，备注 `<GS 1117` |
| 预测驱动假设（增速、take rate、利润率、费用率、税率） | 蓝 `0000FF` | 浅米黄 `FFFFC8` | 百分比斜体；金额正常 | 四边极细虚线 | `0.0%` 或金额格式 | 3Q26E GMV 增速 `12.0%`；`=AZ21+0.3%` 也是假设 |
| 管理层指引等直接输入的金额 | 蓝 `0000FF` | 浅米黄 `FFFFC8` | 正常 | 四边极细虚线 | 金额格式 | 2027E CapEx 指引 `10,000`，备注写来源 |
| 同表公式（预测金额、合计、勾稽） | 黑 `000000` | 无 | 正常 | 无 | 金额格式 | `=BA20*BA21` |
| 跨表引用公式 | 绿 `008000` | 无 | 正常（百分比斜体） | 无 | 同类型 | `='Key Metrics - PDD'!BA12` |
| 衍生比率（增速、利润率、占比、反算 take rate） | 黑 | 无 | 斜体 | 无 | `0.0%` | 收入增速 `=R10/Q10-1` |
| 小计、合计行（收入合计、毛利、营业利润、净利润） | 黑 | 无 | **加粗**（标签和数字都加粗） | 无 | 金额格式 | 收入合计 |
| 来源和说明 | 红 `FF0000` | 无 | 正常 | 无 | 文本 | 备注列 `<Yipit`、`<<GS 1117`、`<<主要是腾讯` |
| 目标价结果 | 深红 `C00000` | 无 | 加粗 | 无 | 两位小数 | Valuation 页目标价 |

不用单元格批注；来源和说明写在数据区右侧的备注列。

维护原模型时要注意的旧习惯（照原样保留，不要批量改）：
- 历史年度的汇总公式（`=SUM(季度)`）在原模型里常是蓝字；新增列用黑字即可，原有的不改。
- 绿字跨表引用是电商模型的主流写法，券商模型用得少；维护时照这张表已有的颜色。
- 少数黄底假设格没有边框，维护时不要补。
- 某些页（例如 Key Metrics）有大片灰色主题底色，那是版面底色，不要当成「公式应无底色」清掉。

## 数字格式

| 类型 | 格式字符串 |
|---|---|
| 金额（整数，最常用） | `_(#,##0_);\(#,##0\);_(?\-?_);@`　负数显示为括号，0 显示为 `-` |
| 一位小数 | `_(#,##0.0_);\(#,##0.0\);_(?\-?_);@` |
| 两位小数（EPS、EPADS、股价） | `_(#,##0.00_);\(#,##0.00\);_(?\-?_);@` |
| 百分比 | `0.0%`（精细的 take rate 用 `0.00%`） |
| 百分点变化 | `#,##0.0" pp"` |
| 倍数 | `#,##0.0" x"`（样本里也有 `#,##0.0\x`） |

样本里还出现过另一套金额格式 `_(* #,##0_);_(* \(#,##0\);_(* "-"??_);_(@_)`，以及 `0%`。新建模型用上表；维护时复制同一行或相邻同类单元格的格式字符串，不要统一替换。

**正负号**：沿用公司报表和原模型的习惯——有的模型把费用记为正数、在利润行相减，有的直接记为负数。一张表内保持一致；新建模型时选一种，在 `README & Changelog` 写明。

## 表头与分节

- **第 1 行期间表头**：底色亮蓝 `3366FF`，白字加粗，右对齐。A1 写单位，例如 `(RMB MM)`、`(US$'000)`、`(HK$'000)`。
- **期间标签**：新建模型用历史年度 `2025`、预测年度 `2026E`，历史季度 `2Q26`、预测季度 `3Q26E`。维护时按这一列左右已有的表头写（券商模型是 `2026Q3E`，同一本里不同工作表写法可能不同，各自沿用）。
- A1 单位格与表头同为蓝底白字，水平对齐保持常规。
- **分节标题**：新建时只涂 A 列那一个单元格；原表把同一颜色横涂一段的，照相邻分节涂。颜色与分节的对应以这张表已有的分节为准（券商模型里桃色是大节、浅蓝是子块，和下面电商模型的分工不同）。电商模型的分工：
  - 报表级（Income statement、Cash flow statement、Balance sheet、Other disclosure）：浅蓝 `99CCFF`，黑字加粗；
  - Non-GAAP、分部报告、子公司块（例如 JD Health）：棕色 `993300`，白字加粗；
  - 业务子模型块（例如 Temu、3P、1P）：桃色 `FFCC99`，黑字加粗。

## 版面

- 列顺序：标签列 → 年度列（早年在左）→ 窄空列 → CAGR 列 → 窄空列 → 季度列 → 最右备注列。CAGR 列不是每张表都有（例如 `Model - PDD` 没有），没有就不要为了对齐而插入。
- 标签分层：A 列分节、B 列合计和一级行、C 列明细、D 列细项。A/B/C 列很窄（约 2），D 列较宽（约 22–37），期间列约 7–9，空隔列约 1。
- 冻结标签列和表头所在的行（冻几行看这张表的表头在哪）；打开时让最近几个季度在视野内（冻结点或滚动位置放在最新季度附近）。
- 较早年份的年度列和季度列做列分组并折叠；增速、比率小节做行分组。
- 段落之间空一行；增速小节紧跟在金额块下面，行标签斜体。
- 主模型页关闭网格线。
- 多公司模型：同一家公司的工作表用同一种标签颜色，颜色沿用这本已有的分组；每家公司前放一个空白分隔页（例如 `PDD>>`）。各公司有哪些工作表以原模型为准（电商模型有 Valuation、Key Metrics、Model、Subs 等，券商模型只有 Model），不要为了凑齐而新建。
