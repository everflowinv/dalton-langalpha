# 建模指引：版面、公式与各部分怎么预测

以下示例以电商公司说明；其他行业按公司自身的 KPI（关键经营指标）和报表口径替换。

## 1. 预测期

- **季度预测：本财年和下一财年逐季。** 例如当前在 2026 财年（FY26），季度预测做到 `4Q27E`（后缀 `E` 表示预测期 Estimate）。
- **年度预测：至少到下下个财年。** 同一例子里年度做到 `2028E`；无季度拆分的远期年份直接在年度列放驱动假设。市场按更远期利润定价的公司（高增长、利润尚未释放）可以继续往后延伸。
- **季度路径要有季节性**：看这家公司历史各季度占全年的比例和披露习惯，按同比增速或历史季度结构预测；业务本身没有季节性时才平均分配。
- **财年与自然年不同**（例如 3 月底结账）：按公司财年组织季度和年度，在 `A2` 单元格注明财年截止月（例如写 `FY ends Mar`〔财年截至 3 月底〕）。对比按自然年统计的数据时另做换算，模型本身保持公司口径。
- 历史期覆盖跨度参考 `.agents/skills/dalton-conventions/references/model-standards.md`；原模型已有的历史列全部保留。

## 2. 版面样板（一张公司主模型页，例如 `Model - PDD`）

列（从左到右）：

| 列 | 内容 |
|---|---|
| A–D | 标签。A 列：分节标题；B 列：合计行、一级行；C 列：明细；D 列：细项（D 列较宽） |
| 年度列 | `2018`…`2025`（历史）、`2026E`、`2027E`、`2028E` |
| 窄空列 | |
| CAGR（复合年增长率）列（可选） | 例如 `CAGR 25-28E`；维护原模型时仅在原模型已有该列时保留 |
| 窄空列 | |
| 季度列 | `1Q24`…`2Q26`（历史）、`3Q26E`…`4Q27E` |
| 备注列 | 最右，红字写来源和说明 |

行（从上到下，按公司调整）：

1. 第 1 行：期间表头；A1 写单位，例如 `(RMB MM)`（人民币百万元）。
2. **Income statement（利润表）**（A 列浅蓝分节条）
   - 收入分项 → 收入合计（加粗）→ 收入增速（斜体）
   - 营业成本 → 毛利（加粗）→ 毛利率（斜体）
   - 销售、管理、研发费用（必要时 SBC〔股权激励费用〕单列）→ 营业利润（加粗）→ 营业利润率（斜体）
   - 利息收入、利息支出、投资收益、其他 → 税前利润 → 所得税（有效税率）→ 少数股东损益 → 归母净利润（加粗）
   - 加权平均股数（基本、稀释）→ EPS（每股收益）/ EPADS（每份美国存托股收益）
3. **Non-GAAP measures（非公认会计准则指标）**（A 列棕色分节条）：SBC 等调整项 → Non-GAAP 营业利润、净利润、EPS。
4. **Segment Reporting（分部报告）**（棕色分节条）：各分部收入、营业利润、利润率。
5. **业务拆解区**（每个子业务一个桃色分节条，例如 `Temu`、`3P`〔第三方平台业务〕、`1P`〔自营业务〕）：KPI（GMV〔商品交易总额〕、订单量、用户数、ARPU〔单用户平均收入〕）→ take rate（货币化率）→ 收入；这里的收入被上面的收入分项引用。
6. **Cash flow statement（现金流量表）**（浅蓝分节条）：净利润、折旧摊销、SBC、营运资本变动 → 经营现金流；CapEx（资本开支）→ 自由现金流；分红、回购、借还款 → 现金净变动。
7. **Balance sheet（资产负债表）**（浅蓝分节条）：至少现金和有息债务；资产负债表驱动的公司做完整资产负债表。
8. 增速、利润率、占比小节紧跟在对应金额块下面，行标签斜体，做行分组。

多公司行业模型：前面放行业页（可比公司、行业数据），每家公司前放一个空白分隔页（例如 `PDD>>`），后面跟这家公司的 `Valuation - PDD`、`Key Metrics - PDD`、`Model - PDD` 等。

## 3. 常用公式写法

下面用列字母举例（`P = 2025`、`Q = 2026E`、`R = 2027E`、`S = 2028E` 年度列；`AW–AZ = 1Q26–4Q26` 季度列；`BA–BD = 1Q27E–4Q27E` 季度列）。

| 用途 | 写法 | 说明 |
|---|---|---|
| 收入 = 量 × 价 | `=BA20*BA21` | GMV × take rate；用户数 × ARPU |
| 同比增长 | `=AW15*(1+BA16)` | 去年同季 × (1 + 增速假设)，季节性强的业务首选 |
| 环比增长 | `=AZ15*(1+BA16)` | 上季 × (1 + 环比假设)，季节性弱时用 |
| 占收入比例 | `=BA10*BA31` | 费用 = 收入 × 费用率假设 |
| 分部加总 | `=SUM(BA40:BA44)` | 合计行引用明细 |
| 年度流量 | `=SUM(BA15:BD15)` | 2027E 年度收入 |
| 年度时点余额 | `=BD80` | 年末现金 = 第四季度期末现金 |
| 年度比率 | `=R15/Q15-1`、`=R25/R10` | 用本年度列的分子和分母重算 |
| 假设沿用 | `=AW21`、`=AZ21+0.3%` | 去年同季的 take rate、上季 + 0.3 个百分点（属于驱动假设，套驱动假设格式） |
| 跨表引用 | `='Key Metrics - PDD'!BA12` | 用绿字 |
| CAGR | `=(S10/P10)^(1/3)-1` | 2025→2028E 三年复合年增长率 |

### 季度路径怎么定

- **季节性参照年**：选最近一个完整、没有明显异常的年份作参照。季节性写在各季的同比或环比假设上，年度由季度加总；历史各季占全年的比例只用来检查这些增速像不像过去，不要把季度写成「占全年比例 × 本年度合计」（本年度合计本身是四季之和，会形成循环引用）。业务结构变化大的公司（新业务占比快速上升）按子业务各自的季节性预测再加总。有新业务爬坡、一次性事件、口径变化的年份会扭曲季节性，换用更正常的年份或几年平均，并在最右备注列写明用了哪一年、为什么。
- **同一行不同列用不同方法**（例如有的季度按同比、有的按环比）：沿用原模型每一列的写法；新增列参照同一季度位置的既有写法，拿不准时选同比（季节性业务）并在最右备注列说明。

## 4. 收入（重点）

1. **找到这家公司的关键驱动。** 读卖方报告和电话会，看市场在争论什么（例如 Temu 的 GMV 增速、主站 take rate、广告变现率）。影响大的驱动单独拆出来、单独给驱动假设；披露过少、缺乏拆分依据的，按卖方估算方式做简化拆分或保持合并预测，在最右备注列说明。
2. **KPI 与收入建立公式关系。** 公司披露的 KPI（GMV、订单量、用户数、ARPU、take rate、单车收入、在管资产等）尽量与收入用公式连起来。披露不全时，参照卖方的估算方式建一个合理的拆分，在最右备注列写来源（例如 `<GS 1117`，表示高盛 11 月 17 日报告），并套历史估算格式。
3. **检查历史关系是否还适用。** 会计处理（总额法 / 净额法）、业务组合或口径变化后，历史 take rate、ARPU 不一定可比；必要时分段处理并在最右备注列说明。
4. **有分部披露时按分部预测。** 集团营业利润 = 各分部营业利润之和 + 总部费用及分部间抵销（单列一行）。分部利润口径与集团不同、对不上时，把调整项单列，写明对不上的部分。
5. **分部口径变更**：默认新旧口径的数据都保留，排法沿用原模型的结构（例如在同一分部区上下各放一块，旧口径填到最后披露期，新口径从最早重述期起填并向后预测）。公司提供了重述数据就用它形成可比序列；在新旧口径（或分部合计与集团合计）都有数据的重叠期间加对账行（reconcile）检验差额，缺数据的不可比期间一般留空，对不上的在最右备注列写明差额和原因。

### 汇率与固定汇率口径

- **固定汇率增长**（constant currency，剔除汇率变动后的增长）用来区分业务增长和汇率影响：优先用公司披露的固定汇率增速或汇率影响；没有时按公司的算法，或用上年同期汇率重算本期收入后与报表增速比较（套历史估算格式，在最右备注列写明算法）。按业务实际计价结算币种判断是否需要汇率换算（例如美元报表公司的美元海外收入已是报表币种，直接使用原金额）。
- **预测怎么算**：外币业务的收入、成本先按当地货币预测，再乘汇率换算为报表币种；已按报表币种计价的部分直接计入。默认用取值日的即期汇率并在预测期保持不变；改用远期汇率时，按期限逐期写出。利润表用期间平均汇率，现金、债务等余额用期末汇率，估值换算在估值区另写明所用汇率。同一用途的汇率集中在一行（或原模型的汇率命名区域）维护供各处引用，并在该行标签或最右备注列写明报表币种、报价方向（如 USD/CNY，即 1 美元兑人民币数）和取值日期。

### 日历与节假日效应

- 春节、复活节的日期在不同年份移动；618、双十一、黑五等大促更常见的是活动窗口、发货节奏或收入确认时点变化；闰年、工作日和周末天数、财季边界也会影响单季增长。
- 预测季度时，比较本期与上年同期（或季节性参照年）的财季边界、有效营业天数和活动窗口，存在明显日历差异时再做调整：通常可单设一行「日历调整」驱动假设并由预测公式引用（历史实际值保持披露数不变），优先参考公司或卖方披露的量化影响，在最右备注列写明原因、来源和日期。
- 春节、大促跨季通常是把收入在相邻两个季度之间挪动，对全年影响小：调整了这一季，就在相邻季度做等额反向调整：两季在同一财年内时全年合计不变；跨财年（例如从上一财年末季挪到下一财年首季）时分别反映两年的影响。远期趋势不因此改变。公司某年为 53 周（某季多出一周）时，通常只在该季计入多一周的影响，后续年份回归正常周数。

### 管理层指引

**指引历史记录**：在模型里（单独一张「指引」工作表，或原模型已有的指引区）按发布时间逐条记录公司历次给出的指引，用来判断这家公司给指引的习惯。每条一行（同一次发布给了几个指标或几个期间，就记几行），列：发布日期、适用期间（某季度或全年）、指标、指引形式与数值、该期实际值、兑现情况、备注（来源，例如哪次业绩会）。
- 指标因公司而异，数量也不同：收入、某业务收入、利润率、经营利润、资本开支、订单量、用户数、店铺数等都可能出现；公司给什么就记什么，列名照公司的说法写。
- 指引的形式也不同：具体数字、区间、同比增速区间、「不低于 / 约」、只给方向（例如「利润率同比改善」）。原样记录形式，再写出用于比较的数值：区间记下沿和上沿，单个数字记该数，只给方向的只记文字描述，数值列留空。
- 实际值公布后补上实际值和兑现情况，写法跟着指引的形式走：区间写实际落在哪个位置（低于下沿、下沿到中值、中值到上沿、高于上沿）；单个金额或数量（订单量、用户数、门店数等）写百分比差异，数值小时也可以写绝对差额；利润率等比率写相差多少个百分点；指引为零或接近零时写绝对差额；「不低于」和只给方向的写是否达到。年度指引在年内修改过的，每一次修改都单列一行，能看出公司是逐步上调还是下调。
- 用法：看同一指标、同一类期间（季度对季度、全年对全年）的历史规律。全年指引要区分年初首次给出的和年内修订后的：判断公司给指引的习惯时，用该期间第一次给出的指引（例如年初首次给出的全年指引）与实际比较，并且只拿发布时点相近的记录互相比较（年初给的全年指引和第三季度才首次给的全年指引，管理层掌握的实际数据不同）；后来的修订行主要看是上调还是下调，临近年末的修订已经包含大部分实际结果。例如公司的季度收入一贯落在区间上沿附近或超出上沿，说明指引偏保守，预测高于指引中值是合理的；一贯落在下沿附近或低于下沿，预测就应更谨慎。管理层更换、业务结构变化后，较早的记录参考价值下降，在备注列说明。
- 原模型没有指引记录时，在第一次更新时补上能查到的近几期（公司业绩新闻稿、业绩会纪要里都有），查不到的期间留空。

**本期指引怎么用**：
- 本期指引：按指标和适用期间找到最新有效的那一条。模型采用的取值（中值、下沿、上沿或高于上沿）放在驱动假设输入格里，历史习惯是重要参考，再结合本期的新信息（行业数据、渠道调研、管理层表态）判断，在最右备注列写理由（例如「过去 8 个季度有 7 个季度收入高于指引上沿」）。
- 全年指引与季度预测的关系（以下算法适用于收入、利润、订单量等可加总的流量；期末门店数、年度去重用户数、利润率等按指标自己的定义和公司的披露方式处理）：已有部分季度实际值时，用全年指引减去已披露的累计数，得到剩余季度隐含的金额，再对照剩余季度的预测。季度预测直接采用全年指引时，把全年金额放进驱动假设输入格，已披露季度用实际数，其余季度引用「全年指引 − 已披露累计」这笔剩余金额，再按季节性拆到各季。由季度汇总的年度列始终是四个季度的公式之和。
- 指引是增速、利润率或固定汇率口径时，先换算成模型里对应的那一行（金额或比率）再比较或引用；利润率指引换算成利润金额后再与预测核对。
- 模型预测与采用的指引取值不同时，在最右备注列和变更记录写明差异和理由。

### 收购与出售（M&A）

**已完成的收购：把内生增长和收购贡献分开**
- 收入增速拆成内生增长（organic growth，不含收购的同口径增长）和收购贡献。优先采用公司自己对可比范围的定义；没有时，常见做法是被收购业务并表后的头 12 个月计入收购贡献，满 12 个月后并入内生基数。公司披露了内生增速或被收购业务的收入时直接用；没披露时参考卖方估算填入（套历史估算格式，在最右备注列写来源）。
- 预测时分别给假设：原有业务按内生增速，被收购业务按它自己的增速。满 12 个月只改变增速的归类（收购贡献并入内生），报表上是否继续单列，看它是不是独立的驱动。周年落在季度中间时，那一季按天数拆分收购贡献和内生部分。
- **协同效应**：公司在财报、电话会或交易公告中给出了收入协同、成本协同时，单独一行建模，按公司给的实现节奏逐期计入。注意区分当期实现的金额和「年化目标」（年化目标通常要一两年才达到），并确认协同是否已经包含在被收购业务自身的预测里，避免重复。通常在有披露依据时计入，在最右备注列写来源和日期；成本协同的正负号与费用行保持一致。整合费用，以及有披露的存货评估增值、递延收入折价等交割初期购买会计影响，均按第 6 节「一次性项目」单列。
- 收购带来的无形资产摊销单独一行（会影响 GAAP〔公认会计准则〕利润和 Non-GAAP 调整），按公司披露的摊销额或年限预测。
- 出售业务（剥离）同理：从出表日起移出收入和利润，处置损益作为一次性项目，剥离的投资现金流按净额（实收现金 − 随业务出表的现金及现金等价物）单独一行计入，期末现金由现金流公式滚存；历史期采用公司重述的持续经营数据，或保留原披露数并单列「已出售业务」，剥离后 12 个月内的可比同比增速按扣除已出售业务后的基数计算。

**尚未完成的收购（已宣布或很可能发生的交易）**
- **交割时间**：按最可能取得控制权的时间建模（参考公司指引、监管审批进度、股东投票时间），在最右备注列写依据。不确定性大时，主模型只采用一种处理（计入或不计入），另一种处理的假设和影响写在变更记录里。
- **并表**：从预计交割日起把被收购业务的收入、成本、利润并入；交割在季度中间时按天数折算是近似做法，业务季节性明显时参考它在季度内的分布。
- **支付方式决定对三张表和股数的影响**：
  - 现金与投资现金流净额：收购的投资现金流按净额单独一行计入（收购净支出 = 实付现金 − 被收购方账上的现金及现金等价物；股票支付的收购也可能取得被收购方账上的现金），期末现金由现金流公式滚存得出，利息收入随之变化；
  - 借款支付：新增借款计入融资现金流，有息债务增加，按融资利率计利息支出，偿还计划按公司说明；
  - 发股支付：按换股比例或发行股数增加股本，从收购日（取得控制权之日）起计入加权平均稀释股数；
  - EPS 按下文「稀释」的算法计算（分母计入可转债转股等稀释股份时，分子同时做对应调整），由新增利润、新增利息、无形资产摊销和新增股数共同决定是增厚还是摊薄。
  - 混合支付按各自比例处理。交易费用作为一次性项目。交易重大时，按公司披露的购买价分摊列出取得的主要资产负债（含无形资产与商誉）。
- 被收购业务的预测：用公司或交易公告给出的收入、利润、增速，或卖方的估算；协同效应按上面的方法。
- 在汇总表或变更记录里写清：交易是否已计入、按什么时间和支付方式计入，方便与只看现有业务的一致预期对比。

## 5. 成本和费用

- 能拆则拆：营业成本可拆成履约 / 支付处理 / 带宽与服务器；费用拆成销售、管理、研发，SBC 单列；折旧与人工及其他分开。有原模型就沿用原模型的拆法。
- 缺乏持续披露依据的科目合并为一行，按占收入比例预测。
- 集团营业利润由分部加总得出时，集团层面的细分费用行只回填历史实际值，预测期留空（或由分部费用汇总）。

## 6. 营业利润到 EPS

- 依次：营业利润 → 利息收入 / 支出 → 投资收益和其他 → 税前利润 → 所得税 → 少数股东损益 → 归母净利润 → ÷ 加权平均稀释股数 → EPS。
- **所得税**：有效税率是驱动假设，参考历史和公司指引；现金税和会计税差别大时再拆。
- **投资收益、联营收益、少数股东**：有披露就单独一行并参考历史预测；未披露时沿用原模型，或留空并在最右备注列注明。
- **SBC**：利润表 SBC 费用与现金流量表 SBC 加回直接引用同一金额；股本滚存中的股权激励新增股数按同一套授予假设或历史稀释率配套测算。
- 营业利润趋势和 EPS 趋势不一致时（税率变化、大额投资收益、少数股东、一次性项目），把起主要作用的项目拆出来，区分经常性和一次性。
- 发行 ADS（美国存托股）的公司同时算 EPADS（`= EPS × 每份 ADS 对应普通股数`），与公司披露口径一致。

### 一次性项目（one-off）

历史数据里的一次性项目会扭曲利润率、费用率和税率的基数；直接拿含一次性项目的历史去外推，预测会偏。

- **常见的一次性项目**：裁员和重组费用（例如亚马逊〔AMZN〕营业利润里的裁员相关费用）、资产减值、诉讼和解、出售业务或资产的损益、投资公允价值变动、一次性的税务调整（例如唯品会〔VIPS〕的往期税率补提〔catch-up〕、递延税资产重估）、并购相关费用。
- **历史期单独列出**（作为备忘行，不参与上面合计的加总）：在相关行下方加一行（例如「其中：重组费用」「一次性税务调整」），数字来自公司披露（财报附注、业绩公告、调节表、电话会），在最右备注列写来源。披露不清时参考卖方处理填入估算值（套历史估算格式，在最右备注列写明来源与口径）。
- **计算正常化的基数**：把一次性项目按它对报表利润的实际方向冲回（费用加回、收益扣除，注意原模型的正负号习惯），得到正常化的利润率、费用率、有效税率，作为预测驱动的参照。调整税前项目时同时考虑它的税务影响；一次性税务调整则直接从所得税里冲回。区分公司披露的调整后指标和我们自己的正常化估计，同类的收益和费用一致处理。
- **预测期**：驱动假设基于正常化的水平；已公告或已确定的未来一次性项目（如已公布的重组计划、已确定的税务事项）在预测期单独列行，并在最右备注列写依据；没有明确依据的预测期通常留空。
- **两套口径都要能看到**：报表口径（含一次性项目）和正常化口径的利润、EPS 都能在模型里找到；与一致预期对比时先确认对方是哪个口径（见 `sanity-check.md`）。
- **判断标准**：按是否偶发判断并在最右备注列写明理由——每年反复发生的经营性支出（即使公司称为「重组费用」）保留在正常化基数里；投资公允价值变动等非经营损益从正常化经营利润中剔除，报表口径照常保留。

### 子公司、联营和少数股东

- **受控子公司**（含上市子公司，例如京东健康、京东物流）：收入、成本、利润按 100% 全额并入并抵销内部交易；在税后利润与归母净利润之间单列少数股东损益，按「= 子公司税后利润 × 非控股股东经济权益比例」扣除（子公司亏损时反向加回）。持股比例变化（增持、回购、配售）按当期加权计算。
- **联营和合营企业**（权益法）：只计入利润表的应占联营/合营损益（单独一行）和资产负债表的长期股权投资；间接法经营现金流从净利润出发时冲回权益法损益，实际收到的分配按公司自身的会计政策列在经营或投资现金流（参照历史现金流量表的列法）。金额大的在行标签或最右备注列写明被投公司和持股比例。
- **分部加总估值（SOTP）**：对上市子公司按持股市值计入估值时，其余业务的企业价值和净现金按同一业务范围计算（均剔除该上市子公司的利润、现金和债务），再加上该持股市值，避免重复计算或漏算。原模型有 SOTP 页时沿用它的拆法，在变更记录写明利润、净现金和股权价值各算在哪。

### 稀释

- 期权和限制性股票（RSU）按库存股法计算净增稀释股数（假定所得按当期股价回购股票，仅计入行权价低于股价的期权；假定所得按授予条款和公司适用的会计处理确定，包括行权款，以及尚未确认的股权激励费用等；股价假设可与回购均价共用）；可转债仅在假设转换会拉低 EPS 时计入稀释——分母加上转股新增股数，分子加回可转债税后利息（反之分子分母均保持转换前原值）。
- 年度 EPS = 归属于普通股股东的年度利润（含上述可转债利息加回等调整）÷ 年度加权平均稀释股数。期末股数和加权平均稀释股数分两行列出，历史期与公司披露的稀释股数核对一致。
- ADS 公司核对每份 ADS 对应的普通股数；换算比例调整时优先采用公司重述数据，在最右备注列或变更记录保留原比例备查。

### 税务细节

- 税收优惠到期（例如高新技术企业优惠税率、免税期）、可抵扣亏损用完、跨境利润汇回的预提所得税、全球最低税等会改变有效税率。已知的变化从生效期起反映在税率假设里，最右备注列写依据。
- 影响大的事项区分会计确认和现金纳税的时点（例如递延税资产重估一次性确认，而现金税逐年支付）；影响集中在个别地区或主体时，可以按主要地区或主体估算后汇总到集团。
- 即使税法不变，利润在不同税率主体之间的结构变化（例如低税率的海外业务占比上升）也会改变有效税率；结构变化明显时按主要主体估算。

## 7. 净现金公司示例：现金、利息、回购、股本怎么联动

以一家有大量净现金、持续回购的公司为例（每个季度一列）：

1. **现金滚存**：`期末现金 = 期初现金 + 经营现金流 − CapEx − 分红 − 回购 + 借款净额 + 其他`。期初现金 = 上季期末现金。
2. **利息收入**：`= 期初生息资产 × 年化收益率 / 4`（用期初余额避免循环引用）。生息资产沿用原模型和公司披露：通常是现金及现金等价物加短期投资（定期存款、理财），受限资金一般不计息。收益率：用历史「利息收入 ÷ 平均生息资产」反算作参考，结合利率环境和资产配置变化设定驱动假设；预测期的收益率假设明显偏离历史隐含水平时，在最右备注列说明。
3. **回购**：金额按公司股东回报计划和历史节奏假设（例如每季 X 亿美元）；从现金流量表里扣除。
4. **股本**：`期末股数 = 期初股数 − 回购金额 ÷ 回购均价 + 股权激励新增股数`。回购均价可用当前股价或假设价格；股权激励新增按这家公司自己的历史稀释速度。
5. **EPS 用加权平均稀释股数**：季度可近似为（期初 + 期末）÷ 2 加上期权等稀释效应；与公司披露的稀释股数核对一次。
6. 金额不大的公司（现金少、无回购）可以简化：利息按固定金额或简单比例，股数按年化增长。

## 8. 资产负债表

- 至少：期末现金（来自现金流量表滚存）；债务影响大的同时预测有息债务（到期、利率、再融资假设，复杂的可以逐笔列）。
- 资产负债表驱动的业务（银行、券商、保险、融资租赁、金融科技）：预测完整资产负债表，并按季报、年报（如美股季报 10-Q、年报 10-K）附注披露理清资产负债科目与收入成本的关系，例如 `利息收入 = 平均生息资产 × 收益率`、`佣金收入 = 客户资产 × 换手率 × 费率`。
- 做了完整资产负债表时核对：资产 = 负债 + 权益；现金流量表期末现金 = 资产负债表上同一范围的现金合计（现金流量表期末数包含受限现金的，与资产负债表的现金、现金等价物和受限现金之和核对）；下一期期初 = 上一期期末。

## 9. 现金流量表

- **至少预测到自由现金流**。各家算法不同（经营现金流 − CapEx，是否再扣 SBC、租赁），在表上写明本模型的口径，便于和卖方对照。
- **平台型公司的资金沉淀**：商家应付款、用户预付款、保证金等会形成大量资金沉淀（例如拼多多 PDD），营运资本变动是经营现金流的重要来源。按交易额和结算周期估算商家应付款、支付机构结算应收款及对应受限现金的各期期末余额；对于现金流量表期末数包含受限现金的公司（例如 PDD），受限现金在该总额里一起滚存，营运资本变动只放结算应收款、商家应付款等的变动额（应收增加减少经营现金流，应付增加增加经营现金流；沿用模型已有的正负号表示方式）（自由现金流仍由经营现金流减 CapEx 算出），受限现金作为待结算给商家的资金，在计算可支配现金时另行扣除；按公司披露的生息范围和利息归属确定生息资产基数（参照第 7 节），对滚存现金余额只计息一次。可分配净现金沿用 `.agents/skills/dalton-financial-lenses/SKILL.md` 的口径。
- **营运资本**：有规律时按周转天数或占收入比例预测（季节性强的业务参考同季历史）；波动大、找不到规律时，可以用合理区间的中值，或者只预测营运资本变动前的经营现金流（营运资本变动行预测期留空，并在经营现金流行标签或最右备注列写明「未含营运资本变动」）。
- **折旧**：CapEx 重要时，折旧 = 资产基数 × 折旧率或按 CapEx 滞后；不重要时按占收入比例。**摊销**：有重大并购时单独预测。
- **CapEx**：重资产业务按产能、门店、数据中心等拆；轻资产按占收入比例；有管理层指引时用指引金额作为输入。
- **分红和回购**：结合历史和最新股东回报计划；回购重大时勾稽到股本（见第 7 节）。
- 银行、券商等：现金流量表意义有限，重点看资本充足、流动性和可分配利润。

## 12. 政策与监管

- 对业绩影响大的政策变化（例如关税、跨境小额包裹免税规则调整、平台监管、反垄断措施）：将政策影响单列一行驱动假设（或在受影响的驱动假设行体现），在最右备注列写明政策状态（已公布 / 已生效 / 仍在讨论）、生效时间、经营影响显现时间、作用范围（地区、业务量、成本及转嫁方式）以及依据和日期。
- 政策状态会变化，建表或更新时先核实最新进展，按最新状态设定假设。

## 13. 业绩更新时的偏差分解

- 保留财报公布前交付的那一版模型。新季度实际值披露后，在脚本或辅助计算中按可比口径逐项把主要驱动（量、价、take rate、费用率、税率、一次性项目、汇率）从上一版预测值替换成实际值，算出每一步解释的差额；各项解释金额与「剩余未解释差额」之和应等于「实际 − 上一版预测」（多驱动同时变化时结果受顺序影响，一并记录替换顺序）。
- 在变更记录里分开写清两件事：① 当季预测偏差的逐项来源（含替换顺序和剩余未解释差额）；② 排除一次性项目（第 6 节）和日历挪动（第 4 节）后，对后续预测修改了哪些驱动假设、保留了哪些假设及各自理由。

## 14. 判断依据（遇到这些问题时怎么想）

- **什么是关键驱动？** 对估值和股价影响最大、市场分歧最大的那几个变量。读最近两三篇卖方报告的核心论点和电话会问答，被反复讨论的就是。
- **拆多细？** 拆到能解释主要的增长和利润变化、能回答市场在争论的问题为止；缺少披露支撑且影响微小的细项保持合并。
- **利息、债务是否值得建勾稽？** 利息或债务对净利润的影响达到能改变 EPS 判断的程度（例如净现金利息贡献利润的可观比例、或有大额到期债务）就建；其余情况用简单假设。
- **营运资本有没有规律？** 看过去 8–12 个季度的周转天数或占收入比例是否稳定或有清晰趋势；季节性看同季。
- **原模型的做法和这份指南不同？** 沿用原模型；若与四条核心要求冲突则按四条要求修正，并在变更记录说明。
- **数据缺失与零值**：能合理估算的填入估算值（套历史估算格式，最右备注列写依据）；无法估算的留空并在最右备注列写原因；仅在确认实际发生或预测为零时填 `0`。
- **原模型的公式明显算错？**（例如合计多加了一行）不属于「沿用原模型」的范围，按 `rollforward.md` 的「发现原模型的计算错误」处理。
