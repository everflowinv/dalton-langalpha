# 公司财务建模（`dalton-model`）

Fund methodology: .agents/skills/dalton-conventions/SKILL.md — read before the first deliverable.

这份指南告诉你一本基金模型应该长什么样、每一步怎么做、格式怎么写。每家公司的指标、正负号习惯、财年和业务结构都不同：下面的做法是默认做法和例子，遇到不适用的情况，按公司实际调整，并在变更记录里写一句为什么。与基金通用标准 `dalton-conventions/references/model-standards.md` 的关系：维护用户模型时，期间跨度、表头写法、来源写法都沿用用户模型；新建模型时，表头和来源列按本指南的 `format-spec.md`，`model-standards.md` 用来确定历史尽量覆盖多长、空值留空、历史实际数取自一手披露。

## 一、四条必须做到的要求

1. **预测期的金额由公式算出。** 收入、成本、费用、利润这些金额行，在预测期写公式，例如 `=GMV×take rate`、`=去年同期×(1+增速)`、`=收入×利润率`、`=各分部之和`。
   - 调整**预测数值**：改驱动假设（增速、take rate、利润率、费用率、税率），让公式自己算出新结果。
   - 调整**建模方法**（重新分部、补一条勾稽关系、换一个驱动）：可以改公式结构，在变更记录写明。
   - 管理层直接给了金额指引（例如明年 CapEx 指引 100 亿）：把这个金额放进一个单独的输入格（假设格式，备注写来源），预测行引用这个输入格。
   - 原模型里是公式的预测行，更新后仍是公式。
2. **由季度汇总的年度列不放假设。** 年度按指标性质由季度算出：
   - 流量（收入、成本、利润、现金流）：四个季度相加；
   - 时点余额（现金、债务、期末股本）：取财年最后一个季度；
   - 比率（增速、利润率、take rate、占比）：用年度的分子和分母重新算，不把季度比率相加或平均；
   - 年度 EPS：年度利润 ÷ 年度加权平均稀释股数（与公司披露口径一致）；
   - 用户数、活跃商家等 KPI：按公司的定义（期末数、年度平均或年度去重），不要直接把四个季度相加。
   只有真正驱动计算的季度列和没有季度拆分的远期年度列放假设。
3. **与市场预期的重大差异要查明原因。** 我们的预测与一致预期（consensus）或主要卖方预测差距较大时，拆到分部、驱动、费用、利息、股本找出差距从哪来；有依据就保留我们的判断并写明理由，发现自己的假设有问题就改。是否改，看有没有可核实的新信息或具体的假设问题，而不是向一致预期靠拢。
4. **用户提供了模型，就在它的基础上维护。** 沿用它的结构、预测方法和格式；原件不动，新版本另存。

## 二、操作步骤

**第 1 步　确定底稿和任务范围**
- 看用户这次给了什么文件、要求做什么（补实际值？加预测期？改假设？从头建？）。
- 已有模型：优先用用户本次指定的文件；其次是 `data/models.json` 登记的当前版本和工作区此前交付的版本（看文件内容判断）。几份都可能是正本、而且选错会影响交付时，再问用户。然后读 `references/rollforward.md`。
- 没有模型：读 `references/forecast-rules.md` 的「版面样板」，按基金格式新建。
- 行业工作区的模型放在 `model/` 目录。单公司模型文件名 `<TICKER>-model-v<NN>.xlsx`；用户的行业整本模型（例如按日期命名的行业模型）沿用原文件名的写法，只更新版本号或日期，不拆成单公司文件。
- `model/` 和 `models/` 各有一份时：内容相同（哈希一致）就是副本；不同就比较内容和交付记录判断哪本是最新正本，仍无法判断时问用户。

**第 2 步　读材料**
- 公司最近的年报和季报（10-K、10-Q、20-F 或港股、A 股定期报告）：分部披露、KPI、管理层指引、股东回报计划。
- 主要卖方报告或模型：他们拆哪些驱动、市场在争论什么、一致预期大概在哪里。
- 维护已有模型时：读懂原模型的工作表结构、哪些行是公式、用什么驱动预测、哪些地方相互勾稽、格式习惯。

**第 3 步　搭建或更新预测**（按 `references/forecast-rules.md`）
- 顺序：收入（重点）→ 成本和费用 → 营业利润到归母净利润 → 利息、税、少数股东 → 股本与 EPS → 现金流 → 资产负债表（现金、债务）→ 汇总表。
- 每新增一行先想清楚它是哪类单元格（披露数、我们的估算、假设、公式、跨表引用、衍生比率），再按 `references/format-spec.md` 写格式。

**第 4 步　写格式**（按 `references/format-spec.md`）
- 有原模型：照原模型同一区块、同一用途的单元格写格式。
- 新建模型：用基金默认格式。`scripts/model_style.py` 提供写入默认格式和读取原模型格式的函数。

**第 5 步　重算并自查**
- 在副本上重算：上游 `xlsx` skill 的 `scripts/recalc.py`。
- 运行 `scripts/model_scan.py <模型路径>`。它列出值得看一眼的地方：预测期里的数字常数、可能引用了错误期间的公式、外部链接和插件函数、`#REF!`、循环引用、重算错误。它不判断对错，由你判断：重点看本次改动涉及的期间和重要公式；确认是问题就改；影响结论或后续维护的判断，在变更记录写一句。
- 自己再核对几件事：年度 = 季度汇总是否成立；集团利润与分部之和能否对上（对不上的差额是什么）；现金和股本的滚存是否连贯；EPS 与净利润、股数是否一致。

**第 6 步　对照市场预期**（按 `references/sanity-check.md`）

**第 7 步　交付**
- 新版本另存，例如 `model/PDD-model-v03.xlsx`（行业整本按原文件名递增版本或日期）；原件不改。
- 登记新版本：在 `data/models.json` 里新增这一版（`versions[]` 加一条，`current` 指向它），下一轮才会以它为底稿。
- 在 `README & Changelog` 工作表（没有就新建，放在最前面）写：版本号、日期、底稿是哪本、补了哪些实际值、新增了哪些期间、改了哪些关键假设和理由、新增或修改了哪些结构、与一致预期的主要差异和理由、扫描里你判断为「不是问题」的重要条目和原因。
- 回复用户时用几句话说清：关键预测（收入、利润、EPS）、和上一版相比变了什么、和一致预期差在哪里。

## 三、最常见的错误（用户纠正过的）

| 错误 | 看起来是什么样 | 正确做法 |
|---|---|---|
| 把公式改成了数字 | 原来 `=GMV×take rate` 的收入行，更新后变成一串固定数字 | 保留公式，只改 GMV 增速和 take rate 假设 |
| 汇总年里留着假设 | 2027E 年度收入是四季之和，下面的 2027E 增速却是一个手填的 15% | 年度增速写成 `=2027E收入/2026E收入-1`，用衍生比率格式 |
| 套用了别的格式 | 表头深蓝 `1F4E79`、字号 10、浅灰底，和原模型不一样 | 照原模型或基金默认格式（Arial 8、亮蓝表头 `3366FF`、假设格浅米黄 `FFFFC8`） |
| 偏离一致预期没检查 | 2028E 净利润明显高于一致预期，没有说明来源 | 拆差异来源，确认有依据再保留，并写理由 |
| 集团和分部脱节 | 集团营业利润单独预测，与分部营业利润之和对不上 | 集团营业利润 = 分部之和 + 总部及抵销（单列），或在对不上时写明差额 |
| 现金和股本不联动 | 净现金很多却没有利息收入增长；回购了但股数不变 | 利息随现金滚存；回购和股权激励改变股数（见 `forecast-rules.md` 净现金公司示例） |
| 外部插件公式留在模型里 | Capital IQ、Bloomberg 公式在 Dalton 里显示 `#NAME?` | 换成有来源和日期的数值输入，原单元格引用它 |
