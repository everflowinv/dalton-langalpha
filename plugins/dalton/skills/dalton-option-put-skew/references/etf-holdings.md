# ETF 成分股与权重快查

## 1. 固定基金与回答范围

1. 用 `web_search` 搜索 `"<TICKER> ETF official holdings"`，打开实际返回的发行人产品页，确认基金全名、交易所及是否杠杆／反向，因为相近代码可能代表不同策略。
2. 仅问成分股时直接列主要公司，不启动行情归因、公司财报、社区研究、评分或文档发布，因为这类问题只需要持仓快照及必要的策略说明。

## 2. 先读发行人的方法与持仓

1. 调用 `WebFetch(url="<已定位产品页>", prompt="提取基金 Overview、完整持仓 Holdings 表（公司名、代码、权重、持仓截止日期）及权重方法 FAQ")`，读取 Overview、Holdings 和 FAQ，因为搜索合成答案不能替代持仓表。
2. 分别记录投资范围、权重方法、再平衡频率与持仓表日期，因为策略目标和实际持仓不是同一个数据。
3. 当持仓表只有 `TBD`、空列或占位符时，沿页面提供的 Holdings CSV／PDF／Fact Sheet 链接读取带日期快照，仍未取得数值则保留权重缺口，因为页面返回成功不代表持仓已加载。
4. 只有发行人明确写明等权规则时才按 `100% / 标的数` 给出目标权重，并写“再平衡时目标约……，期间会漂移”，因为等权目标不能冒充今日实际权重。

## 3. 用第三方补齐可核验的快照

1. 官方数值未取得时，用 `web_search(query="<TICKER> ETF holdings", time_range="month")` 定位公开持仓页，再用 `WebFetch` 打开正文，因为换来源比反复引用同一空表更能补齐证据。
2. 美股可先读取 `https://stockanalysis.com/etf/<小写ticker>/holdings/`，再打开搜索返回的 MarketBeat、Morningstar 或 ETF.com 页面核对公司与权重，因为至少两个展示页能帮助发现漏行、代码变更与日期差异。
3. 同时检查底层数据商、持股数量和日期；若两个页面沿用相同数据，只标为一致性检查，不称独立验证，因为重复分发不能提高原始数据的独立性。
4. 优先采用明确标注持仓截止日的一整张表，不混合各站最新百分比或取平均，因为差异可能只是快照时间不同。
5. 将持仓的 `as of`、网页更新日期、抓取日期和旁边的实时股价分别记录，缺少持仓日期时写未知，因为行情实时刷新不代表持仓同步更新。

## 4. 核对“成分股”与“经济敞口”

1. 将股票、现金、货币基金、国债、期货和互换分开识别，不把 total holdings 数直接称为股票家数，因为持仓行可能包含现金管理和衍生工具。
2. 遇到股票加总收益互换的基金，优先采用发行人公布的合并敞口权重；仅有原始持仓时分列直接持有与衍生敞口，保留无法穿透的部分，因为衍生品市值权重不等于其标的股票敞口。
3. 只列证据实际显示的股份类别代码；若按公司合并多类股或多笔敞口，注明合并口径，因为公司名称本身不能证明基金持有哪一类股票。
4. 对同一快照按原权重降序排列，并复算所列前十大权重之和、检查重复公司和舍入差，因为网页显示的集中度也可能与列表日期或范围不一致。
5. 页面只公开前若干项时，写“主要持仓／已读取前N项”，不补写未展示的尾部或将其称为完整清单，因为访问范围决定可交付范围。

## 5. 简短交付与验收

按“基金投向一句话 → 持仓截止日 → 公司名／股票代码／权重 → 必要的加权规则 → 来源及缺口”回复，因为用户首先要知道买入后暴露于哪些公司。

固定少数标的的基金列全；其他基金默认列前十大并标集中度，余下仅按需要补充，因为主要持仓不需要展开无关费用、表现或投资建议。

用条目列示并保留同一快照的百分比精度；官方仅核到策略而持仓来自第三方时，明确写“第三方披露，截至某日”，因为不能把补源结果包装成官方实时持仓。

发送前核对每个名称、代码和数值可回指本轮已读页面，等权目标与实际权重未混用，股票家数与持仓行数未混用，因为这些是简短ETF答复最容易隐藏的口径错误。
