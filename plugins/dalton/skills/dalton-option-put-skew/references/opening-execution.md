# 开盘卖出看跌期权（put），还是稍后再卖

## 1. 先确认市场阶段和合约

1. 核对当前美东日期、时间及盘前／盘中／盘后状态（可在沙箱中用 `datetime.now(ZoneInfo("America/New_York"))` 核对当前美东时间），因为股票盘前交易不代表同名期权已经开市。
2. 核对标的、到期日和行权价；用户没提供后两项时先给出基于条件的执行原则，再一次追问缺失的到期日和行权价，因为本周到期与跨财报的远月 put 对开盘等待的敏感度不同。
3. 将用户说的“vol”明确区分为隐含波动率（IV）、成交量或实际波动率（RV）；语境指期权贵不贵时说明按隐含波动率（IV）理解，因为成交量增加不意味着 IV 必然上涨。
4. 只在用户要求评估金额或张数时补充说明现金担保／保证金模式与被行权后需接手的股票规模，因为时点问题不需要默认生成一笔百万美元交易。

## 2. 先核消息，再解释开盘定价

1. 用 `WebSearch` 的明确日期窗口（`start_date` / `end_date`）定位当天事件，并用 `WebFetch` 读公司公告、投资者关系页面（IR）或可靠通讯社原文，因为搜索摘要不足以确认风险是否仍在发展。
2. 需要内部交易台观点时，在沙箱中调用 `researchdata.research(route="all", operation="search", query="<ticker> <event>", start="<date>", params={"media": "text"})` 搜索，再按返回的 `document_id` 读取相关正文，因为交易台／销售团队判断与公司官方确认必须分开。
3. 核对到期前的财报和其他已公布事件；先用 `yf.Ticker(ticker).calendar` 定位，再以公司投资者关系页面（IR）公布的日期为准，因为跨事件期权的较高 IV 不能只归因于当天新闻。
4. 将“隔夜消息会在期权开盘时直接重新定价”与“开盘之后风险可能继续变化”同时写清，因为 IV 不需要等成交量积累，也没有固定的日内峰值时间。

## 3. 检查实际可成交报价

1. 用 `yf.Ticker(ticker).option_chain(expiry).puts` 按准确的合约代码（`contractSymbol`）和行权价（`strike`）定位合约，记录抓取时间、报价时间、同步的标的现股价格、买一价（`bid`）、卖一价（`ask`）、成交量和未平仓合约数，因为不同合约或不同时间的数字不能拼凑成执行价。
2. 将最近成交时间（`lastTradeDate`）只用作最近一笔成交的时间，不当作 `bid` / `ask` 的报价更新时间，因为旧成交不证明当前报价仍有效。
3. 要求有效双边报价（`0 < bid <= ask`）并核对报价时效性；没有可核验时间的行情只标为延迟／参考报价，因为盘前返回的期权链可能仍是前一交易日的状态。
4. 卖出时先看 `bid`，再看可尝试的限价和价差比例 `(ask-bid)/mid`（`mid` 为买卖中间价）；将 `mid` 标为估值而非成交保证，因为高 `ask` 或高最新成交价（`last`）并不代表卖方一定能以此价格成交。
5. 在合约尚未开市或没有可靠的实时期权链数据时，明确说明“今天开盘 IV 尚未观察到”，仅给出分情景的条件方案，因为不能用股票盘前跌幅反推出可成交的期权价格。

## 4. 固定比较对象，拆开方向与波动

1. 比较开盘与稍后时点时固定同一到期日和行权价，并同步记录现股价格与 IV，因为每次重新挑选 90% 行权价或同 delta（期权价格对标的价格变动的敏感度指标）合约，会混入切换合约带来的不可比误差（换档效应）。
2. 将权利金变化拆成股价方向、IV／偏度（skew）和时间价值三项，因为等到更高权利金可能只是接股风险增大，而非获得更厚的波动率溢价。
3. 按三种走势路径给出判断：低开后反弹时，同一行权价的 put 可能受股价回升和 IV 回落双重压低价格；继续下探时，权利金可能升高但接股风险也同步增加；横盘时重点看事件溢价与买卖价差变化，因为不能预先断言早卖或晚卖必胜。
4. 没有历史日内期权报价时，不把“开盘后几分钟观察报价”写成最佳收益时点或回测结论，因为现股分钟线不能验证期权执行优势。

## 5. 给执行条件和停止条件

1. 将开始执行条件写为合约完成开盘、双边报价稳定且买卖价差可接受；可给出数分钟的观察窗口但注明仅是执行经验，因为固定等待半小时未必能改善报价。
2. 说明建议限价和分批卖出仅用于控制成交成本与择时风险，并保留不成交或不做的选择，因为分批卖出不能消除跳空与事件风险。
3. 股价持续创新低或消息升级时，先重新评估该行权价是否仍愿意接股，不因 put 更贵就自动加卖，因为卖出 put 同时承担标的下跌风险与波动率上升风险。
4. 在收尾写明目前缺失的合约参数（如到期日、行权价）及数据限制；未安排监控时不承诺开盘后自动补充报价，因为后续跟踪需要实际可用的查询或监控机制。

## 输出验收

- 用简短中文先给出倾向性判断，再列出三种走势路径和执行条件，因为用户问的是时点取舍而非完整公司研究。
- 检查每个报价是否注明交易时段和时间、每个时点比较是否为同一合约，因为过期期权链和更换行权价会造成虚假的收益优势。
- 检查是否把经验分钟数、事件新闻或 IV 方向写成确定性预测，并将尚未观察到的指标改为条件表述，因为盘前无法预知开盘后的实际路径。
