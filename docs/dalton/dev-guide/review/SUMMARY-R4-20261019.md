## 4. 本轮审查的新发现（预审之外）

1. **【高】OSS 身份模型使全部证据的"测试用户"实为 owner**：`.env` 未设 `INTERNAL_SERVICE_TOKEN`，`get_current_user_id` 在 HOST_MODE=oss 下对一切请求返回 `local-dev-user`（src/server/utils/api.py:90-91），服务令牌路径关闭。lead 实测：带任意 X-User-Id（含陌生用户）调 PM 接口全部放行，因为请求者就是 owner（PM）。后果：G1 的"测试用户预算"、G2/G3/G4 的按用户主张全部失效——按用户维度的隔离、额度、审批都没有被真正测试过。**修法：证据环境必须设 INTERNAL_SERVICE_TOKEN 并以服务令牌+X-User-Id 跑脚本，或在平台模式验证。**
2. **【中】settings 默认工厂含 `'default'`**（settings.py:59/124，自第一轮 7061b70e 起）：PM 列表默认含一个易猜的用户名。上游 OSS 兜底用户是 `local-dev-user` 而非 `default`，该条目无正当用途，建议删。
3. **【中】夹带代码里 3 处新的 `local-dev-user` 字面量分支**（board/director/assist）：dev 用户跳过所有者过滤，托管模式下属越权面。
4. **【中】complete.py 的换模重试**：核验路径上 deepseek-flash 静默换模重试（R6），花费与家族隔离有影响。
