## 1 谱系证据链（E1 ①）

**结论：❌ 坐实，thesis.json 与 raw/META.json 同源，G3 的 META 场景是自我核验。**

证据链（每一环都实测）：

1. **生成逻辑（读 `scripts/dalton/migrate_legacy_knowledge.py`）**：`run_migration_pipeline()` 对每家公司先 `extract_company_bundle()` 得到 bundle 并原样写入 `raw/<T>.json`（L1483-1486），随后 `build_knowledge_documents(bundle)` 从 bundle 里的 `parsed_thesis`/`raw_thesis_md` 生成 8 个 JSON 文档（含 `thesis.json`）并写入 `Home/dalton/companies/<T>/data/`（L1487-1488、L1405）。即 `raw/META.json` 与 `thesis.json` 是**同一次函数调用、同一秒**写出的上下游产物。
2. **字段级同源**：`build_knowledge_documents` 把底稿每个 bullet 逐字放进 `evidence[].fact`（L735-751 事实/看多/看空/专家各分支、L884-915 其余小节），`"fact": b_text` 无任何改写。实测：`thesis.json` 92 条 evidence 的 `fact` **92/92 是 `raw_thesis_md` 的逐字子串**（0 条例外）。`market_view.figures`（Consensus EPS 5.94 等 6 条）也取自 `raw/META.json` 内的 `latest_consensus`。`provenance.json` 记录 `migrated_by: scripts/dalton/migrate_legacy_knowledge.py`，其 `thesis_md_sha256=957b59a6…` 与 `raw/META.json` 中 `raw_thesis_md` 的实测 SHA-256 **完全一致**。
3. **时间戳**：`raw/META.json` mtime 17:04:33（其内 `extracted_at=2026-10-18T21:04:33.071Z`，本地 EDT+4 吻合）；`thesis.json` mtime **同一秒 17:04:33**；`migration_report.json` 17:04:37；G3 证据 `g3_real_llm_audit_20261018.json` 17:11:56——核验用的两个文件出自 7 分钟前同一次迁移。
4. **重放复核**：以 `raw_thesis_md` 为草稿、`META/data/thesis.json` 为证据，离线跑 `audit_draft`（无 LLM）：**figures=443, matched=443, contradicted=0, unverified=0, uncertain=0，全部 kind='evidence'**。逐项检查：443/443 的 matched 引用的 evidence fact 是草稿自身句子的逐字子串（循环率 100%）。开发方 445 = 443 + 2：差异只能来自 Step B 真实 LLM 标注的 `extra_figures`（❓ 无法离线复现确认具体是哪 2 条；草稿前 3000 字符内无"两成/腰斩"类口语词，445−443 的确切来源存疑但不影响结论——两条额外数字同样落在循环证据上）。
5. **机制**：`match.py` Order 4a 对无脚注数字自动遍历 `thesis.evidence`，`_inspect_text_source` 在 evidence `fact` 文本里抽数比较（`match.py:841-853`、`296-412`）。因为 `fact` 就是草稿原句，数值/单位/期间必然逐字相等 → 自动"verified"。**全程不需要 LLM**，这也解释了 E2 的 15 次调用与 7.56 秒：445 个数字几乎全在 C 环节确定性自匹配。

### 2.1 误判数（有矛盾/无来源）
contradicted=0（四口径均无）；有矛盾方向无误判。真实覆盖的约 20 个数字中，**误伤 2 个**：`2,425 亿`（6 月底现金）与 `5,140 亿`（云积压）在**正确证据 EV-SEC-008/EV-SEC-009 明明存在**的情况下判"无来源"——根因是 `retrieve_candidate_sources` 的打分与 fallback 截断（10 条证据里排不进前 5；`match.py` Order 4a/`retrieve_candidate_sources` fallback_pool[:limit]）。证据集越大问题越重。这是与 LLM 无关的管线缺陷。

### 2.2 未能判断数与占比
- 失败退路口径 A：511/514=**99.4%**（设计行为：LLM 不可用时不猜）。验收标准"≤10%"只在 LLM 在位时适用。

### 2.3 与开发方 445/445 的差异原因
开发方的 445 个"已核实"中，可复现的 443 个全部是"证据=草稿自身句子"的确定性自匹配（§1）。换成真正独立的证据后，同一套管线在同一数量级的草稿上：真实覆盖数字大多能核实（D 口径 12/约20），但有检索误伤（≥2）与巧合错放（D 口径 2 个、跨公司口径 58 个）。**差异不在管线换了，而在开发方的证据不独立。**

### 2.4 错放案例（锚定盲区，D 口径实测）
1. **F-016 `400 亿`（L12，2027 capex 预算余量）→ EV-SEC-005（"最高 400 亿美元的 ATM"）**：数值相等、引文真实 → 锚定放行 → `verified`。主题完全无关。根因：锚定（`verify_llm_judge_verdict` supported 路径）**只校验引文逐字存在+数值换算相等，不校验指标/期间/主题**；语义把关全在 LLM。
2. **F-241 `19.11`（L70，2026 一致 EPS 区间上界，美元/股）→ EV-SEC-002（"同比增长 19.1%"，百分比）**：`values_within_tolerance` 的 pct 分支把容差放宽到 0.05 绝对值，每股数与百分比量纲混同 → 相等 → 锚定放行 → `verified`。
两条都是"引文真实、数字真实、但说的不是同一件事"。真实 LLM 大概率不犯，但代码层面无法否决——错放方向最后防线仍是 LLM 本身。

开发方 `colloquial_cn_extraction.elapsed_s=0.07`。70 ms 减去 <1 ms 的代码成本，剩 ~69 ms 只够 `assist_json→dalton_complete` 的本地开销（模型解析、YAML 读取、journal 查询、schema 校验）——即**缓存重放（journal cached）或替身**的量级；任何真实模型往返（含最快 flash、含结构化输出）都要数百 ms 起步。**判定：❌ 0.07 秒不是新鲜真实 LLM 调用；❓ 是缓存重放还是替身，需 `dalton_llm_journal` 的 cached 标记（后端停运无法核）。** 若是缓存重放，则该场景展示的是早前一次运行的回放，不能作为"真实 LLM 抽出 4 条口语数字"的独立证据；顺带说明 Step B 每次只送**前 10 个**候选数字 + 草稿前 3000 字符（`numbers.py:898、901`），"每份报告必经标注"是一次调用、小覆盖，与 E2 的 15 次总量相互印证。
