对比**长期记忆（Memory）**、**个人资料（Memo）**、**团队知识库**、**团队对话归档**与上游 **草稿本（Scratchpad）** 的保存层级。

想让助手长期记住你的习惯或对某只股票的基本假设，用**长期记忆**；有一批参考文档需要个人跨对话反复查阅，传到**资料（Memo）**；要把一手纪要或卖方观点沉淀给全团队共享检索，明确要求入库到**公司 Wiki / 销售纪要**；而上游的**草稿本（Scratchpad）**在当前部署已关闭，过程稿直接保存成工作区文件即可。

## 快速决策表

| 你想存什么 | 选哪种方式 | 谁能看到 | 存储位置与关键限制 |
| :--- | :--- | :--- | :--- |
| 你的个人偏好、分析口径、某标的长期关注点 | **长期记忆（Memory）** | 你自己（按用户/工作区层级） | 随对话自动或按指示更新，注入每轮运行时基线 |
| 你搜集的方法论 PDF、个人研究模板、多对话共用的参考文件 | **个人资料（Memo）** | 你自己（助手只读，支持 `⌘K` 全文搜） | 右侧 Memo 面板上传，原始 ≤ **5 MB** 且抽取正文 ≤ **1 MiB** |
| 管理层/专家一手纪要、团队调研笔记 | **归档至公司 Wiki** | 内部成员与管理员（外部成员不可用） | 对话中明确要求归档；单文件 ≤ **20 MB**，每人每小时 ≤ **30 次** |
| 卖方研报、券商电话会、销售推票纪要 | **归档至销售纪要** | 内部成员与管理员（外部成员不可用） | 同上，通过统一入库按「谁在说」自动分流 |
| 本次研究产生的中间表格、初稿报告、代码输出 | **工作区普通文件** | 工作区所有者 + 已授权查看该工作区的同事 | 工作区目录持久化保存（右侧文件面板可见） |
| 过去团队对话里讨论过的判断、目标与待办 | **团队对话归档** | 内部成员与管理员（`conversation_search`） | 后台定时自动抽取，无需手动维护 |
| 单条对话的临时草稿本（Scratchpad） | **当前已关闭** | — | `config.dalton.yaml` 关闭了该开关，请直接用工作区 `.md` 文件替代 |

## 选型原则（三条经验法则）

1. **区分“个人参考”和“团队资产”**：
   - 只给自己看、不希望影响团队公共库或受入库去重规则限制的材料，放进**工作区文件**或 **Memo**；
   - 对全团队有复用价值的一手纪要或卖方观点，明确要求归档进 **公司 Wiki** 或 **销售纪要**（或在工作区顶部打开「自动入库」后让分析师批量分流）。
2. **卖方观点不要进公司 Wiki**：
   - 公司 Wiki 只沉淀一手访谈、管理层原话、公告与内部笔记；卖方观点与销售路演请务必走销售纪要（使用统一入库入口时，系统会自动按「谁在说」分流）。
3. **别把大文件或超长文本往 Memo 塞**：
   - Memo 面板单文件原始体积限制 **5 MB**，且抽取出的纯文本正文上限为 **1 MiB**（文本特别密集的文件即使不到 5 MB 也可能因正文超 1 MiB 被拒收）；几十兆的财报 PDF 或原始数据包请直接传进**聊天输入框（≤ 200 MiB）**或右侧**工作区文件面板**。
