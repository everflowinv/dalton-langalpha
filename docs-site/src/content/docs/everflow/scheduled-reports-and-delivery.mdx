这页教你绑定个人通讯账号、配好任务推送路线、查看团队公共任务，以及看懂投递失败告警。

Everflow 通过专用的**频道网关（Channel Gateway）**把自动化结果推到**飞书（私聊和团队群）**和 **Discord（私聊，以及带模板定时报告的 Discord 频道）**，同时支持绑定个人微信用于微信私聊提问及通用会话消息。自动化推送按**「自动推送总开关 → 个人接收账号 / 单任务路线覆盖」**两级规则走。

## 第一步：绑定个人接收账号

点左下角头像，进「设置 → 个人设置 → 消息与渠道」：

### 1. 绑定飞书或 Discord

1. 在**「飞书与 Discord 账号绑定」**卡片里，点**生成飞书绑定码**或**生成 Discord 绑定码**。
2. 复制那条一次性绑定命令（格式为 `/bind <绑定码>`）。
3. **私聊发送**这条命令给平台里的 Dalton 机器人（记住要私聊发，发在群里没用），在过期前发出去就行。
4. 回到设置页点刷新，状态变成**已绑定**后就能收个人推送了。

### 2. 绑定个人微信

1. 在**「我的微信绑定」**卡片里点**「生成个人微信绑定码」**。
2. 复制页面给的绑定指令，用自己的微信发给团队 Dalton 机器人，再回设置页确认状态变成**已绑定**。
3. 绑好后可以直接在微信里私聊问 Dalton 问题，并接收通用会话渠道消息。

:::note[团队微信机器人 vs 我的微信绑定]
普通成员只要去「个人设置 → 消息与渠道 → 我的微信绑定」生成绑定码、发指令绑自己的微信就行。**「团队管理 → 团队渠道与运维 → 团队微信机器人」**是管理员用来扫码登录、维护团队微信机器人的，普通成员不用管。
:::

## 第二步：打开自动推送总开关与默认接收账号

打开「设置 → 个人设置 → 消息与渠道 → **自动推送与接收账号**」卡片：

1. **打开「自动推送总开关」**（默认关闭）：打开后才会按勾选列表向你的个人账号发送自动化结果。
2. **勾选接收账号**：从已绑定的**飞书**或 **Discord** 账号里勾出想收推送的账号，还可以点发送测试消息确认通不通。

## 第三步：按任务配置投递路线（普通自动化 vs 定时报告）

两类任务的推送目标配置方式略有区别：

### 1. 普通自动化任务（可视化设置）

打开左侧主导航的 **自动化（`/automations`）**，按单个任务细调推送目标：

- **单任务推送开关**：每条自动化行旁边都有独立的推送开关。
- **单任务目标选择器**：点行内或详情里的目标下拉框，可以覆盖全局默认设置，例如：
  - 只推给其中某几个已绑定飞书或 Discord 个人账号；
  - 推给管理员已拉入 Dalton 机器人的**飞书团队群**（可选 1 个或多个群）；
  - 给某条测试任务设成「不推送」。

### 2. 带固定报告模板的定时报告（对话自助配置）

使用结构化报告模板的定时报告拥有独立的报告投递配置。内部成员可以在对话里直接让 Dalton 查看、配置或撤销自己定时报告的投递目标：

- 经对话添加**飞书团队群**或已登记的 **Discord 频道**时，需要你明确确认才会生效。内部成员可添加本人所在、且已获授权的飞书群（群若绑定了工作区，任务所有者需对该工作区有写权限）；Discord 频道由管理员配置。
- 这类定时报告中，富文本交互卡片目标面向飞书，Discord 频道接收纯文本版本。
- 当已提交的卡片或纯文本报告确认最终送达失败（通常是 3 次尝试后，卡片超出大小上限时会直接判定），且该报告配置了有效的告警目标时，系统会发一条**投递失败告警**提醒负责人排查；告警发出前原报告补发成功的，告警自动取消。

:::tip[查看已经接入哪些飞书团队群与 Discord 频道]
内部成员和管理员可以在「设置 → 团队管理 → 团队渠道与运维 → **飞书团队群绑定**」看到所有已拉入 Dalton 机器人的飞书群，还能发单群测试消息；管理员还可以在同一页面的「**Discord 频道**」登记可接收群报告的 Discord 文字频道，或在「**管理员手动添加推送目标**」手动添加飞书私聊或 Discord 私信目标。
:::

## 自动化投递与团队公共任务

Everflow 里的自动任务分成两类：

1. **个人 / 团队自动化任务**：由助手按计划、一次性或股价异动触发。每条任务可单独设置**模型**和**思考强度**；主订阅失效时会自动按备用模型链切换（详见 [模型与额度](/help/concepts/models-and-budgets/)）。跑完后通过频道网关发成飞书富文本卡片（超大卡片自动拆分，避免触及飞书 30 KB 卡片上限）或 Discord 消息。没有固定卡片格式的普通任务会生成标准摘要卡片，点一下直接跳回对话详情。
2. **团队公共与定时数据任务**：比如每日盘前盘后巡检、市场情绪看板重建、新闻和研报增量扫描、每周模型用量周报（Antigravity 同系列档位已合并汇总并附档位明细）。内部成员能在「设置 → 团队管理 → 团队渠道与运维 → **自动巡检与团队公共任务**」只读查看最近运行状态和日志尾部（主机与运维任务详情只有管理员能看；启停和调度要去「自动化 → **公司公共任务**」页签操作）。

## 投递可靠性：执行历史状态、自动重试与失败告警

既要防止网络抖动漏发报告，又要避免状态不明时重复刷屏：

1. **执行历史直接展示投递结果**：在「自动化」的执行历史里，**「已完成」**表示任务执行结束（未配置推送或跳过推送的运行也会显示「已完成」）；实际送达情况以展开后的各目标明细及投递标签为准——**「已完成 · 投递中」**、**「已完成 · 投递失败」**、**「已完成 · 部分投递失败」**，并列出具体原因（如卡片超限、通道失败或**「投递状态未确认」**）。按计算机筛选历史时，同时覆盖任务本身或其对话落在该计算机上的记录。
2. **确定失败才自动重试**：明确失败，或者超过 **10 分钟**仍停在待发状态的记录，后台扫描会自动重试，**总计通常最多尝试 3 次（含首次发送）**。
3. **状态不明时保持保守**：如果网关正好在发送瞬间重启，或者返回不确定状态，系统会先保住记录状态、暂停重发，免得同一份长报告连发好几遍。
4. **普通任务看执行历史、模板报告可配失败告警**：普通自动化任务的送达情况直接在「自动化」执行历史中查看目标明细；带固定模板的定时报告在配置了有效告警目标时，确定送达失败后还会按上节规则另发投递失败告警。
