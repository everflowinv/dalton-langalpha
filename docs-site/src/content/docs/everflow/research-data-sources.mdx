梳理 Everflow（Dalton）接入的研究与金融数据源路由，以及 AlphaEngine 缓存与 Guidepoint 专家库的检索规则。

在 AlphaEngine 中，**每一次调用检索（`search_library`）都会消耗额度（即使参数完全相同），而同一篇文档读过一次全文后再读不会重复扣费**；为降低团队额度浪费，Everflow 在宿主侧建设了团队级 **AlphaEngine 检索缓存**，短时间内相同检索直接返回缓存结果，只有在确实需要最新进展（如财报刚发）时才通过 `params.fresh=true` 绕过缓存。

## 研究数据源全景路由

助手在工作区沙箱内通过 `researchdata` 与 `dalton_sec` 插件以及直连行情/搜索工具访问以下数据源：

### 1. 内部研报、会议与公司库（`research` 路由）

| 路由 | 名称 | 提供什么证据与使用要点 |
| :--- | :--- | :--- |
| **`alphaengine`** | 卖方研报与机构/个人会议 | 卖方研报、机构会议、个人会议、录制状态与词典。先 `search_library` 再按文档 ID 调 `get_document` 读正文（支持按 `content_field` 与字符分段翻页） |
| **`guidepoint`** | 专家访谈 | 供应链/渠道/竞品一线专家访谈摘录。仅返回问答摘录，无全文接口 |
| **`transcript`** | 业绩会转写 | 财报电话会与管理层回访原话（含指引与 Q&A）。注意 **`all` 跨库初筛不包含 `transcript`**，需单独检索 |
| **`company-wiki`** | 公司资料库 | 团队已沉淀的公司笔记与行业档案（在检索通道为只读；归档需走专门入库流程） |
| **`sales-notes`** | 销售邮件与纪要 | 交易台反馈、市场一致暗线预期（bogey/whisper）与早报催化；注意摘要转述与原件计作同源证据链 |
| **`tmtb`** | TMT 总结 | TMT 收盘总结与盘前盘后复盘（注：与原研报重复转述计同一条证据链） |
| **`funda-ai`** | FUNDA AI | 独立拆解与高频产业图表，适合 AI 算力与科技产业链跟踪 |
| **`all`** | 跨库初筛 | 并行检索 `company-wiki + sales-notes + tmtb + funda-ai`，同时并发检索 `alphaengine` 与 `guidepoint`；**不含 `transcript`** |

### 2. 财务、公告与宏观（`finance` / `macro` / `dalton_sec`）

- **美股 SEC 原始报表与 XBRL（`sec` & `dalton_sec`）**：支持 `10-K`、`10-Q`、`8-K`、`20-F`、`6-K` 及高管增减持 `Form 4` 等原文；`dalton_sec` 提供按日历/财季、年度、YTD、推导 Q4 与滚动窗口归一化的 XBRL 财务事实，并显式标明重述口径（`as_reported` vs `latest`）与申报号。
- **一致预期（`estimates`）**：营收、EPS 等一致预期快照，用于财报 Beat / Miss 对比与报告核验。
- **港 A 股财务与公告（`cn-hk`）**：包含法定公告（巨潮转载）、财务与估值问答（`ask`）及备用报价（`quote`）。注：港股约有 **5%** 缺口（主要是仅英文版公告与股东大会投票结果），助手会在需要原文时改用全网搜索查 `site:hkexnews.hk`。
- **宏观与市场状态（`fred` / `treasury` / `market-regime`）**：美国通胀、就业、GDP 与利率序列（FRED），财政部 TGA 余额与联邦债务（Treasury），以及市场过热/超卖、顶部底部、拥挤度与两融杠杆快照。

### 3. 实时行情、社区与公开网络

- **行情与 K 线**：在 Dalton 中优先使用免费行情链（美股免费行情数据、A 股日线与快照 `tushare`、非美盘中及全市场免费回退 `yfinance`），最后兜底 `fmp`（节省每日有限配额）；复牌日会自动交叉核对近期日线防止假暴跌，并支持**不复权**历史股价选项。
- **社区与公开网络**：雪球讨论（`xueqiu`）、员工评论（`employee`）、跨平台社区情绪（`last30days`）、固定账号 X 时间线（`x-timeline`）、全网搜索 `web_search`（Gemini Grounding）及 X 社媒检索 `x_search`（xAI）。

:::note[未直连的高频/另类数据]
暗池与期权异动流、高频另类数据（信用卡/卫星/海关等）目前未直连（13F 持仓可使用 `dalton-13f-tracker` 技能，期权链使用 `get_options_chain`；其余仅能通过 `alphaengine`/`funda-ai`/`guidepoint` 检索二手引述）。期货与大宗商品行情存在约 **15 分钟延迟**。
:::

## AlphaEngine 额度计费与系统缓存机制

### 1. 额度到底扣在哪里

- **每次检索（`search_library`）都会消耗一次额度**：哪怕两次传的参数完全一模一样，只要打到上游 AlphaEngine，就会扣减一次检索额度。
- **重读同一篇文档不扣额度**：使用 `get_document` 读过一次全文后，同一篇文档后续再翻页或重读不会重复扣费。
- **最佳实践**：检索前让分析师**把同一公司或同一主题的相关关键词合并进一次检索**（例如用中英文公司名和代码组合），不要把一个问题拆成三四次几乎相同的 `search_library` 调用。

### 2. 系统搜索缓存怎么工作

为了替团队省额度并加速常见查询，宿主机桥接层对 `alphaengine.search_library` 与 `transcript` 启用了 **SQLite 团队级精确缓存**（第一期）：

1. **参数规范化**：对查询词做全半角与空白归一化，统一日期键与数组排序；未填 `limit` 时统一按默认 **3 条**处理。
2. **大条数命中截取**：如果缓存里已经存过同一检索条件 `limit=20` 的结果，而你这次只查 `limit=5`，系统会直接从缓存截取前 5 条返回（不耗费新额度），并附上说明*「结果由更大条数的缓存截取；需要更多结果请提高 limit 重新检索」*。
3. **动态缓存有效期（TTL，按北京时间相对于查询结束日期计算）**：

| 查询结束日期（`end`）范围 | 缓存有效时长（TTL） |
| :--- | :--- |
| 未指定结束日期，或结束日期 ≥ 今天（北京时间） | 有结果缓存 **2 小时**；空结果缓存 **30 分钟** |
| 结束日期在过去 **7 天**内 | 缓存 **12 小时** |
| 结束日期早于 **7 天前**（历史查询） | 缓存 **7 天** |

### 3. 什么时候会绕过缓存（直接请求上游）

遇到以下四种情况时，系统**不会命中共享缓存**，而是直接访问 AlphaEngine 上游（并计入检索额度）：

1. **主动要求最新结果**：调用时传入 `params.fresh=true`（例如公司刚刚发布财报、突发公告或你明确在对话里要求“跳过缓存查最新进展”）。
2. **翻页游标续查**：请求携带了 `cursor` 翻页参数时，不走首屏缓存。
3. **个人会议范围（隐私隔离）**：任何涉及个人会议的请求（如 `meeting_scope="personal"`、`own_reservations_only` 或 `personalmeeting` 相关分类/代码）**永远绕过团队共享缓存**，保证个人会议记录绝对不会跨用户共享。
4. **仅规划模式（`mode="plan"`）**：不触发实际检索与缓存。

:::tip[怎么让分析师强制刷新]
如果你觉得某公司刚刚出了一篇重磅卖方点评但没搜到，可以直接在对话中告诉分析师：*“请加上 `fresh=true` 重新检索一次 AlphaEngine，别用缓存。”*
:::

## Guidepoint 专家库使用规则

- **只提供问答摘录**：Guidepoint 没有全文读取接口，也不支持游标翻页。
- **条数与上限**：`limit` 省略时默认返回 **3 条**，单次上限 **30 条**；即使返回满 30 条，也不能据此推断已经扫完全部访谈。
- **关键词与排序偏好**：`params.keywords` 支持 1–10 个非空字符串（多项之间为 OR，单个词组内为 AND）；`params.recency_bias` 取值 1–100（偏好近期访谈一般从 30 起，只影响排序，不截断日期）；`start`/`end` 按 UTC 日期硬过滤。
- **合规引用**：对外或报告中只能匿名引用专家职务/身份（不出现专家真实姓名），且原话直接摘录不得超过 **20 词**。
