了解 **Everflow** 的核心架构、「研究总监」与「工作区分析师」的分工，以及沙箱执行代码的工作方式。

Everflow 不是一个只做问答的聊天框，而是一套运行在隔离容器里的投研工作台。界面与品牌名为 **Everflow**，里面的研究助手叫 **Dalton**。你提问时，Dalton 会在平台托管的独立沙箱计算机（隔离的 Linux 容器环境）中编写并执行 Python 代码，直接拉取行情、财报、研报库与专家摘录，处理数据、绘制图表或生成 Excel/HTML 文件，再把经过交叉核对的结论呈现给你；默认情况下同一位用户的多个工作区共享主计算机沙箱、各自拥有独立的工作区目录，如需容器级隔离可将工作区建在另一台计算机上。

## 两个核心角色：研究总监与分析师

Everflow 的每一轮对话都会落在以下两种角色之一：

| 角色 | 所在位置 | 适合解决的问题 | 文件与上下文范围 |
| :--- | :--- | :--- | :--- |
| **研究总监（Chief of Staff）** | 「研究总监（Home）」全局视图 | 跨公司对比、日常快速问答、创建工作区、把任务分派给多个公司分析师并汇总结果 | 拥有自己的 `Home` 目录，可读取你名下工作区及已授权同事工作区的资料（取决于共享设置） |
| **工作区分析师（Analyst）** | 具体某个公司或专题工作区 | 深度覆盖、财报拆解、估值建模、修改工作区内的笔记与档案、运行长流程技能 | 专注于当前工作区目录、该工作区的长期记忆、资料（Memo）与本地产物 |

:::tip[第一次用怎么选]
不确定该去哪个工作区、需要同时对比几家公司、或只是先问一个快问题时，直接问**研究总监**；一旦任务要长期沉淀某只股票的知识档案、建立估值模型或出深度研报，建议在对应的**公司工作区**里与分析师对话。更多细节见 [研究总监还是分析师？](/help/compare/chief-of-staff-or-analyst/)。
:::

## 核心能力全景

- **程序化工具调用（PTC）**：Dalton 在处理复杂数据时，不会一次次零散地“猜数字”，而是把查询、清洗、统计和画图写进沙箱脚本里一次算清，减少幻觉并提升可复现性。
- **内部与公开研究数据源**：在一个入口内打通内部研报库（AlphaEngine）、专家访谈（Guidepoint）、业绩会转写（Transcript）、公司 Wiki、销售纪要、美股 SEC XBRL 原始财报、一致预期、港 A 股财务与公告，以及全网与社交媒体实时检索。详见 [研究数据源](/help/everflow/research-data-sources/)。
- **沉淀为团队资产**：工作区里生成的图表和 HTML 页面可以发布成团队可见的 [监控面板](/help/everflow/monitors/)；研究结论与一手纪要可以按规范归档进公司 Wiki 或销售纪要；[自动化任务](/help/concepts/automations-wakeups-commands/) 可以按计划或股价异动自动执行并把报告推到你的飞书、Discord 或微信。
- **团队协同与权限隔离**：支持管理员、内部成员和外部协作成员三级身份体系，内部成员之间可按账户开关或工作区三档权限协同研究，外部成员的工作区则保持严格隔离。详见 [分享与权限边界](/help/concepts/sharing/)。

## 与常见通用聊天助手的差异

1. **有状态的工作区文件夹**：你上传的 PDF、模型 Excel、生成的图表和报告（在持久化体积上限内）都会保存在工作区目录中，不会聊完即失。
2. **后台长任务与子代理协同**：深度覆盖、财报全套分析等复杂任务会自动拆分成多个并发子代理（Subagent）并行查库与核验；耗时较长的脚本会自动转为后台命令继续运行，完成后主动汇报。
3. **内置投研质量护栏**：Everflow 为中文投研场景内置了数据核验（Number Audit）与语言审校环节，强调来源可追溯、口径一致与明确标注未核实数字。
