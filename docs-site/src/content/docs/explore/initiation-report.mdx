从建库初始化到多源证据收集与数字核验，完成一家新公司的**首次覆盖报告**交付。

写首次覆盖报告建议在**公司独立工作区**中进行，依次走完「建工作区并初始化（`dalton-init-company`）→ 跑覆盖流程（`/initial-coverage` 或 `/full-coverage`）→ 数字核验与审校（`/dalton-publish`）」三步；长流程如果中途中断，只需回复**“继续”**即可接续上次进度。

## 准备工作：建工作区与预算确认

1. **新建工作区**：在左侧栏点击**新建工作区**，以目标公司命名（如“宁德时代”或股票代码）。
2. **上传本地资料**：如有团队会议纪要或外部文件，可直接拖入聊天输入框随提问发送（单文件上限 **200 MiB**，单条消息合计 **600 MiB**），或拖入右侧「文件面板」上传（单文件上限视存储配置为 **100 MiB** 或 **256 MiB**）。
3. **确认单任务预算上限**：首次覆盖与完整覆盖会编排多个子代理并行查库，耗时较长。若你在「设置 → 个人设置 → 用量与预算」设置了较低的默认单任务上限，建议提前为该工作区单独配置合适的任务上限（或保持默认的日预算控制）。

## 执行步骤

### 第一步：初始化公司档案

在工作区对话中输入 `/dalton-init-company` 或直接指示：

> 请帮我初始化这家公司的知识档案（Knowledge 与 Agenda），确认股票代码与交易所时区。

分析师会梳理公司基本面背景、确立核心论点文件与跟踪议程结构。

### 第二步：启动首次覆盖或完整覆盖

根据需要的深度选择对应指令：

- **首次覆盖（`/initial-coverage`）**：多阶段编排工作流，默认子任务超时放宽至 **90 分钟**（`workflow.child_timeout: 5400`），避免大规模证据抓取中途被截断。
- **完整覆盖（`/full-coverage`）**：面向需要更全面拆解竞争格局、财务透视与情景建模的标的。

在提示词里写清你最关心的问题（如：核心增长驱动、单位经济模型、关键风险与赔率评估），分析师会自动并发调用：
- `dalton_sec` / `cn-hk` 获取法定财务数据；
- `alphaengine`、`guidepoint` 与 `transcript` 获取卖方观点、专家访谈和管理层口径；
- `estimates` 获取一致预期。

:::tip[中途断开或想继续怎么办]
1. 长流程中单个对话最多同时运行 **8 个**后台子代理，其余会自动显示「排队中」，请耐心等待，**不要让分析师重复派发同一子任务**。
2. 如果因为网络或系统重启导致长流程中途停下，直接发送 **“继续”**，系统会接着上次已完成并检查过文件的阶段续跑；只有在你想彻底重跑时才说“重新开始跑一次”。
:::

### 第三步：数字核验、语言审校与交付

初稿落盘工作区后，核对质量分成两档标准：

1. **日常研究交付**：让分析师跑完数字核验与语言检查，只要把核验工具列出的少数“尚未核实”数字明确标明供你人工判断，即可交付团队内部讨论或写入飞书文档。
2. **正式发布（`/dalton-publish`）**：正式发布的研报要求未核实数字清零，系统会在独立子进程中进行跨段落与数据源比对，确保口径一致且无“核验未完成”遗留项。

:::note[核验细节说明]
- “9.14 亿美元”与原始英文“$914 million”等单位换算写法核验工具会自动识别对齐，不会误报差异。
- 如果报告篇幅很大导致部分派生比对超出单次核验超时，系统会明确标出**「核验未完成」**及具体原因，方便重新触发核验，不会无限卡死在“审计中”。
:::
