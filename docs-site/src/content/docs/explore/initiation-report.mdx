这页带你走完写**首次覆盖报告**的完整流程，从建工作区、收集多源证据到数字核验与发布。

写首次覆盖报告时，先给目标公司建一个**独立工作区**，再按三步走：初始化公司档案（`/dalton-init-company`）→ 跑覆盖流程（`/initial-coverage` 或 `/full-coverage`）→ 数据核验与审校（`/dalton-publish`）。长流程中途断掉时，回一句**“继续”**就能接着跑。

## 准备工作：建工作区与确认预算

1. **新建工作区**：点左侧栏的**新建工作区**，用公司名或股票代码命名（比如“宁德时代”）。如果团队或你名下已有这家公司的工作区，系统会自动提醒供你直接复用，避免重复建区。
2. **上传本地资料**：手头有团队纪要或外部文件，直接拖进聊天输入框（单文件上限 **200 MiB**，单条消息最多 **10 个附件**、合计 **600 MiB**），或者拖进右侧「文件面板」（单文件上限看存储配置，为 **100 MiB** 或 **256 MiB**）。
3. **确认单任务预算上限**：首次覆盖和完整覆盖会并发调多个子代理查库，跑的时间比较久。如果你在「设置 → 个人设置 → 用量与预算」设过较低的默认单任务上限，建议提前给这个工作区单独调高上限，或者留着默认的日预算控制。

## 执行步骤

### 第一步：初始化公司档案

在工作区对话里发 `/dalton-init-company`，或者直接对助手说：

> 请帮我初始化这家公司的知识档案（Knowledge 与 Agenda），确认股票代码与交易所时区。

分析师会整理公司基本面背景，建好核心论点文件和跟踪议程结构。

### 第二步：启动首次覆盖或完整覆盖

按需要的研究深度挑一个指令：

- **首次覆盖（`/initial-coverage`）**：多阶段编排流程，默认把单支子任务超时放宽到 **90 分钟**，避免大规模查资料跑到一半被掐断。
- **完整覆盖（`/full-coverage`）**：适合要更深拆解竞争格局、财务透视和情景建模的标的。

发指令时顺手写清你最关心的问题——比如核心增长驱动、单位经济模型、关键风险和赔率评估。分析师会自动并发调这些数据源：
- 美股 SEC 财报或港 A 股法定公告与财务数据；
- {/* DALTON_DOC:everflow */}AlphaEngine 卖方研报、Guidepoint 专家访谈与业绩电话会转写{/* DALTON_DOC_ELSE */}业绩电话会转写与公开行业资料{/* /DALTON_DOC */}；
- 市场一致预期数据。

:::tip[中途断开或排队怎么办]
1. 长流程里单条对话最多同时跑 **8 个**后台子代理，多出来的会显示「排队中」。等队列依次消化完就行，不用重复派同一个任务。
2. 网络波动或系统重启导致长流程停在半路时，直接回一句 **“继续”**，系统会检查已经落盘的文件进度接着跑。只有想彻底重来时，才说“重新开始跑一次”。
:::

### 第三步：数据核验、文字审校与交付

初稿写进工作区后，核对分成两档标准：

1. **日常研究交付**：让分析师跑完数据核验和文字审校。核验工具列出的少数“尚未核实”数字会明确标出来供你判断，之后就能发给团队讨论{/* DALTON_DOC:everflow */}或写进飞书文档{/* DALTON_DOC_ELSE */}或在工作区归档留存{/* /DALTON_DOC */}。
2. **正式发布（`/dalton-publish`）**：正式发布的研报要求全部数字均已完成核实，系统会逐段对照数据源保证口径统一，所有核验条目均须通过。

:::note[核验细节说明]
- “9.14 亿美元”和英文原文“$914 million”这类单位换算，核验工具会自动对齐为一致口径。
- 报告很长、部分派生比对超出单次核验超时时，系统会明确标出**「核验未完成」**和原因，方便你单独重跑核验、快速收尾。
:::
