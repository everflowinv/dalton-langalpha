说明 Everflow 中三类后台异步能力——**自动化任务（Automations）**、**唤醒（Wakeups）** 与 **后台命令（Background Commands）** 的机制与状态。

日常定时研究与个股异动监控请统一使用左侧导航的 **自动化（`/automations`）**；对话中超过 5 分钟的长脚本会自动转为**后台命令**并在结束后主动向你汇报；而上游的**对话内自定唤醒（`schedule_wakeup`）**与**内置目标价（`watch_market`）**功能在当前 Dalton 部署中处于**关闭状态**。

## 1. 自动化任务（Automations）

打开左侧主导航的 **自动化（`/automations`）**，可以创建、管理和查看团队及个人自动任务，支持三种触发方式：

| 触发方式 | 界面标签 | 适用场景 | 关键规则 |
| :--- | :--- | :--- | :--- |
| **按计划（Cron）** | `按计划` | 每日盘前晨报、每周行业扫描、定期公司近况巡检 | 可选执行频率与时区（默认跟随 Home 时区） |
| **一次性（Once）** | `一次性` | 预约在未来某个明确时间点跑一次研究或检查 | 到点执行一次后自动进入「已完成」分组 |
| **价格触线时（Price）** | `价格触线时` | 盯一只股票价格突破目标价或单日/参考基准涨跌幅达标时自动触发 | 填写股票代码、触发条件（金额或百分比基准）即可监测 |

### 自动化任务的管理与可靠性保障

- **前置预检（Preflight）**：平台托管的自动巡检任务启动前会先做零消耗前置预检（常规任务超时 **45 秒**，数据健康任务 `dalton-data-health` 超时 **600 秒**），判断是否有新事件或达到触发条件；未达条件时直接跳过。其中公司跟踪、行业巡检和数据健康任务在预检超时后也会跳过，避免浪费额度；日历与研究总监日报/周报等汇总任务在预检超时后仍会保守唤醒分析；用户自建的普通自动化任务则按配置直接触发，不经过该预检。
- **团队公共任务与修改历史**：内部成员与管理员可以在自动化页查看团队级公共任务（如周期性研报扫描、公司近况巡检）的运行记录、修改历史与版本回滚；删除的任务会进入 **30 天回收站**，误删可恢复。
- **指定模型与通知路线**：在自动任务高级选项中可为单个任务指定模型（留空则使用账户默认模型）；列表页和详情页支持勾选该任务的个人及飞书团队群推送目标。详见 [定时报告与投递](/help/everflow/scheduled-reports-and-delivery/)。
- **后台续跑保持投递**：如果自动任务派生了后台命令或子代理，整个任务执行记录会保持等待直到后台工作彻底完成（当前默认最长上限 **6 小时**，由系统工作流超时与至少 3 小时保底共同决定），确保最终报告仍能准确投递。

### 跟踪议程（Agenda）的到期规则

在公司工作区的议程中记录待验证事项时，如果只填写了日期（如 `2026-11-18`）而没写具体时刻，系统会按**该工作区股票所属交易所当地时间 18:00** 判定为到期：

- A 股按上海时间 18:00，港股按香港时间 18:00，美股按纽约时间 18:00（涵盖收盘后业绩电话会）。
- 往议程添加或修改到期时间时，只接受标准日期（`YYYY-MM-DD`）或带时区的完整 ISO 时间，不接受模糊文字描述。

## 2. 唤醒（Wakeups）与内置盯盘目标价

在 `config.dalton.yaml` 中，`features.wakeups.enabled` 与 `features.market_watch.enabled` 均为 `false`：

- 助手不会在对话里自行注册后台定时器（`schedule_wakeup`）或内置价格触发器（`watch_market`），避免无人值守时静默消耗预算。
- 所有需要定时追踪或盯盘的需求，请直接在 [自动化（`/automations`）](/help/explore/price-move-watch/) 中明确配置开关与触发条件。

## 3. 后台命令（Background Commands）

当分析师在工作区沙箱中通过 Bash 或 `execute_code` 执行耗时操作（如批量回测、长视频/音频转写后处理、大规模数据清洗）时：

1. **自动交接转后台**：单次调用默认等待 **5 分钟**（Bash 最长可设 **10 分钟**，或由助手直接设为后台运行）。超时未结束的命令不会作废，而是自动转为后台命令继续运行，输出持续写入工作区日志 `.agents/threads/<thread8>/commands/<command_id>.log`。
2. **随时查看与一键停止**：聊天框底部状态栏会显示**「N 个命令运行中」**，对应的执行步骤行上会出现实时状态与**停止**按钮，不想等时可随时中止。
3. **自动回报结果**：命令跑完时，如果当前回合还在跑，结果直接并入该回合；如果回合已结束，系统会自动开启一轮新回复把命令结果汇报给你。
4. **额度耗尽不丢结果**：若命令完成时你的每日模型预算恰好耗尽，结果会先安全保留；额度恢复后，你只需在原对话里发一句话或继续操作即可拿到完整输出。
5. **休眠停机规则**：在闲置会自动休眠的计算机上，后台命令会在所在对话最后一轮回答结束 **1 小时**后自动停止。

:::note[遇到后台命令一直跑不完？]
可以点击状态行里的**停止**按钮，再让分析师检查刚才日志里的报错或改小测试范围重试。
:::
