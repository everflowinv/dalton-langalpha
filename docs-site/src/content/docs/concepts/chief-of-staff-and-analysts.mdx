这页讲清 Everflow 里**研究总监（Chief of Staff）**和**工作区分析师（Analyst）**怎么分工、怎么派活，以及同事间协同的边界。

**研究总监**管全局统筹、快问快答、建工作区和往下派活。**工作区分析师**留在具体工作区里，专做深度投研、写代码查库、搭模型和出报告。要跨工作区比几家公司，找研究总监；要深挖一只标的并沉淀文档，进对应的工作区找分析师。

## 职责与工具能力对比

| 维度 | 研究总监（Chief of Staff） | 工作区分析师（Analyst） |
| :--- | :--- | :--- |
| **所在位置** | 「研究总监（Home）」全局视图 | 任意公司或专题工作区 |
| **运行目录** | 个人 `Home` 目录 | 当前工作区目录 |
| **专属工具** | 管工作区、向分析师派活（`delegate_to_analyst`）、看协调汇报、管对话 | 读写当前工作区文件，调用沙箱和研究技能 |
| **深度研究子代理** | 把单家公司的深度任务转派给目标工作区的分析师 | 直接调用内置与长流程编排技能，并发跑多个后台子代理 |
| **团队记忆查阅** | 在设置里打开「共享团队历史研究记录」后，统筹时能查团队公开研究结论与对话 | 按配置查当前工作区和全局数据源 |

## 派发与汇报流程

你在「研究总监」里提出一个具体公司的深度任务时，后台会按下面四步流转：

1. **派活**：研究总监先定位目标公司工作区。要是还没有，经你确认（或已开启「创建工作区前不再询问」）后会帮你新建，再通过交接工具把明确目标交给那个工作区的分析师。
2. **执行与排队**：分析师在自己的沙箱里查数据、写文件或跑长流程。多个任务并发时，单条对话最多同时跑 **8 个**后台子代理，全系统最多 **24 个**，多出来的自动排队。
3. **中断续跑与稳定汇报**：如果分析师的任务中途碰到重启并自动续跑，系统会留着交接关系，等续跑稳稳结束后再把最终结论送回你的 Home 对话。如果你主动取消了任务，就不会再续跑。
4. **查看回报**：研究总监的回复里会贴一张紧凑的交接卡片，点**查看汇报**就能直接跳去对应工作区看详细结论和文件。

:::tip[减少确认打断]
如果习惯让研究总监直接建工作区并马上派活，可以去「设置 → 个人设置 → 对话与助手」打开**「交给分析师前不再询问」**和**「创建工作区前不再询问」**。
:::

## 给同事的工作区派活（协同规则）

在权限允许的范围内（仅限内部成员和管理员之间），你可以让自己的研究总监往同事的工作区派任务，也可以在同事设为「可读写」的工作区网页里新建对话提问。如果页面上找不到对应入口，请联系管理员。

- **派发标记**：同事发起或派发的对话，会标出**「由某某派发」**。
- **发起人专属追问与只读保护**：这条对话**只有发起人本人能继续追问**。工作区主人和其他有权限的同事点进去时，输入框是只读的。这样既方便大家看过程和结果，也能保住原对话的上下文不被打乱，工作区主人也不会收到多余未读红点。
- **费用与入库归属**：向同事工作区派任务时，**模型调用费算进发起人（提问人）自己的每日预算**。派发过程中触发的资料入库，记录也算在发起人名下。
- **外部成员严格隔离**：外部成员的研究总监谁的工作区也碰不到，任何人的研究总监（包括管理员）也永远看不到外部成员的工作区。详情见 [分享与权限边界](/help/concepts/sharing/)。
