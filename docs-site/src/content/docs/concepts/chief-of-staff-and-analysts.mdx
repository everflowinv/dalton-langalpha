介绍 Everflow 中**研究总监（Chief of Staff）** 与 **工作区分析师（Analyst）** 的工具能力、任务派发路径与团队只读保护边界。

**研究总监**负责统筹、快问快答、管理工作区和向下派活；**工作区分析师**负责在具体工作区里执行深度投研、写代码查库、建模和出报告。遇到跨工作区或需要同时调动多家公司的问题，找研究总监；需要深挖单个标的和沉淀文档，找对应的工作区分析师。

## 职责与工具能力对比

| 维度 | 研究总监（Chief of Staff） | 工作区分析师（Analyst） |
| :--- | :--- | :--- |
| **所在位置** | 「研究总监（Home）」全局视图 | 任意公司或专题工作区 |
| **运行目录** | 个人 `Home` 目录 | 对应工作区目录 |
| **专属协调工具** | 管理工作区、向工作区分析师派活（`delegate_to_analyst`）、读取协调输出、管理对话 | 专注当前工作区的文件、沙箱与研究技能 |
| **深度研究子代理** | 不直接启用 `equity-analyst` 等单公司深度研究子代理，而是把深度任务交给目标工作区的分析师完成 | 可直接调用内置及长流程编排技能，并发运行多个后台子代理 |
| **团队记忆查阅** | 若在设置中开启「共享团队历史研究记录」，统筹时可查阅团队过往公开研究结论与对话记录 | 根据配置查阅当前工作区与全局研究数据源 |

## 派发与汇报流程

当你在「研究总监」里提出一个涉及具体公司深度研究的任务时，实际流转如下：

1. **派活**：研究总监根据你的意图定位目标公司工作区（如没有且获得你的确认或已开启「创建工作区前不再询问」，会替你新建工作区），然后通过交接工具把明确的任务目标派发给该工作区的分析师。
2. **执行与排队**：工作区分析师在自己的沙箱里独立查数据、写文件或跑长流程；如果有多个任务并发，单个对话最多同时运行 **8 个**后台子代理（全系统最多 **24 个**），其余自动排队。
3. **等待与静默完成**：如果分析师的任务中途被系统重启或中断并自动续跑，系统会保留交接关系，等续跑彻底稳定结束后，再把最终结论回报到你的 Home 对话中（若你主动取消了任务则不会自动续跑）。
4. **查看回报**：在研究总监的回答里会附带紧凑的交接卡片，点击**查看汇报**可以直接跳转到对应工作区的详细结论与产物。

:::tip[减少打断的快捷设置]
如果你习惯让研究总监全自动建工作区并直接派活，可以在「设置 → 个人设置 → 对话与助手」里开启**「交给分析师前不再询问」**和**「创建工作区前不再询问」**。
:::

## 给同事的工作区派活（协同规则）

只要在权限允许范围内（仅限内部成员与管理员之间），你可以让自己的研究总监向同事的工作区派任务，或在同事设为「可读写」的工作区网页里新建对话提问（如果你在页面上看不到相关入口，请联系管理员）：

- **派发对话标记**：由同事发起或派发的对话会标上**「由某某派发」**。
- **发起人专属追问 & 只读保护**：这条对话**只有发起人自己能继续追问**；工作区所有者和有访问权限的其他同事打开查看时，输入框为只读状态，方便围观过程和结论，但不会打乱对话，也不会给工作区主人亮起未读红点。
- **费用与入库归属**：向同事工作区派发任务时，**模型调用费用计入发起人（提问人）自己的每日预算**；如果派发过程中执行了资料入库，入库记录也记在发起人名下。
- **外部成员严格隔离**：外部成员的研究总监不能访问任何人的工作区，任何人的研究总监（含管理员）也永远不能访问外部成员的工作区。详情见 [分享与权限边界](/help/concepts/sharing/)。
