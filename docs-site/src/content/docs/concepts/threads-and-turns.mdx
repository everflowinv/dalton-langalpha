解析**对话（Thread）**与**回合（Turn）**的运行生命周期，包括流式重连、打断续跑与上下文自动压缩机制。

一个工作区可以包含多条互不干扰的**对话（Thread）**；你在一条对话里每发一次消息或由自动化触发一次执行，就开启一个**回合（Turn）**。每个回合有独立的推理配置记录、断线重连缓冲与上下文压缩机制。

## 对话（Thread）与回合（Turn）

- **对话（Thread）**：对应侧边栏里的一条会话记录，承载同一脉络下的连续追问、产物卡片与历史引用来源（单次回复的溯源归档上限可达 **10,000 条**，多轮对话可跨回合累积）。
- **回合（Turn）**：指从你按下发送（或后台任务/命令回报唤醒）开始，到助手完成思考、调完工具并给出最终回复的完整过程。
- **回复中断与防丢**：
  - 所有流式事件都会在服务端缓存在 Redis 并同步落入检查点，刷新页面或网络闪断时会自动从断点重放，不会丢失正在生成的结果。
  - 若你在大模型生成前刚好打断了对话，下一句仍会保持原本选定的模型继续运行，不会因为格式中断被迫切换备用模型。

## 单条对话的独立推理设置

- 在聊天输入框下方调节的**推理强度**（如高、中、低）和**速度**，只对**当前这一条对话**生效，并随该对话长期保存，换电脑或刷新都不会丢。
- 如果你想改变所有**新对话**的全局默认值，前往「设置 → 个人设置 → 模型」修改即可。
- 在「设置 → 个人设置 → 对话与助手」中，还可以单独调整：
  - **实时显示推理**（开 / 关）
  - **回答显示方式**（连续显示 / 按段落）
  - **工具调用**（逐行 / 状态行）
  - **回复结束时**（停留在末尾 / 显示回复开头）

## 长对话上下文压缩

当一条对话积累了大量工具返回与多轮分析、接近模型的上下文窗口上限时，Everflow 会触发**自动压缩**：

1. **按 token 预算保留近期内容**：系统不会粗暴地按“最后几条消息”截断，而是按 token 预算保留近期完整对话（默认约 **2 万 token**，Claude 模型约 **3.2 万 token**，上限不超过模型压缩触发阈值的三分之一）。
2. **清理旧历史附件**：早期回合中占体积的图片或旧内联附件会被自动清理，保留结构化研究结论，保证后续追问不超时、不报错。
3. **跨模型切换交接**：如果你在长对话中途切换了另一家模型，且历史中存在旧模型专有的加密思维摘要，系统会让原模型先将其转为通用文字摘要再交接给新模型。
4. **冷启动压缩关闭**：在当前 Dalton 部署中，回合开头的冷压缩（`cold_compact_tokens`）保持关闭（设为 `0`），日常长对话仅在达到阈值时触发常规压缩。

## 输入框草稿与消息附件

- **自动草稿保存**：在输入框打字后还没发出去之前，即使切到别的工作区或刷新页面，草稿也会自动保留在当前浏览器中（保留 **7 天**，单条上限 **100 KB**，不同账号互不串味）；**只有当服务端确认收到消息后才会清除**。注意：**草稿只保存文字，不保存待发附件**。
- **附件上传机制与上限**：
  - 从聊天输入框直接上传时，文件会在添加时立即分段上传，并显示实时体积与进度，支持单文件重试。
  - **带工作区直传上限**：单文件最大 **200 MiB**，单条消息所有附件合计最大 **600 MiB**；附件落盘到工作区 `work/uploads/` 目录供代码沙箱直接读取。
  - **内联发送回退上限**：当工作区不可用或直传通道未启用时，走内联通道的文件上限为单文件 **30 MiB**、单条消息合计 **60 MiB**。
  - **图片自动适配**：发送给模型的单张图片若超过 **5 MiB** 或尺寸/方向异常，系统会自动缩放转码并摆正方向；单次传给模型的图片总预算为 **20 MiB**，超出时优先保留最新图片，较早图片转为提供工作区文件路径。
