## 一分钟看懂

把 Dalton 想象成一个**小型研究团队**：

| 角色 | 在系统里叫什么 | 负责什么 |
|---|---|---|
| **研究总监** | Chief of Staff，在 **Home** 工作区 | 看全局：管理你的覆盖名单、回答"今天哪些公司有变化"、"帮我比较 GOOGL 和 META 的云业务"，并把具体研究派给对应公司的分析师 |
| **公司分析师** | 每家公司一个**工作区**（比如 GOOGL 工作区） | 专门负责这一家公司：建覆盖、建模型、读公告、跟财报、写报告 |
| **档案柜** | 每个公司工作区里的**知识档案** | 记录这家公司的 thesis、核心争论、关键驱动因素、管理层、历次结论。分析师每次研究都在这份档案上接着做，不会从零开始 |
| **审稿人** | 独立审稿模型 | 正式报告发布前，用**另一家公司的模型**挑错，避免自己审自己 |
| **你（PM）** | 审批人 | 正式报告必须由 PM 点"批准"才会发布 |

Dalton 和普通的 AI 问答有三点不同：

1. **它有记忆，而且记的是"研究档案"，不是聊天记录。** thesis 是什么、上次结论是什么、还有哪些问题没验证，都写在档案里，下次研究直接接着做。
2. **它会自己推进研究并私信汇报。** 打开"自动跟踪"后，有新公告、新研报、盘中股价大动、财报临近，它都会自己处理，在档案里记下结论，并把重要结果通过飞书或 Discord 私信发给你。
3. **正式报告有关卡。** 报告在完成与发布前会经历两轮语言审查（只标问题不改原意）、逐个核验数字（找不到出处、引用的模型公式未重算或与证据矛盾的数字会挡住发布）、独立审稿和 PM 审批，通过后才算正式发布。草稿阶段只提示问题，不拦着你继续研究。

## 开始使用

### 1. 登录

用浏览器打开团队的 Dalton 地址，用公司邮箱登录。只有名单里的邮箱能登录。新账号默认使用**香港时区（`Asia/Hong_Kong`）**和中文界面，并默认开启研究总监向公司分析师派活时的自动交接（都可以在设置里修改）。

### 2. 连接 AI 模型（第一次使用，或者页面提示"请重新连接"时）

进入 **设置 → 模型**，可以看到各个模型账号的状态。系统接入了下面这些模型，都走团队的**订阅账号**，不按次收费：

- Anthropic Claude（订阅）
- OpenAI GPT（ChatGPT 会员订阅，系统里叫 Codex）
- Google Gemini（订阅）
- xAI Grok（SuperGrok 订阅）
- Meta Muse（订阅）
- 智谱 GLM（Coding Plan 订阅）

另外还可以经 OpenClaw 使用更多模型（名字以 `ocb-` 开头），以及按量计费的 DeepSeek 等。

看到"请重新连接"，点对应的连接按钮，按页面提示完成：多数是在弹出的网页里用该账号登录并确认授权（和"用微信或 Google 账号登录某个网站"是一回事），有的需要输入页面上显示的验证码。**PM 连一次，全队共用**，同事不需要各自连接。

### 3. 看懂页面

- **左侧栏**：各个工作区。点 **Home**（或"All workspaces"）就是在找研究总监；点某家公司的名字（如 GOOGL）就是在找这家公司的专属分析师。"团队"分组里可以看到同事的工作区（只读）。仪表盘保留了**持仓**视图供查看持仓，交易与券商连接入口已隐藏。
- **覆盖一家新公司**：在 Home 里对研究总监说"把 NVDA 加进核心覆盖"或"开始覆盖 NVDA"，或在左侧栏新建一个以股票代码命名的工作区。通过研究总监新建时，如果已经有同名或同一股票代码（如 `700.HK` 与 `0700.HK`）的工作区，它不会自动新建，而是弹出确认卡片并给出已有的工作区；你可以直接用已有的，也可以确认后继续新建（完全同名的仍需换个名字）。
- **对话区**：和分析师说话的地方。分析师的每一步操作（查数据、跑代码、读文件）都会显示成卡片，可以点开看。
- **文件面板**：工作区里的所有文件，包括知识档案、模型 Excel、报告草稿、已发布报告。

## 日常怎么用

### 直接说话

用平时和分析师说话的方式就行，不需要特殊格式。例如：

- 在 **GOOGL 工作区**里说："Search 本季增速放缓主要是什么原因？和一致预期比怎么样？"
- 在 **Home** 里说："这周我的覆盖池里有哪些公司出现了 thesis 变化？"
- 在 **Home** 里说："帮我看一下 NVDA 今天为什么跌了 6%。"（不需要先建工作区）

### 管理你的覆盖名单

每个人都有自己独立的覆盖名单，分**核心标的（Core）**和**观察名单（Watch）**两档，和同事互不干扰。在 **Home** 里直接对研究总监（Chief of Staff）说话就能管理：

- **加减单家公司或改档位**：比如"把 NVDA、TSM 加进核心覆盖"、"把 BABA 调到观察名单"、"把某公司移出覆盖名单"。系统会自动核对股票代码，补全公司名、市场和行业。
- **按描述加一组公司**：比如"帮我把市值 100 亿美元以上的美股半导体公司加到观察名单"。研究总监会先筛出符合条件的公司列表给你确认，你点头后才加入名单。这类按条件加入的分组每季度会自动刷新一次；不再符合条件的公司只会标出来提醒你，不会自动删掉。

### 常用的"快捷命令"

在输入框里打 `/` 会弹出命令列表。**不用背**：直接用大白话说"帮我做一下 META 的首次覆盖"，效果和输入 `/initial-coverage` 一样。最常用的几个：

| 命令 | 在哪里用 | 做什么 |
|---|---|---|
| `/initial-coverage` | 公司工作区 | **首次覆盖**：公司背景、行业、财务三镜头（净现金、隐含资产、股东回报三项"体检"）、估值历史四条线并行，产出买方 12 问初筛报告（生意模式、竞争壁垒、增长驱动、财务质量、估值、多空分歧等 12 个核心问题），并建立这家公司的知识档案 |
| `/full-coverage` | 公司工作区 | **完整覆盖**：事实底表、四条取证线、带公式的 Excel 模型（含 DCF）、12 问 memo、两轮审稿 |
| `/bullbear` | 公司工作区 | 多空分析：一致预期 vs 2–4 个核心争论、预期修正、催化剂 |
| `/dalton-earnings-preview` | 公司工作区 | 财报前瞻：给出可以事后核对的预测清单 |
| `/dalton-earnings-flash` | 公司工作区 | 财报快讯：发布后第一时间的解读和初步结论 |
| `/dalton-earnings-deep` | 公司工作区 | 财报深度点评：八段式点评、thesis 校准；已有财务模型时同时更新模型 |
| `/dalton-filing-review` | 公司工作区 | 读一份公告（美股 SEC、港股、A 股）并给出结论 |
| `/dalton-stock-move` | 任何地方 | 解释一次大的股价异动：先查今天和昨天的新闻与 X 搞清楚发生了什么，再查公告、研报并区分是板块共振还是公司自身原因 |
| `/dalton-call` | 公司工作区 | 高 conviction 观点：先过六道证据检查（逻辑是否完整、分歧是否落到具体驱动因素、三种情景的估值是否算清等），再给情景加权收益和仓位建议；证据不够时只陈述事实，不硬给买卖建议 |
| `/dalton-language` | 任何地方 | 对报告草稿或研究笔记做中文语言审查（只标问题，不改原文） |
| `/pm-qa` | 任何地方 | 按五段式回答 PM 关于覆盖公司的问题 |
| `/weekly-review` | Home | 覆盖池周度复盘 |
| `/topic-research` | Home | 跨公司主题研究，比如"AI agent 对搜索广告的影响" |
| `/dalton-director` | Home | 让研究总监扫一遍覆盖池，按紧急程度在当天预算内派活 |

### 读懂知识档案

每个公司工作区的根目录下有这些文件。**这是分析师对这家公司的全部认知**：

| 文件 | 内容 |
|---|---|
| `thesis.md` | 投资逻辑：核心观点、支撑的证据、什么情况下会证伪 |
| `debate.md` | 市场上的核心争论，以及多空双方各自的论据 |
| `drivers.md` | 关键驱动因素和跟踪指标（比如 Search 的点击量和 CPC、云的 backlog），以及已经拿到的最近读数和来源 |
| `management.md` | 管理层和他们的指引风格 |
| `agenda.md` | 研究议程：还没回答的问题、下一个验证点和时间 |
| `lessons.md` | 复盘教训 |
| `verdicts.md` | 研究的**结论记录**（最近 60 条），每条用五个词之一：无变化 / 强化 / 削弱 / 证伪 / 新论点 |
| `published/` | 已正式发布的报告（发布后不可修改） |
| `drafts/` | 报告草稿 |
| `model/` | 财务模型 Excel |

**想修改档案，最好直接告诉分析师**，比如"把 thesis 的第二个支柱改成……"，它会按规范写入并留下修改理由。如果你直接改了这些 `.md` 文件，系统会保存你的修改并提醒分析师合入；在分析师合入之前，正式档案不会变。档案的每个版本都会留底，可以回看改了什么、为什么改。

### 日常笔记和正式报告

- **日常与起草保持 Markdown**：日常笔记（写在 `research/`）和报告草稿（写在 `drafts/`）平时都保持 `.md` 格式。如果你在设置里把输出格式选为 HTML，正式发布时还会生成一份排版好的同名 `.html` 文件。
- **日常笔记**：财报快讯、公告点评、异动解释、增量检查等，写在工作区的 `research/` 里，并直接在对话中告诉你结论，**不需要 PM 审批**。
- **正式报告**：首次覆盖、完整覆盖、多空报告、深度点评、调整观点等，先写成 `drafts/` 里的草稿，走下面的发布流程后才进入 `published/`。

### 发布一份正式报告

1. 让分析师写报告。草稿放在 `drafts/` 里。
2. 在报告收尾与提交发布的过程中，会依次经过三道把关：
   - **语言审查（两轮，只标不改）**：检查草稿里有没有空洞套话、没有数字支撑的程度词、不必要的中英混杂、生硬翻译腔或逻辑跳步。审查工具只在旁边的清单里标出原句和修改建议，不直接改稿；分析师按清单改完后再过第二轮复核（日常研究笔记和自动推送稿同样要过两轮语言审查）；
   - **数字核验**：逐个核对报告里的数字、单位、币种和比率，看能否对上出处（档案里的证据、已重算的 Excel 模型单元格、原始文件）。找不到出处、引用的模型公式未重算或与证据矛盾的数字会挡住发布；汇率折算、拿不准的以及明确标为假设或估计的数字会列出来，交给 PM 判断；
   - **独立审稿**：用另一家公司的模型审一遍，审稿人和作者不能是同一家的模型。
3. 数字核验和独立审稿通过后，对话里会弹出一张**发布审批卡片**，列出核验结果、拿不准的地方和审稿意见。**只有 PM 能点"批准"**。
4. 批准后，报告写入 `published/`。正式版本不覆盖，需要更正时发布一个新版本。批准只对当时的正文和附件有效，发布完成前如果内容又被改动，需要重新审批。

如果是自动任务里写的报告，系统不会打断你，而是把"待审批"放进议程，等你下次打开时处理。

## 它会自己做什么

### 自动跟踪

覆盖名单分两档：**核心标的（Core）**是重点覆盖的公司，**观察名单（Watch）**是需要留意但不做高频盯盘的公司。

一家公司打开"自动跟踪"后，系统会按档位安排三件事：

| 任务 | 什么时候 | 做什么 |
|---|---|---|
| **盘中盯盘** | 仅**核心标的**：周一至周五 6:00–20:30 每 30 分钟一次（美股按美东时间，A 股和港股按北京时间；观察名单不做盘中盯盘） | 先做一轮低成本检查：SEC 或巨潮有没有新公告、议程里有没有到期的验证点、财报日是否临近。**什么都没有就直接跳过**；有事才唤醒分析师去处理 |
| **内部来源与每日增量** | 北京时间 11:00：核心标的周二至周六每天一次（对应美股周一至周五收盘后）；观察名单周六一次 | 每天集中扫描一次六个内部研究来源（公司 wiki、专家访谈、独立研究、销售纪要、TMT 纪要、卖方研报）、一致预期变化和新公告；没有实质变化就记一笔"无变化"并提前结束 |
| **股价异动提醒** | **只在常规交易时段**，股价较前收盘涨跌达到 ±4% 时（每个交易日上涨、下跌各最多触发一次；盘前、盘后和休市不触发） | **先查今天和昨天的新闻与 X** 搞清楚当天发生了什么，再查公告、卖方研报与专家纪要，并做同业和板块对比。如果只是大盘或板块共振、没有公司自身的催化，只记一笔"无变化"，不发私信打扰你 |

另外，**财报日历**（见下节）确认财报日期后，会为核心标的单独排好"财报三连"：财报前 3 个工作日早上 8:00 做前瞻，发布后 30 分钟出快讯，发布后下一个工作日晚上 8:00 做深度点评。

分析师每次被唤醒、处理完之后，都要在 `verdicts.md` 里记一条五词结论，并更新研究议程。

> **怎么开关**：可以在 **设置 → 模型** 页面或自动任务列表随时查看和开关每家公司的跟踪，也可以直接对研究总监或公司分析师说"开始跟踪 NVDA"、"暂停 GOOGL 的跟踪"。

### 结果私信推送

重要的自动任务跑完后，可以把结论直接私信推给本人（支持**飞书交互卡片**和 **Discord 私信**，卡片底部带"在 Dalton 中打开"按钮直达原对话）：

- **哪些任务会推送**：
  1. **财报快讯与深度更新**（发布后 30 分钟快讯、次一工作日深度点评）；
  2. **有实质催化的股价异动**（结论不是"无变化"时才推；纯板块共振不推）；
  3. **财报前 3 个工作日前瞻**；
  4. **周度复盘与财报日历周报**。
  - 日常盘中盯盘、每日增量检查、每日派活和数据源体检不会发私信。推送正文在发出前会经过两轮语言审查。
- **怎么开关**：每个人独立设置、互不影响。在 **设置 → 模型** 里设置自己的推送总开关和接收账号（飞书或 Discord）；单个任务的推送开关在自动任务列表里逐项切换。

### 研究总监与财报日历

研究总监（Home）可以在周一至周五早上 7:30（北京时间）把覆盖池里待办的研究排一次序，依据是这件事的价值、紧急程度和距上次研究的时间；然后在当天预算内把研究派给各公司的分析师。周六上午 10:00 做一次周度复盘，给出观点变化和 call。

每位有覆盖名单的用户在自己的 Home 里都有独立的**财报日历**任务（周六早上 9:00 运行，也可以在 **设置 → 模型** 里随时开关或立即运行）：它会核实你覆盖名单里未来几周的财报日期（只认公司官方公告），更新你自己的财报日历视图，并为已建工作区的核心标的排好"财报三连"。

## 它能用哪些数据

| 类别 | 来源 |
|---|---|
| 美股公告与财报 | SEC EDGAR：10-K、10-Q、8-K、Form 4 等，含结构化财务数据 |
| 港股与 A 股公告 | 巨潮资讯（A 股、港股法定公告的官方转载平台）：公告和 PDF 原文。仅英文版的港股公告，再去港交所披露易查 |
| 港股与 A 股行情和财务 | 行情、资金流、两融、龙虎榜、股东、分红回购、AH 溢价 |
| 一致预期与基础财务 | 优先使用 Yahoo Finance（实时报价、财务报表、一致预期、股票筛选），仅在分部收入等必需处调用 FMP |
| 卖方研报与会议纪要 | AlphaEngine |
| 专家访谈 | Guidepoint（专家匿名，只写职务；引用原话不超过 20 个词） |
| 业绩电话会 | 电话会转写稿 |
| 内部资料 | 公司 wiki、卖方销售邮件、TMT Breakout（科技行业每日纪要）、FUNDA AI（独立研究） |
| 宏观 | FRED、美国财政部、市场拥挤度和过热指标 |
| 社区与舆情 | 雪球、员工评论（Blind 等）、X：跨账号搜索，以及固定账号的时间线 |
| 行情 | 行情、日线、美股盘前盘后（盘前盘后与休市报价会明确标注收盘日期和美东时间） |
| 网页 | 网页搜索、网页正文读取。读取失败时自动改用 Firecrawl 再试 |
| 团队的历史讨论 | OpenClaw 里的团队对话，每天整理成**知识卡片**，分析师可以检索"之前团队怎么看这件事" |

系统每天早上给数据源做一次体检：能不能用、探测到的最近资料是哪一天，结果会告诉分析师，所以它知道自己能拿到什么。（个别调用成本高的来源不做自动体检。）

## 费用和额度

- 大部分模型走**订阅账号**，用多少都不额外付费，系统只记录一个"名义成本"供参考。
- 少数按次付费的模型和服务，受**每天的现金额度**限制，默认每天 100 美元。用完后，自动任务会暂停，第二天再继续；你的手动对话会提示额度不足。
- 盯盘的检查本身成本很低：大部分时候只是查一下有没有新公告；少数信号需要一个小模型判断要不要唤醒分析师。
- 设置 → 模型 页面可以看到今天的花费和剩余额度。

## 常见问题

**支持哪些市场？股票代码怎么写？**
美股、港股、A 股都支持。直接写代码（如 `META`、`0700.HK`、`600519`）或公司中文名都可以。

**我手上有研报 PDF、访谈纪要或自己的 Excel 模型，怎么给它？**
在对话框里作为附件发给分析师，或者上传到这家公司工作区的 `sources/`（资料）、`model/`（模型）文件夹。

**深度报告要跑很久，中途可以关掉网页吗？**
可以。任务在服务器上运行，关掉网页或切到别的工作区都不影响，回来后结果都在。中断后让分析师续跑原任务，已完成的步骤不会重跑。

**分析师说的数字可信吗？**
引用的来源会显示成卡片，可以点开看原文。对草稿，可以让分析师"核验一下这份草稿"，系统会生成一份核验报告和一份逐个标注了数字的副本。正式发布时，找不到出处、引用的模型公式未重算或与证据矛盾的数字会挡住发布，并且要经过两轮语言审查、独立审稿和 PM 审批。

**我直接改了 thesis.md，分析师会知道吗？**
会。系统会保存你的修改，并提醒分析师把它合入正式档案；在合入之前，正式档案不变。更省事的做法是直接对分析师说你想怎么改。

**它能下单交易吗？**
不能。Dalton 已隐藏并禁用所有券商连接和交易下单功能，也不会给分析师绑定任何下单工具；仪表盘上的"持仓"仅用于查看持仓。

**它会不会一直在后台花钱？**
花费受每日现金额度约束。盘中盯盘没事时只做低成本的公告检查；内部来源每天只集中扫一次；股价异动只在常规交易时段监控，且每个交易日每个方向最多触发一次。定期任务大多使用的是订阅模型，不额外付现金。

**看不到同事的工作区？**
在左侧栏的"团队"分组里。同事的工作区你只能看，不能改。你的覆盖名单、财报日历和私信推送开关都是个人独立的。

**模型页面显示"请重新连接"？**
点对应的连接按钮重新授权即可。团队模式下，需要 PM 来连。

**我想查团队以前在群里讨论过的观点？**
直接问分析师，比如"之前团队对 AppLovin 的电商广告怎么看？"。它会去检索团队对话整理出的知识卡片，并标明出处。
